# Локальная LLM для NPC

Когда читать: перед правкой NPC-диалога, очереди генерации, workers Ollama/MLX, переводчика BABEL, таймаутов и профилей. Перед добавлением поведения NPC также прочитайте [../game/npc.md](../game/npc.md).

Вся генерация идёт локально на серверном ноутбуке. Браузер к модели не обращается. Модель, tokenizer, шаблон и зависимости готовятся до игры; во время игры нет скачиваний, внешних API и телеметрии. Все профили моделей остаются **unverified** (реальный MLX-прогон, Windows, OS-изоляция, пик RAM и 4-player burst не квалифицированы).

## Backend и модель

| Выбор | Требования | Заметки |
|---|---|---|
| `ollama` | подготовленные Ollama, Python tokenizer, локальные веса; POSIX (macOS/Linux) | Qwen3.5-2B Q4_K_M (основной); Qwen3.5-0.8B Q8_0 (явный кандидат) |
| `mlx` | только macOS Apple Silicon, `mlx-lm==0.32.2` | text-only Qwen3.5-2B 4-bit group 64; на Intel — unavailable, а не переключение на Ollama |
| `scripted` | модель не нужна | детерминированная заглушка по умолчанию; не доказательство LLM |

- Одновременно загружены один backend и одна модель для всех NPC. Автоматического выбора, скачивания и fallback нет; горячей смены во время игры нет. Windows-supervisor не реализован.
- Оператор выбирает `npc.adapter` явно. Один лишь `npc.adapter: ollama` BABEL не затрагивает: переводчик включается `language.adapter: local`.
- Workers: [ollama_worker.py](../../server/llm/ollama_worker.py), [mlx_worker.py](../../server/llm/mlx_worker.py) под управлением POSIX-supervisor в [localLlm.ts](../../server/src/npc/adapters/localLlm.ts). Сервер ↔ worker: приватный ограниченный IPC; Ollama-worker владеет выделенным native-процессом и отдельным loopback-listener, cloud отключён. Loopback не заменяет проверенную OS-изоляцию native-endpoint.
- Python 3.12 готовится через uv с раздельными `pyproject.toml` и `uv.lock` на backend: [server/llm/envs/](../../server/llm/envs/). Runtime вызывает готовый Python напрямую и не запускает uv/install.

## Профили запуска

- Выбор на один запуск: `make server BACKEND=ollama MODEL=2b` (также `0.8b`; `BACKEND=mlx MODEL=2b`). Поддержаны ровно три пары. `BACKEND` и `MODEL` задаются вместе. Без аргументов читается сохранённая пара.
- Внешняя versioned коллекция `~/kuda-llm/profiles.json` связывает runtime, модель, digest и tokenizer целиком. Без коллекции работает прямой `npc.adapter/options` в `config.json`. Явно запрошенный, но отсутствующий профиль не откатывается на legacy/scripted. Разовый перенос — `make llm-import` (не установщик).
- Профиль фиксирует: ID и commit исходной модели, хеши файлов, quantization, tokenizer/шаблон, версии runner и библиотек, параметры генерации, `maxConcurrentGenerations`, режим GPU. Для Ollama фиксируется digest активного manifest, а не только имя тега.
- Подробнее: [PROFILES.md](../../server/llm/PROFILES.md), [SETUP.md](../../server/llm/SETUP.md) (установка с нуля), [README.md](../../server/llm/README.md) (справочник runtime), [TIMEOUT.md](../../server/llm/TIMEOUT.md), [UPDATING.md](../../server/llm/UPDATING.md), [MAC-INTEL.md](../../server/llm/MAC-INTEL.md), [MAC-INTEL-08B.md](../../server/llm/MAC-INTEL-08B.md), [MAC-30S.md](../../server/llm/MAC-30S.md). Установка через агента: [install-local-ai](../../.agents/skills/install-local-ai/SKILL.md).

## Очередь и лимиты

[GenerationQueue](../../server/src/npc/GenerationQueue.ts) — единая очередь для NPC, переводов, подсказок словаря и ответов BABEL. Второй очереди нет.

| Параметр | Значение |
|---|---|
| Незавершённых запросов всего | ≤4 (`npc.maxUnfinished`) |
| На одного игрока (`playerId`, независимо от вкладок, NPC и AUTH-сессий) | ≤1 |
| Параллелизм | 1 по умолчанию; 2 только после квалификации. Для реальных Ollama/MLX `maxConcurrent: 2` отклоняется |
| Порядок | FIFO; ожидание очереди входит в дедлайн |
| Слот и квота | держатся до подтверждённой физической остановки вычисления (включая abort и quarantine) |
| Сообщение BABEL-чата | один слот; языки переводятся последовательно |

- Успешный ответ пишется в SQLite до доставки. Таймаут и отмена историю не создают.
- Отмена (закрытие диалога, logout, перехват, разрыв, истёкшая сессия) останавливает конкретное вычисление через `AbortSignal`.
- Поздний результат после дедлайна → `UNAVAILABLE`, без продления.
- Сбой `NpcResponder.start()` игровой сервер не останавливает: NPC недоступны, мир и чат работают. После runtime-сбоя очередь отклоняет вопросы без записи, затем делается ограниченная попытка восстановления.

## Память

- **Лимит всех процессов LLM ≤ 4 000 000 000 байт RAM** (4 GB, не GiB): daemon/runner/worker, веса, tokenizer, KV/состояние, prefill, очереди, буферы. Idle-базу runner вычитать нельзя.
- Рабочий порог — **3 500 000 000 байт** (soft): достижение отменяет работу и может остановить worker с `resource_limit`. Монитор RSS опрашивается периодически и считает Node с потомками; он **не** является проверенным hard cap ОС и не доказывает пик ≤4 GB (unified memory, кратковременные пики).
- Модель остаётся прогретой в пределах запуска; персональные prompt/KV-кеши между областями не переиспользуются. Профиль 2 (параллельность) принимается только при реальном выигрыше для 4 игроков с одной копией весов без регрессии памяти и игры.

## Размеры и язык ответа

| Путь | Вопрос | Вход | Контекст | Выход |
|---|---|---|---|---|
| Обычный NPC (русский) | ≤240 символов, до 6 пар истории | ≤1792 токенов | 2048 | 128 токенов (жёстко); мягкая цель 1–2 коротких предложения, до 20 слов, без обрезки по словам |
| Local BABEL en/es (A2) | ≤500 символов (публичный BABEL v2) | ≤1792 | 2048 | ≤256 токенов, проверка ответа ≤800 codepoints, без эмодзи, нормальное завершение |
| Перевод | — | — | — | 128 токенов |

Thinking выключен средствами шаблона; текст thinking не отправляется игроку и не пишется в историю. Ответ игрового сервиса нормализуется до 4000 символов. Реальный tokenizer/template ограничивает вход.

Цель, не реализованная целиком: вопрос и ответ по 800 codepoints, контекст 4096 / выход 256 токенов (кандидат на квалификацию — просто поднять число в config нельзя), ответ на en/es A2 по серверной настройке игрока, обычно 2–4 коротких предложения. Planning: FTS5-grounding и утверждённый корпус, полный архив и компактная память, модельное приветствие при открытии, ledger/result после reconnect.

## Поведение NPC на сервере

- Scope личного разговора — `(AUTH sessionId, playerId, npcId)`: продолжается при той же действующей сессии (меню, reconnect, рестарт), новый login начинает знакомство заново; словарь, инвентарь и задания не сбрасываются. Кнопки сброса NPC нет.
- Отношение — три состояния `ordinary`/`displeased`/`friendly`; влияет только на речь. Явное оскорбление → `displeased`; извинение → `ordinary` (не дружба); цитаты, вопросы о слове, оскорбление третьих лиц, технический сбой, отмена отношение не меняют. Классификатор — [intentClassifier.ts](../../server/src/npc/intentClassifier.ts), факты — [factExtractor.ts](../../server/src/npc/factExtractor.ts); их результат проверяет сервер, модель лишь получает `attitude` и `facts` в prompt.
- Модель не получает инструментов и не меняет игру: задания, предметы, прогресс определяет только сервер. Реплика игрока и найденный текст — данные, не системные инструкции.
- Карточка NPC (характер, знания, голоса) — см. [../game/npc.md](../game/npc.md).

## Таймауты

| Что | Значение |
|---|---|
| `npc.timeoutMs` | default 30000, config 1–300000 мс |
| `npc.streamTimeoutMs` | те же default и диапазон |
| `NPC_TIMEOUT` (Make) / `KUDA_NPC_TIMEOUT` / `--npc-timeout` | целые секунды 1–300 на запуск; задаёт оба поля сразу; приоритет CLI → env/Make → config → default |
| Клиент ждёт | `npcTimeoutMs` из `/api/game-config` + 2000 мс; прочие pending, включая чат — 10 с |
| Клиентский BABEL HTTP | 30 с; серверный `NPC_TIMEOUT` его не увеличивает |
| Старт worker (прогрев) | до 120 с по умолчанию |

Неверное значение отклоняется, не обрезается. Это аварийный предел, а не выполнение цели p95 полного ответа ≤8 с.

## Стриминг ответа

`NpcResponder.answer(request, signal, onPartial?)` передаёт накопленный текст; `NpcDialogueService` нормализует его, `PartialThrottle` ограничивает частоту (≤10/с), realtime шлёт `npc-partial` ([protocol.md](protocol.md)). Ollama-worker шлёт partial по токенам (`stream=True`), MLX-worker — накопленный текст без `<think>`; supervisor принимает не более 512 partial-сообщений на запрос, отдельно от ≤12 progress-сообщений. Приватный progress (стадия, счётчики, без текста) идёт в диагностику, не игроку. Расхождение: старые документы называли реальный стриминг нереализованным; по коду и git он есть.

## Цели квалификации (не достигнуты)

Прогретый свободный сервис: p95 первого видимого текста ≤2 с, p95 полного стандартного ответа ≤8 с; 4 одновременных запроса — отдельная цель по худшему игроку. Корпус проверок D01–D24 на en и es, 3 повтора; холодная загрузка ≥5 раз; ≥100 диалогов, 20 отмен, 10 stop/start без роста кешей и процессов. Запасной кандидат Qwen3-1.7B и сравнительный Qwen3-4B-Instruct-2507 не приняты. Отклонённые варианты (4B, LFM2.5-2.6B, Gemma 4 E2B, SmolLM3-3B) — в [../decisions/README.md](../decisions/README.md).
