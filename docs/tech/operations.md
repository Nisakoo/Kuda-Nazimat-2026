# Эксплуатация

Когда читать: готовите ноутбук-сервер к игре, чините «не открывается», выдаёте доступ администратору, смотрите логи и метрики, делаете бэкап. Команды установки и проверки — [setup.md](setup.md).

## Роли и режимы сети

Администратор (хост) готовит ноутбук-сервер и запускает сервер; игроки открывают только адрес в браузере (до 4 человек, один общий мир).

| Режим | Когда | Адрес | Ограничения |
|---|---|---|---|
| R1. Свой роутер (рекомендуется) | дешёвый Wi-Fi-роутер без интернета | `https://<IP сервера>:8080` | нужен роутер; IP лучше закрепить (резервирование DHCP) |
| R2. Существующая сеть | общая Wi-Fi или проводная сеть | так же по IP | в гостевых и публичных сетях бывает изоляция клиентов — тогда нужен R1 |
| R3. Один компьютер | нет сети, игроки по очереди за одним ПК | `https://localhost:8080`, окно браузера на игрока | Wi-Fi можно выключить; сервер и браузеры делят ресурсы |

Раздача Wi-Fi самим сервером (точка доступа ноутбука) не поддерживается. Мобильные браузеры не целевые: нужны клавиатура и мышь, WebGL 2, Pointer Lock.

Сетевые требования: входящий TCP на порт игры; одна IP-сеть без изоляции клиентов; DNS и интернет не нужны. Нагрузка: до ~10 KB/s на игрока в игре, ~2 MB данных карты при входе. Рабочая задержка до 150 мс.

## Офлайн-запуск

1. Один раз, с интернетом: `make prepare` (Node 24.15+, зависимости клиента и сервера, сборка клиента и мира, сертификат, самопроверка). Идемпотентна, БД игроков не трогает.
2. Перед игрой, без интернета: `make start` (синоним `make demo`). Порт другой: `make start PORT=9000`.
3. Сервер печатает блок подключения: адрес для этого компьютера, адреса для других устройств по интерфейсам (частные сети первыми), адрес `/operator`, адрес `/setup`, отпечаток сертификата, подсказку про брандмауэр.
4. Остановка — Ctrl+C: позиции сохраняются, печатается отчёт приёмки. Аварийное завершение теряет не больше `saveIntervalMs` (10 с) движения.

Самопроверка без запуска: `npm --prefix server run lan:check` (Node, интерфейсы, свободен ли порт, сборка клиента и мир, БД и схема, сертификат, брандмауэр; ненулевой код, если запуск невозможен). Занятый порт даёт понятную ошибку с подсказкой `--port` (в Windows порт, занятый другой программой, приходит как `EACCES`).

Брандмауэр (сервер настройки сам не меняет):
- Windows: разрешить Node.js для частных сетей; сеть должна иметь профиль «Частная».
- macOS: разрешить входящие для Node в «Системные настройки → Сеть → Брандмауэр».
- Linux: открыть порт, например `ufw allow 8080/tcp`.

Целевые показатели: от включения подготовленного ноутбука до двух игроков ≤5 минут; подключение игрока после получения адреса ≤30 с; обрыв Wi-Fi до 7 с — возврат без потери позиции; ноль запросов в интернет во время игры. Физическая проверка двух ноутбуков и реально выключенного Wi-Fi пока не выполнена.

### Диагностика «не открывается»

| Симптом | Причина | Действие |
|---|---|---|
| адрес не открывается | брандмауэр, сеть «Общественная», изоляция клиентов, не тот IP | проверить блок подключения, настройки ОС, перейти на R1 |
| открывается `/api/health`, но не игра | нет сборки клиента | `make prepare` |
| «Сервер заполнен» | 4 игрока уже в мире | дождаться выхода (место освобождается через 10 с) |
| «Игра открыта в другом окне» | то же имя во второй вкладке | закрыть лишнюю вкладку |
| «Связь потеряна» | обрыв Wi-Fi или сервер остановлен | «Повторить», проверить сервер |
| ничего не открывается после смены сети | IP сервера сменился | взять новый адрес; возможно, обновить сертификат |

`/api/health` открывается и по HTTP, и по HTTPS (проверка IP/порта до установки доверия).

## HTTPS/WSS и доверие сертификату

Всё приложение работает только по HTTPS/WSS на одном порту (по умолчанию 8080); режима без TLS нет. Сервер сам создаёт самоподписанный сертификат при первом запуске или `make prepare` (`server/data/tls/server.crt`, ключ `server.key` с правами `0600`, не коммитится, никуда не отдаётся).

**Один раз на каждом устройстве игрока:**
1. Открыть `http://<IP сервера>:8080/setup` (адрес и отпечаток печатает сервер и показывает `/operator`).
2. Скачать сертификат и **сверить отпечаток SHA-256** с экраном ведущего (скачивание идёт по открытому HTTP).
3. Установить по инструкции на странице: macOS — «Связка ключей» → «Всегда доверять»; Windows — «Доверенные корневые центры сертификации» (текущий пользователь); Linux/Chrome — менеджер сертификатов; Firefox — добавить исключение.
4. Открыть `https://<IP сервера>:8080/` — замок без предупреждений.

Сертификат привязан к адресам, которые были у ноутбука при создании (`localhost`, IP интерфейсов, `<имя>.local`, `tls.extraNames`). Автоматического перевыпуска нет: при смене IP предупредят блок подключения, `/operator` и `lan:check`, игроки увидят ошибку имени. Исправление — `npm --prefix server run tls -- renew --yes` и повторный `/setup` на всех устройствах. Чтобы смена IP не ломала игру, закрепите IP на роутере или добавьте стабильное имя в `tls.extraNames`.

```sh
npm --prefix server run tls -- status          # отпечаток, срок, покрытие адресов, права
npm --prefix server run tls -- init            # создать, если нет
npm --prefix server run tls -- renew --yes     # выпустить новый
npm --prefix server run tls -- export cert.crt # только сертификат
```

| Симптом | Действие |
|---|---|
| «Подключение не защищено» | устройство не доверяет сертификату: пройти `/setup` (IP такого устройства виден на `/operator`) |
| `ERR_CERT_COMMON_NAME_INVALID` | адреса нет в сертификате: `tls status`, `tls renew --yes`, `/setup` заново |
| сервер не стартует: сертификат истёк (825 дней) или повреждён | `tls renew --yes`, `/setup` заново |
| `http://…` сразу уходит на https | так задумано (308) |
| Firefox всё ещё предупреждает | у Firefox своё хранилище: добавить исключение |

Dev-клиент Vite на `:5173` тоже должен работать по HTTPS (CORS `https://localhost:5173`). Публичный домен, ACME и обратный прокси не поддерживаются.

## Админ-панель и доступ

- `/operator` — только на самом ноутбуке-сервере (loopback, с других адресов 404). Данные обновляются каждые 2 с, графики — из встроенной истории метрик за 4 часа.
- `/admin` — из LAN, после входа административным аккаунтом (сессия 8 ч, токен в памяти страницы, игровое место не занимает). Страница та же. До появления первого администратора вход подскажет команду `create-admin`.
- Разделы: Обзор, Сервер, Клиенты, NPC, Журнал, Аккаунты. Показывают места и игроков онлайн, RTT и FPS, состояние NPC/переводчика, очередь, память, предупреждения; правка, создание, выключение NPC без перезапуска; сброс живой сцены; журнал изменений с CSV; карточка аккаунта. Неполученные показатели — «нет данных». Тексты игроков, токены и пароли не показываются.

Управление аккаунтами (на сервере, `--env production` для боевой БД):
```sh
npm --prefix server run auth -- create-admin <имя> --env production   # временный пароль показан один раз
npm --prefix server run auth -- grant-admin <имя> --env production
npm --prefix server run auth -- revoke-admin <имя> --env production
npm --prefix server run auth -- reset-password <имя> --env production # временный пароль 24 ч, смена обязательна
npm --prefix server run auth -- revoke <имя>                          # завершить сессии
npm --prefix server run auth -- list                                  # аккаунты без хешей
```
В Windows PowerShell используйте `npm.cmd`. Блокировку входа снимает только экран `/operator` (она живёт в памяти сервера). Игрок, забывший пароль, получает временный пароль от администратора и сам задаёт новый.

## Логи, метрики, самописец

- Журнал: `server/data/logs/server-*.jsonl` (JSON на строку), ротация 20 МБ, ≤200 МБ всего, ≤14 дней. Окружение `test` файл не пишет.
- Бортовой самописец: при первой ошибке и по кнопке «Сохранить отчёт» (раздел «Сервер») пишет `incident-*.jsonl` — последние 5000 событий, снимок метрик, 10 минут истории. Это главный источник для плавающих ошибок.
- Метрики: `/api/operator/status`, `/history`, `/metrics` (только loopback). Внешний Prometheus/Grafana не нужен и не поддерживается.
- Раз в минуту в журнал пишется `metrics.minute`. Выгрузка в CSV:
```sh
jq -r 'select(.event=="metrics.minute") | [.ts, .values.seated, .values.errors, .values.warnings, .values.rssBytes] | @csv' server/data/logs/server-*.jsonl > metrics.csv
```
- Отчёт приёмки (без запущенного сервера; ту же таблицу сервер печатает при остановке):
```sh
npm --prefix server run report                                  # последний запуск
npm --prefix server run report -- --env production --last 2h
npm --prefix server run report -- --file server/data/logs/server-20261101-ab12cd34.jsonl
```
Пороги: p95 шага ≤5 мс, p95 рассылки ≤120 мс, ошибки сервера 0, p95 ping ≤150 мс, FPS ≥30, таймауты NPC ≤25%, потерянные логи 0; «нет данных» нормой не считается. FPS появляется, только если клиент шлёт `perf`-отчёты.

## Данные и бэкап

```sh
npm --prefix server run inspect                                 # БД read-only: аккаунты, позиции, сессии, диалоги
npm --prefix server run backup -- /absolute/path/backup.sqlite  # VACUUM INTO, существующий файл не перезаписывается
```
- При работающем сервере копируйте БД только через `backup`. При остановленном — файл вместе с `-wal` и `-shm` как единый комплект; один основной файл WAL-БД копировать нельзя.
- Проверка восстановления: отдельный каталог и отдельный JSON-конфиг с `dbPath` на копию, `inspect --config …`, `PRAGMA integrity_check`; текущую БД не заменять.
- Перед обновлением рабочей БД (миграции) делайте backup. Удалять `game.sqlite` ради починки входа не нужно.
- БД окружений разделены: `data/dev.sqlite`, `data/game.sqlite`, `data/test.sqlite`. SQLite и бэкапы не шифруются; доступ ограничивает локальный оператор.
- Ручная проверка аварийного завершения: `node server/test/crash-recovery.ts`.

## Безопасность в LAN

Трафик шифруется TLS; риски — режим `guest` (только development/test) и первое скачивание сертификата по HTTP (защищено только сверкой отпечатка). Сеть роутера лучше защитить WPA2/WPA3. Администратор ноутбука-сервера и скомпрометированная ОС вне модели угроз.
