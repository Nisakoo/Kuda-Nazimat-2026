# Клиент

Когда читать: перед правкой `client/`: сессии, карта и подгрузка мира, рендер, ввод, звук, профили графики.

Стек: один Vite-проект [client/](../../client/), TypeScript strict, Svelte 5 + CSS, Three.js (единственный движок), Socket.IO Client, Vitest. Нет SvelteKit, DI-контейнера, полного ECS, переключения движков. Серверный код, БД и модели ИИ в клиентскую поставку не входят. Общие границы — [architecture.md](architecture.md), сообщения — [protocol.md](protocol.md), команды — [setup.md](setup.md).

## Сессии

- `GameSession` — одинаковый интерфейс команд, чтения состояния, подписок и завершения.
- `LocalSession` — прогулка без сервера (только Vite-стенд): `GameWorld` проверяет команды и расстояние, интегрирует движение общей кинематикой [shared/movement](../../shared/movement/simulation.ts). Начальная позиция — spawn из manifest.
- `OnlineSession` — replica серверного мира: хранит `playerId` и AOI из `joined`, применяет снимки и дельты на `update`. Входная очередь ≤8 пакетов; переполнение или разрыв revision → `resync`. После reconnect всегда новый join. Для отображения хранит историю из 8 снимков и интерполирует всех игроков (включая цель камеры) с задержкой 100 мс; авторитетное состояние не интерполируется. Позицию определяет сервер, клиент шлёт `preparedChunks` и нулевое движение при неготовой области.
- `SocketIOAdapter`: подключение явное, без autoConnect/reconnection; retry 1/2/4 с, максимум три попытки; отказ авторизации или версии терминален; транспорт не накапливает действия для повтора; важные действия ждут коррелированного подтверждения с таймаутом.
- Серверная сессия `{token, expiresAt}` приходит через `GameApp.provideServerSession()`; токен только в памяти, после reload нужен новый вход. Режимы входа берутся из `/api/auth/mode`. Смена сервера не переносит токен на другой сервер; поздний ответ входа/выхода не меняет новый контекст. В серверной поставке доступен только online.
- `MarketSession` расширяет `LocalSession` только для клиентского стенда рынка; данные стенда на сервер не переносятся. `BabylonClient` обращается к `/api/babylon`, опрашивает личный снимок раз в секунду, сохраняет `requestId` для безопасного повтора.

## Игровой цикл

Один планировщик кадров в `GameLoop`: шаг симуляции 1/60 с, `delta` ≤0,1 с, ≤5 догоняющих шагов. Внутри шага: опрос ввода → обновление сессии → применение сетевых данных → планирование чанков → синхронизация визуалов; без `await`. Рендер получает `alpha`. Скрытие вкладки и stop/start сбрасывают часы; пауза останавливает симуляцию. Повторное создание/завершение приложения не оставляет циклов, обработчиков и GPU-ресурсов.

## Карта и подгрузка мира

- `HttpMapSource`: bootstrap → manifest → JSON и collision-bitmap чанков. Реальный онлайн читает `<serverUrl>/world/` с Bearer, публичного fallback нет. HTTP-запросы ограничены объявленным размером, `no-store`, redirect запрещён, service worker нет.
- Мир генерируется перед `dev`/`build`/`test`/`check` скриптом `world:generate`: чанки по 32 м, общие GLB, collision bitmap выводится из геометрии, одинаковые BIN адресуются по SHA. Сгенерированные JSON/BIN исключены из git. В JS-бандл входит только небольшой bootstrap.
- **Окно чанков ≤25.** Радиус 0–2: по умолчанию 2 для `market` (5×5, у компактного города реально ≤16 чанков) и 1 для `demo`/`science`; параллелизм загрузки 2. Сначала текущий чанк и ближайший переход, дальние выгружаются. Движение разрешено только в подготовленную область; при задержке UI показывает ожидание.
- **Защита памяти 128 MiB.** Уникальные сериализованные байты manifest/чанков/collision/моделей/зависимостей учитываются для диагностики; процентного лимита кеша нет. Весь чанк резервируется атомарно до HTTP; pending и CPU/GPU-владельцы держат резерв до последней ссылки. Консервативный cap полезных данных — 128 MiB (не измеряет RSS браузера/драйвера). Расхождение: в части старых документов фигурирует 64 MiB; действует 128 MiB.
- Планирование: одинаковые позиция/радиус/бюджет нового плана не требуют; смена приоритетов будит отложенные чанки; повторное вытеснение той же пары запрещено до смены приоритетов, ручного retry или освобождения бюджета (нет цикла load/unload). Поздние ответы отменённого поколения чанки не создают.
- `AssetManager` объединяет запросы через `AsyncLeaseCache`; `GltfLibrary` удерживает leases, декодирует GLB, делит геометрии/материалы/текстуры, создаёт независимые скелеты и `AnimationMixer`; клонирование ≤8 объектов за кадр и 2 мс бюджета между заданиями. Последний владелец освобождает GPU, текстуры, `ImageBitmap` и исходные байты. Смена карты ждёт освобождения старого бюджета.
- Дополнительные буферы (ветер, следы дроби, аудио) тоже резервируются в том же `WorldBudget`. Ветер: ≤1024 экземпляров (64 KiB) на модель внутри её резерва. Аудио: 8 источников, 2 загрузки, 7 буферов, 8 motion ID, 32 потока, 512 recent message ID.

## Рендер

- Один `ThreeRenderer`, одна сцена; статические чанки — отдельные группы (`VisualChunks`), динамические сущности — `EntityVisuals` (`EntityId → VisualObject`, Mesh не создаётся каждый кадр). Динамические игроки/NPC не выгружаются вместе со статическим чанком.
- Камера: третье лицо по умолчанию, `V` — первое лицо. Препятствия — пять проб `CameraRaycast`: ускорение bounding-коробками диапазонов по 128 треугольников, кеш в `WeakMap` по геометрии, skinned/morph/instanced идут обычным путём; тот же кеш использует `ShotgunVisuals`. Не пересчитывается, пока не изменились камера, цель и набор чанков (неподвижная камера перепроверяет каждые 10 кадров).
- Дальняя плоскость камеры = дальность тумана + 5 м.
- Статические меши потоковых моделей склеиваются один раз на шаблон `GltfLibrary` (`staticMerge.ts`): группа = якорный анимированный узел + материал + флаги теней + формат вершин. Узлы ветра, анимаций и `babel-symbols` остаются отдельными.
- Повторяющиеся непрозрачные wind-поверхности внутри GLB объединяет `WindInstances` (общие geometry/material, instance-буферы освобождаются до release модели).
- Следы дроби в low/balanced — `InstancedMesh`: ≤96 следов, TTL 30 с, 256 KiB резерва; high и нехватка резерва — обычные Mesh.
- Динамика позы (`CharacterRig`/`CharacterMotion`): переходы поз 140/100/140 мс, воздушная фаза приоритетнее; темп походки по наблюдаемому перемещению.
- Потеря WebGL-контекста и ошибки загрузки не останавливают UI; без WebGL 2 показывается понятная ошибка.

### Профили графики

[GraphicsQuality.ts](../../client/src/render/GraphicsQuality.ts) (`low` / `balanced` / `high`; в UI «облегчённое / обычное / высокое»):

| Профиль | DPR | Сглаживание | Тени | Туман непрозрачен с | Дальний ветер |
|---|---|---|---|---|---|
| low | 1 | нет | нет | 60 м | раз в 100 мс |
| balanced | 1 | да | PCF 1024 | 80 м | раз в 100 мс |
| high | 1,5 | да | PCF 2048 | 80 м | каждый кадр |

- Пока игрок не выбрал профиль вручную, подбирается по устройству (`recommendGraphicsQuality`): Intel (кроме Arc), AMD APU, Mali/Adreno/PowerVR, SwiftShader/llvmpipe/Basic Render, `hardwareConcurrency ≤4`, `deviceMemory ≤4` → low, иначе balanced. `high` автоматически не выбирается; подобранное значение не сохраняется; сбой проверки → balanced. Выбор сохраняется в браузере и применяется перезапуском сцены.
- Тень — одна ортографическая карта (область ±24 м), `autoUpdate`. Каскады (CSM), Hi-Z occlusion, кеш теней, LOD и адаптивное разрешение оценивались и не внедрены. Профиль не влияет на Core, протокол, коллизии, окно чанков и `WorldBudget`.
- Диагностика (`debug`): FPS как частота отправки кадров renderer (не показ дисплеем), частота цикла, пропуски из-за занятого GPU, draw calls (`renderer.info`, основной + теневой проход), чанки (готовые, загружаемые, отложенные по бюджету), резерв памяти. График FPS — ≤60 точек раз в секунду.

## Ввод и UI

- `InputController`: физические коды клавиш (работает при любой раскладке), WASD/стрелки относительно камеры; `Space` — прыжок, `Shift` — спринт, `E` — взаимодействие, `F` — рука, `V` — вид, `ЛКМ`/`R` — дробовик, `Esc` — меню. Pointer Lock запрашивается по явному действию; меню, диалог, чат, blur, скрытие вкладки и потеря захвата сбрасывают ввод и освобождают курсор; поздний результат старого запроса управление не включает.
- UI на Svelte 5; текст всегда выводится как текст (не HTML); окна — native `dialog`. Координаты в UI обновляются ≤10 раз/с, производительность — раз в секунду; покадровые трансформации через Svelte не идут. Чат карты хранит последние 50 сообщений.
- Таймауты: обычные pending 10 с, NPC — `npcTimeoutMs` + 2 с; запрос входа — 10 с, один одновременно, смена сервера его отменяет.
- Аудио: один уровень громкости (30% по умолчанию, 0% — тишина), хранится отдельно от токена и профиля; браузер разблокирует звук по действию пользователя, ошибка автоплея игру не останавливает; звуковые файлы — локальные WAV ([provenance](../../client/public/assets/audio/PROVENANCE.md)).

## Конфигурация

[client/public/config.json](../../client/public/config.json) читается с `no-store`, секретов нет; сервер подменяет его своим ответом.

| Поле | По умолчанию | Смысл |
|---|---|---|
| `session` | `local` | `local` — прогулка; `online` требует серверной сессии |
| `serverUrl` | `null` | origin страницы; допустим HTTP(S) или относительный путь; протокол сохраняется при смене IP/порта |
| `mapId` | `market` | локально `market`/`demo`/`science`; онлайн — ID серверной карты |
| `chunkRadius` | `null` | 2 для market, 1 для demo/science; допустимо 0–2 |
| `debug` | `false` | диагностика кадров и ресурсов |
