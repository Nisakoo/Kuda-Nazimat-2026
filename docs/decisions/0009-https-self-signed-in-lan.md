# HTTPS/WSS во всех окружениях с самоподписанным сертификатом сервера

## Context and Problem Statement

Прежняя LAN-версия использовала открытый HTTP: пароль и токен шли по сети без шифрования. Нужен доверенный HTTPS для LAN и соло-режима, включая вход, `/world/*` и Socket.IO, без интернета, публичного домена и внешнего центра сертификации.

## Decision Drivers

* Нет интернета: Let's Encrypt/ACME и публичный домен недоступны.
* Администратор не обязан быть программистом; на ноутбуке может не быть OpenSSL.
* Один порт и одно правило брандмауэра.
* Сертификат должен работать на macOS, Windows и Linux на Node 24.

## Considered Options

* Один самоподписанный сертификат сервера; устройства доверяют ему один раз через `/setup` (выбрано)
* Собственный центр сертификации
* HTTP-режим без TLS (прежний)
* Публичный домен, Let's Encrypt/ACME, обратный прокси (отдельная спека онлайн-развёртывания)
* OpenSSL CLI для выпуска сертификата

## Decision Outcome

TLS завершается в самом сервере (`node:https`), без прокси. Сервер выпускает самоподписанный сертификат ECDSA P-256 (срок 825 дней, SAN: `localhost`, `<hostname>.local`, loopback, LAN IPv4, `tls.extraNames`). Режима без TLS нет ни в одном окружении. Один порт: протокол определяется по первому байту; открытый HTTP обслуживает только `/setup`, `/server.crt`, `/api/health`. X.509 кодирует собственный минимальный DER на `node:crypto`. Сервер не перевыпускает сертификат сам.

### Consequences

* Good: пароль и токен защищены от перехвата в LAN; работает офлайн без новых зависимостей.
* Bad: каждое устройство игрока один раз устанавливает сертификат и сверяет отпечаток; первое скачивание идёт по открытому HTTP.
* Bad: сертификат привязан к адресам; при смене IP браузер покажет ошибку имени — нужен `tls renew --yes` и повторный `/setup` на всех устройствах.
* Bad: нет защиты от администратора ноутбука-сервера или скомпрометированной ОС.
* Bad: Vite dev-сервер тоже должен работать по HTTPS.

### Confirmation

`tls.test.ts` (самоподпись, SAN, права ключа `0600`, 308 и 426 на открытом порту); `lan:check` и `/operator` показывают отпечаток, срок и непокрытые адреса. Физическая проверка доверия на втором устройстве и в Windows не выполнена.

## Pros and Cons of the Options

### Самоподписанный сертификат

* Good: выбор пользователя; один файл для установки на устройство.
* Bad: привязка к адресам и повторная установка при смене сертификата.

### Собственный центр сертификации

* Bad: отвергнут решением пользователя; подробности не указаны.

### HTTP без TLS

* Bad: риск перехвата пароля и токена; принятый ранее риск снят полностью.

### OpenSSL CLI

* Bad: нет гарантии установки у администратора; выбран собственный DER-кодировщик.
