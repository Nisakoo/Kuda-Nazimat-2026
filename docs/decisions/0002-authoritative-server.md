# Сервер авторитетен, клиент шлёт только намерения

## Context and Problem Statement

Несколько игроков делят один мир, у них общие предметы, задания и NPC. Нужно решить, кто владеет позицией, инвентарём, прогрессом и ответами NPC.

## Decision Drivers

* Нельзя доверять данным клиента (изменённый клиент, чужой playerId).
* Прогресс заданий и сохранения должны быть согласованными между игроками и перезапусками.
* Клиентские данные недоверенные в обе стороны.

## Considered Options

* Авторитетный сервер; клиент шлёт намерения (выбрано)
* Prediction/reconciliation на клиенте (оставлено как возможное, не обязательное)

## Decision Outcome

Выбран авторитетный сервер. Он назначает `playerId`, позицию, результат взаимодействия, ответ NPC, прогресс и владение предметами. Клиент отправляет только намерения (направление, спринт, `jumpId`, команды). Клиентская позиция не источник прогресса. Клиент хранит replica и интерполирует отображение.

### Consequences

* Good: единая правда о мире, сохранения и задания не зависят от клиента.
* Good: общая кинематика `shared/movement` выдаёт одинаковый результат на сервере и в `LocalSession`.
* Bad: нет prediction — отклик зависит от сети; клиент сглаживает отображением с задержкой 100 мс.
* Bad: сервер обязан валидировать каждый пакет и каждое действие.

### Confirmation

Строгие runtime-парсеры из `shared/` на входе; тесты `realtime-scenarios`, `integration`; fixtures с невалидными пакетами (`position`, чужой `playerId`, `v: 2`).

## Pros and Cons of the Options

### Авторитетный сервер

* Good: защита от подделки, согласованное состояние.
* Bad: серверная логика для всего игрового состояния.

### Prediction/reconciliation

* Good: меньше задержки отклика.
* Bad: усложняет клиент; в источниках оставлено «возможным, но не обязательным для MVP».
