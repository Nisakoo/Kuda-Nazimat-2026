# `shared/` — единый исполняемый контракт: чистый TypeScript без зависимостей

## Context and Problem Statement

Клиент и сервер обязаны одинаково понимать протокол, формы сущностей, формат карты и правило проходимости. Изначально клиент держал собственную копию контракта. Нужно решить, где хранить общий контракт и как делиться кодом.

## Decision Drivers

* Одна копия правды; нельзя разойтись по wire-поведению.
* Сервер запускается встроенным удалением типов Node, клиент собирается Vite.
* Общая симуляция движения должна давать одинаковый результат на сервере и в `LocalSession`.

## Considered Options

* Корневой каталог `shared/` с относительными импортами (выбрано)
* Собственная копия контракта у клиента с сравнением fixtures (был переходный этап)
* npm workspaces и общий пакет

## Decision Outcome

Создан корневой `shared/`: TypeScript strict для ES2022, без npm-зависимостей, DOM и Node-типов, без `enum`, `namespace` и parameter properties, импорты только относительные с расширением `.ts`. `shared/package.json` — только маркер `{"type": "module"}`. Состав: протокол, BABEL, сущности, карта и проходимость, движение, живой мир, дробовик, город, облики. Игровые правила сервера, Socket.IO, HTTP, SQLite, рендер и UI сюда не входят.

### Consequences

* Good: клиент и сервер используют одну копию; общие fixtures проверяют обе стороны.
* Good: общая кинематика и проходимость исключают расхождения сервер/клиент.
* Bad: запрет нестираемого синтаксиса ограничивает стиль кода.
* Bad: любое изменение wire требует согласованной поставки обеих сторон.

### Confirmation

`tsc -p shared` в профиле `lib: ["ES2022"]` без DOM/Node (входит в `npm --prefix server run check`); dependency-cruiser запрещает зависимости `shared/` от Node/DOM, адаптеров и сторонних библиотек.

## Pros and Cons of the Options

### Корневой `shared/`

* Good: одна копия, Node импортирует без сборки.
* Bad: нужен дисциплинированный чистый код.

### Копия у клиента

* Bad: риск расхождения; сервер сравнивал клиентские fixtures с shared-парсерами, пока копия существовала.

### npm workspaces

* Bad: в источниках явно исключены («workspaces и монорепозиторный инструментарий не создаются»).
