# Одна локальная LLM для всех NPC, бюджет памяти и единая очередь

## Context and Problem Statement

NPC должны отвечать на ноутбуке сервера без облака, пока тот же ноутбук ведёт игровой мир. Нужно выбрать модель и backend, ограничить память и определить, как 4 игрока делят одну генерацию.

## Decision Drivers

* Суммарный пик RAM всех процессов LLM ≤ 4 000 000 000 байт.
* Серверный шаг игры не должен ждать модель.
* Целевая нагрузка: 4 игрока; многоязычность (ru, en, es).
* Два backend: MLX (Apple Silicon) и Ollama (поддерживаемые платформы).

## Considered Options

* Qwen3.5-2B (post-trained, не Base): Ollama Q4_K_M или MLX 4-bit group 64, одна модель для всех NPC (выбрано)
* Qwen3.5-4B (пакет Ollama Q4_K_M около 3,3 ГБ — слишком мало запаса)
* LFM2.5-2.6B (всегда thinking, не рекомендована для knowledge-heavy задач, коммерческие ограничения лицензии)
* Gemma 4 E2B (с embeddings 5,1 млрд параметров, пакеты Ollama больше 4 ГБ)
* SmolLM3-3B (нет доказанного преимущества, русский не входит в основные языки)
* Qwen3-1.7B (запасной кандидат, не принят) и Qwen3-4B-Instruct-2507 (точка сравнения качества)
* Отдельная модель на каждого NPC, fine-tuning/LoRA, внешние embeddings (вне поставки)

## Decision Outcome

Одна модель и один backend на весь запуск, выбор оператором (автоматического выбора, скачивания и fallback нет). Единая `GenerationQueue` для NPC, переводов, словаря и ответов BABEL: ≤4 незавершённых запроса, ≤1 на игрока, FIFO, параллелизм 1 по умолчанию. Слот держится до подтверждённой остановки вычисления. Heavy inference работает в собственном процессе (owned worker). Рабочий порог памяти 3 500 000 000 байт (soft): при достижении работа отменяется. Параллелизм 2 допускается только после квалификации.

### Consequences

* Good: предсказуемая память и очередь; игровой мир не блокируется.
* Good: модель не получает инструментов и полномочий менять игру.
* Bad: 4 игрока делят одну генерацию — задержки возможны; цели p95 ≤8 с (полный ответ) и 4-player burst не достигнуты.
* Bad: монитор RSS — не жёсткий лимит ОС; пик и unified memory не доказаны.
* Bad: профили Ollama/2b, Ollama/0.8b, MLX/2b остаются unverified; Windows-supervisor и реальный MLX-прогон отсутствуют.

### Confirmation

Контрактные тесты `NpcResponder`; квоты проверяются тестами очереди. Квалификация D01–D24 и замеры RAM/латентности по плану LLM-QA — не выполнены.

## Pros and Cons of the Options

### Qwen3.5-2B

* Good: маленький размер, многоязычность, доступен на обоих backend, обычный режим без thinking.
* Bad: качество не квалифицировано; MLX-пакет `mlx-community/Qwen3.5-2B-4bit` мультимодальный, нужен text-only артефакт.

### Qwen3.5-4B, LFM2.5-2.6B, Gemma 4 E2B, SmolLM3-3B

* Bad: причины отказа указаны в списке вариантов выше.
