# Авторские персонажи

Все формы созданы в репозитории средствами Three.js; сторонние модели/текстуры не использованы. Единица — метр, Y вверх, +Z вперёд, origin на земле между стопами.

Четыре облика игрока создаёт `generate-avatar-models.mjs`. Стиль: ориентир — макеты [docs/game/images/](../../docs/game/images/) (экран «Выберите свой облик»): крупная мягкая чиби-голова, гладкое лицо, маленький нос «кнопкой», светлая тёплая кожа, объёмные волосы из прядей с гладкими нормалями. Поверхности частей (`torso`, `neck`, `head`, `face`, `hair`, `shoulder-*`, `elbow-*`, `wrist-*`, `hip-*`, `knee-*`, `ankle-*`, `skirt-*`) лежат в `avatar-parts/<id>.json` — это ассеты из Blender (см. ниже). Если файла нет, генератор строит процедурную запасную скульптуру: гладкий эллипсоид головы (масштаб только по X/Y, глубина общая), черты лица через `headZ`, пряди `crownTuft`. Рост задаёт `AVATAR_PROPORTIONS`: Лукас 2,15 м, Дэн 2,0 м, Ник и Ксю 1,80 м. Части из Blender масштабируются равномерно (`uniformScale`), поэтому ширина и глубина следуют форме (в пределах общей глубины 0,56 м); `width`/`depth` из таблицы применяются только к процедурной запасной скульптуре. Серверная коллизия от этих размеров не зависит. Общие клипы — `idle`, `walk`, `jump`; последний поднимает обе руки. EntityVisuals выбирает его по подтверждённому воздушному состоянию, GltfLibrary смешивает переход за 140 мс. На земле возвращается поза по фактическому перемещению. Предмет наследует трансформацию кисти. Превью использует общий коэффициент масштаба, сохраняющий разницу роста; портреты кадрируются по высоте модели.

После изменения генератора: `node client/scripts/generate-avatar-models.mjs --portraits` (при системном Chrome — `PLAYWRIGHT_CHANNEL=chrome`), затем скопировать `*-portrait.png` из `public/assets/models/avatars/` в `public/assets/ui/avatars/`. `world:generate` обновляет GLB и manifest. Повторяемый осмотр: `node client/scripts/review-avatar-models.mjs client/public/assets/models/avatars /tmp/avatar-review` — шесть ракурсов/поз каждого облика при двух вариантах света, общий ряд и поза прыжка. Это осмотр ассетов, а не замена проверки в игровом клиенте. Новые геометрические снимки не означают независимую художественную приёмку.

Игрок и процедурные NPC: `src/render/three/CharacterRig.ts`, геометрии/материалы через `SceneAssets`. Иерархия: root → torso → head / shoulder → elbow; root → hip → knee → ankle. Длины сегментов ног по 0,38 м. Отдельные суставы каждого экземпляра, общие геометрии и материалы. `CharacterMotion.ts` задаёт темп, повороты, целевую траекторию стопы и аналитическое решение ноги. Полный цикл шага соответствует 1,2 м перемещения; стоящая стопа движется назад в локальных координатах с той же скоростью, что персонаж вперёд. Нет root motion. Визуальное состояние не записывается в Core.

Жители города: `city-residents.mjs` берёт уже собранные облики Ксю и Лукаса (волосы — также Ника и Дэна), перекрашивает одежду, кожу и волосы по палитре с сохранением оттенков, убирает очки и добавляет головной убор и бороду по роли. Каждому новому жителю нужна запись в `LOOKS`, иначе генерация остановится с ошибкой. Результат — одна статичная сетка `resident-<id>.glb` на жителя; Blender для этого не нужен. Люди рынка и пастух собираются тем же кодом через `residentRig`, с суставами для idle-клипов; положение, коллизии, диалоги, asset ID и имена суставов при этом не меняются. Взрослый около 1,8 м, ребёнок 0,72 от взрослого; головной убор и борода — по роли.

Части обликов из Blender (`avatar-parts/<id>.json`, скрипты в `blender/`). Blender 4.2+ нужен только для пересборки частей, для обычной генерации моделей он не нужен. Координаты в соглашении three.js (метры, +Y вверх, +Z вперёд), каждая часть лежит в локальном пространстве своего сустава. Генератор сохраняет риг, клипы и итоговые пропорции, а поверхности берёт из JSON. Источники частей: `build-avatar-parts.py` (авторская скульптура), `import-blend-avatar.py` (разбор вручную собранной фигуры .blend по именам частей и плоскостям отсечения) или `convert-generated-avatar.py` (локально полученная сетка TripoSR, MIT, прогнанная вне репозитория по макетам `docs/game/images/<id>.png`; скрипт ничего не скачивает). `refine-ksu-likeness.py`, `make-lukas-from-blend.py` и `round-blend-avatar.py` правят копию исходного .blend (исходник не меняют), после чего запускается `import-blend-avatar.py`. Исходные .blend в репозиторий не входят. Текстур нет, только цвета вершин и материалов.

Эталоны `fixtures/avatars/approved-neutral.json` (хеши GLB и нейтральные transforms) и `lower-body.json` (`avatarScale`, хеши `knee-*-surface`) переутверждаются осознанно при смене скульптуры; их читают тесты `AvatarModels`, `AvatarWalkPace`, `AvatarJump`. Инварианты, которые не меняются без решения: глубина не больше 0,56 м, темп шага (цикл 1,2 м), контакт стоп, рост из `AVATAR_PROPORTIONS`. Проверка «штаны внутри туники» описывает процедурную запасную скульптуру и идёт на ней (каталог частей подменяется пустым через `AVATAR_PARTS_DIR`). Переутверждение эталонов 2026-11-08 по решению владельца проекта: файлы пересозданы из текущих GLB, пороги ширины/глубины, темпа шага (2–16) и подъёма рук в прыжке (запястье выше плеча более чем на 0,15 м) пересмотрены под равномерный масштаб; визуальной приёмки владельцем в игре это не заменяет. Бюджет облика: меньше 8000 треугольников (после обновления 7494–7650) и 17 draw calls. Слоение одежды при загрузке: `src/render/three/avatarClothLayering.ts`.

Размеры после обновления: облик 450–545 КБ GLB; 23 городских жителя — 223–543 КБ каждый (около 6,4 МБ), 4777–10213 треугольников на жителя (138 тыс. всего), одна сетка без клипов, опора на Y = 0, высота 1,24–2,17 м вместе с головным убором и копьём; `market.glb` около 1,8 МБ, `pasture.glb` около 0,65 МБ. Мир рынка вырос с 21,7 до примерно 29,8 МБ: учитывать при работе с cap 128 MiB. Повторный `npm --prefix client run world:generate` даёт побайтно те же модели.

Рынок и пастух: `generate-market-models.mjs`, функция `merchant`; экспорт в `public/assets/models/market/{market,pasture}.glb`. Редактируется генератор, не бинарник. Плечи привязаны к торсу; локти — к плечам; сосуд и обе удерживающие руки следуют одному торсу. Общий пятисекундный `idle` содержит дорожки отдельных именных групп с разными фазами; цикл замкнут. Статические поверхности объединены по группам с vertex colors, суставы остаются раздельными. Одинаковые итоговые геометрии и материал разделяются между группами при экспорте; это уменьшает GLB без связывания поз экземпляров. Детализация маленьких округлых деталей ниже, чем головы. Материалы матовые, без внешних текстур.

Из корня: `npm --prefix client run world:generate` пересобирает GLB и связанные размеры/хеши manifest. Повторный запуск должен сохранять идентичные бинарники. GLB загружаются только существующим AssetManager, с учётом источников и консервативного memory cap. В коде приложения нет второго загрузчика моделей.

Переходы клипов в `GltfLibrary` занимают 140 мс. Повтор имени сохраняет фазу; быстрый возврат к ещё активному клипу начинает смешивание из текущих весов. Неизвестное имя использует `idle`, когда такой клип есть. Динамический `walk` выбирается по наблюдаемому перемещению, а не только по сетевому имени состояния.

Ручная проверка: приблизить камеру колесом, пройти прямо, отпустить клавиши, быстро сменить W/A/S, упереться в стену, открыть меню и возобновить игру. На рынке проверить гончара и торговцев, на пастбище — пастуха. Точный контакт стоп на декоративной лестнице не подтверждён: её высота не участвует в текущей симуляции.
