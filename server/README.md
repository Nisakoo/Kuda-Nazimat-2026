# Сервер: платформа и данные

Авторитетный мир/Socket.IO v3, HTTP, SQLite, AUTH и OBS объединены. NPC/BABEL используют одну GenerationQueue. В NpcResponder зарегистрированы scripted и локальные Ollama/MLX; LanguagePort BABEL по умолчанию использует test; явный local заимствует тот же локальный responder и общую очередь. Клиент поддерживает парольную регистрацию и вход, загружает мир с Bearer, обменивается чатом и получает финальные NPC-ответы с историей. Development также допускает вход по имени. Полная приёмка TASK-044 остаётся отдельной.

**Python через uv:** `uv python install 3.12` → `make llm-prepare BACKEND=mlx` или `BACKEND=ollama`; зависимости фиксируются в `llm/envs/*/uv.lock`. [Установочный скилл](../.agents/skills/install-local-ai/SKILL.md).

**LLM с нуля:** [SETUP](llm/SETUP.md). Уже подготовленная машина: `make server NPC_TIMEOUT=60`; явный профиль: `make server BACKEND=ollama MODEL=2b NPC_TIMEOUT=120`. [Профили](llm/PROFILES.md), [timeout](llm/TIMEOUT.md), [границы runtime](llm/README.md). Не запускать `make llm-import` как универсальный установщик: это однократный перенос существующих 0.8B/2B конфигов.

## Подготовка и команды

Закреплён **Node 24.15.0** (`.node-version`, `engines >=24.15.0 <25`), npm и Make. Проверяйте `node --version`, а не только имя каталога runtime. Зависимости готовятся до отключения интернета:

```sh
npm --prefix server ci
npm --prefix client ci
make server-test
npm --prefix server run check:platform
npm --prefix server run check
```

`check:platform` проверяет типы набора B, чистый shared без DOM/Node и импорты всех модулей. Это промежуточная проверка; обязательный полный `check` после интеграции A также проходит.

## Окружения (SERVER-009)

| | development (по умолчанию) | production | test |
|---|---|---|---|
| Как запустить | `make server`, `npm --prefix server start` | `make start`, `npm --prefix server run start:prod`, `--env production` | `--env test`, автотесты |
| Вход | имя без пароля, автовход `POST /api/auth/dev`, а также пароль | только пароль | как development |
| БД | `data/dev.sqlite` | `data/game.sqlite` | `data/test.sqlite` |
| Консоль / файл логов | debug / debug | info / debug | warn / выключен |
| Прочее | CORS для Vite `:5173`, `/config.json` с `debug: true`, проверка исходящих пакетов | — | — |

Окружение выбирается `--env` или `APP_ENV`, порт — `--port` или `PORT`, адрес — `HOST`; итог: defaults → пресет → `config.json` → переменные → аргументы. Включить вход без пароля в production нельзя — сервер не стартует. CLI принимают те же флаги: `npm --prefix server run inspect -- --env production`.

## Аккаунты и пароли (AUTH)

Пароль — от 6 символов, хранится как scrypt. Пять неверных попыток блокируют имя на 15 минут (повторно — на час); выход отзывает сессию сразу, смена пароля — все сессии. Забыл пароль — администратор выдаёт временный на `/operator` или `npm --prefix server run auth -- reset-password <имя> --env production`; игрок входит с ним и задаёт свой. `auth -- list` — аккаунты без хешей, `auth -- revoke <имя>` — завершить сессии.

## Логи и метрики (OBS)

Журнал — `data/logs/server-*.jsonl` (JSON на строку: `ts`, `level`, `event`, `msg`, `playerId`, `sessionId`, …), ротация 20 МБ, всего ≤200 МБ и ≤14 дней. При первой ошибке и по кнопке «Сохранить отчёт» на `/operator` бортовой самописец пишет `incident-*.jsonl` с последними 5000 событиями, снимком метрик и последними 10 минутами истории — это главный источник для плавающих ошибок. Пароли, токены, хеши и тексты игроков в журнал не попадают.

Внешний Prometheus/Grafana не нужен (OBS-009 снято): сервер сам держит историю метрик — снимок раз в 10 с за последние 4 часа в памяти (OBS-013) — и отдаёт её экрану администратора: `GET /api/operator/status` (плитки и карточки), `GET /api/operator/history` (ряды для графиков), `GET /api/operator/metrics` (текущий JSON-снимок реестра); всё только с loopback. Раз в минуту в журнал пишется событие `metrics.minute` — минутный агрегат истории (игроки, корзины шага/рассылки/RTT/NPC, ошибки, память, показатели по `playerId`). Выгрузка для Excel:

```sh
jq -r 'select(.event=="metrics.minute") | [.ts, .values.seated, .values.errors, .values.warnings, .values.rssBytes] | @csv' server/data/logs/server-*.jsonl > metrics.csv
```

Отчёт приёмки (OBS-017, OFFLINE-019) — без запущенного сервера, markdown-таблица «показатель — значение — порог — итог» (p95 шага ≤ 5 мс, p95 рассылки ≤ 120 мс, ошибки сервера 0, p95 ping ≤ 150 мс, FPS ≥ 30, таймауты NPC ≤ 25%, потерянные логи 0); «нет данных» никогда не считается нормой:

```sh
npm --prefix server run report                       # последний запуск в каталоге логов окружения
npm --prefix server run report -- --env production --last 2h
npm --prefix server run report -- --file server/data/logs/server-20261101-ab12cd34.jsonl
```

При штатной остановке (Ctrl+C) сервер печатает ту же таблицу за текущий запуск. FPS появляется, только если клиент присылает отчёты `perf` (`POST /api/telemetry/client`, OBS-011, передача клиенту — TASK-081).

Запуск из корня ([OFFLINE](../specs/offline-multiplayer.md)):

```sh
make prepare            # один раз, с интернетом: npm ci, сборка клиента и мира, lan:check
make start              # перед игрой, без интернета (make demo — синоним)
make start PORT=9000    # если порт 8080 занят
npm --prefix server run lan:check   # самопроверка без запуска игры
```

`make start` устанавливает зависимости только при отсутствии `node_modules`, собирает клиент вместе с миром и запускает сервер. При готовности печатается блок подключения: адрес этого компьютера, адреса для других устройств по интерфейсам (частные сети первыми, link-local помечены «нет сети»), адрес экрана администратора и подсказка по брандмауэру. Занятый порт даёт понятную ошибку с подсказкой `--port`; в Windows порт, занятый другой программой, приходит как `EACCES` и сообщается так же. Без `make`: `npm --prefix client run build`, затем `npm --prefix server start -- --port 9000`.

`lan:check` печатает версию Node, интерфейсы, свободен ли порт, найдены ли сборка клиента и мир (с полной проверкой мира), открывается ли БД и подходит ли её схема, инструкцию брандмауэра; ненулевой код, если запуск невозможен.

Панель администратора — `https://localhost:8080/operator`, только с самого сервера (с других адресов 404). Разделы «Обзор», «Сервер», «Клиенты» и «Аккаунты» показывают адреса подключения, занятые места отдельно от игроков онлайн, RTT и переподключения, состояние NPC/переводчика, окружение, версию, память, очередь и предупреждения. Статус обновляется раз в 2 с; при сбое остаются последние данные с временем. Кнопка «Обновить» повторяет запросы. Поиск игроков и фильтр карты работают в «Клиентах». В «Аккаунтах» введите полное имя: доступны число сессий, состояние блокировки и подтверждаемые действия AUTH-010; временный пароль показывается в отдельном окне и очищается после закрытия, смены раздела или скрытия вкладки. «Сохранить отчёт» находится в «Сервере».

Панель содержит обзор, сервер, клиентов, редактор NPC и сцены, журнал с CSV и аккаунты. Графики используют встроенную историю; FPS появится после клиентского TASK-081. Локальные API — `/api/operator/*`, административные API с отдельным Bearer — `/api/admin/*`. Неполученные показатели показываются как «нет данных».

## Администратор в Windows (PowerShell)

Из корня проекта, Node 24.15+ из ветки 24. Команды должны использовать ту же конфигурацию и окружение, что сервер:

```powershell
npm.cmd --prefix server run auth -- create-admin Admin --env production
npm.cmd --prefix server run auth -- list --env production
npm.cmd --prefix server run start:prod
```

Терминал покажет временный пароль один раз. После установки сертификата откройте `https://localhost:8080/admin` (или LAN-адрес сервера), войдите и задайте постоянный пароль. Для уже существующего аккаунта с паролем: `npm.cmd --prefix server run auth -- grant-admin "ИмяИгрока" --env production`; снять роль: `revoke-admin`. Окружение development использует другую БД: для него замените `--env production` на `--env development`. `/operator` открывается без входа только на самом компьютере сервера. Административная сессия хранится только в памяти страницы и не занимает игровое место.

## HTTPS и доверие сертификату

Весь игровой трафик (страница, вход, API, мир, Socket.IO) идёт только по HTTPS/WSS на том же порту 8080; режима без TLS нет ([TLS](../specs/server-tls.md)). Сервер сам создаёт самоподписанный сертификат при первом запуске или `make prepare` (`server/data/tls/server.crt`, ключ `server.key` с правами `0600`, не коммитится и никуда не отдаётся). Интернет не нужен.

Браузер игрока не знает этот сертификат, поэтому **один раз на каждом устройстве**:

1. Откройте `http://<IP сервера>:8080/setup` (адрес и отпечаток печатает сервер при запуске и показывает `/operator`).
2. Скачайте сертификат и **сверьте отпечаток SHA-256** с экраном ведущего: файл скачан по открытому HTTP.
3. Установите по инструкции на странице: macOS — «Связка ключей» → «Всегда доверять»; Windows — «Доверенные корневые центры сертификации» (текущий пользователь); Linux/Chrome — менеджер сертификатов; Firefox — исключение для сертификата.
4. Откройте `https://<IP сервера>:8080/` — замок без предупреждений.

Сертификат привязан к адресам, которые были у ноутбука при создании (`localhost`, IP интерфейсов, `<имя>.local`, `tls.extraNames`). Сервер **сам не перевыпускает** его: если IP сменился, `/operator`, блок подключения и `lan:check` предупредят, а игроки увидят ошибку имени. Исправление — `npm --prefix server run tls -- renew --yes` и повторное прохождение `/setup` на всех устройствах. Чтобы смена IP не ломала игру, закрепите IP на роутере (OFFLINE-007) или добавьте стабильное имя в `tls.extraNames`.

```sh
npm --prefix server run tls -- status          # отпечаток, срок, покрытие адресов, права
npm --prefix server run tls -- init            # создать сертификат, если его нет
npm --prefix server run tls -- renew --yes     # выпустить новый (устройства доверяют заново)
npm --prefix server run tls -- export cert.crt # только сертификат, без ключа
```

| Симптом | Причина | Действие |
|---|---|---|
| «Подключение не защищено» | устройство ещё не доверяет сертификату | пройти `/setup`; на `/operator` виден IP такого устройства |
| ошибка имени (`ERR_CERT_COMMON_NAME_INVALID`) | адрес сервера не указан в сертификате | `tls status`, затем `tls renew --yes` и `/setup` заново |
| сервер не запускается: сертификат истёк или файлы повреждены | срок 825 дней вышел или файлы испорчены | `tls renew --yes`, `/setup` заново |
| `http://…` сразу уходит на https | так задумано (308) | открывать `https://` |
| Firefox всё ещё предупреждает | у Firefox своё хранилище | добавить исключение (инструкция на `/setup`) |

## Конфигурация

Отсутствующий стандартный `server/config.json` означает документированные defaults. Для своей конфигурации скопируйте `config.example.json` в `config.json`; файл исключён из git. Иной путь:

```sh
npm --prefix server start -- --config /absolute/path/config.json
```

Относительные пути разрешаются от каталога JSON, не cwd. Неизвестные ключи, неверные типы и недопустимые лимиты отклоняются до открытия порта. Полная таблица defaults — [SERVER-004](../specs/server-foundation.md): `0.0.0.0:8080`, `../client/dist`, `../client/public`, карты market/demo/science, `content/`, `data/game.sqlite`, четыре игрока, TTL 12 часов, симуляция/рассылка 20/10 Hz, сохранение 10 секунд. `corsOrigins: []` означает same-origin; для Vite укажите точный origin, например `https://localhost:5173` (Vite должен работать по HTTPS). `logWorldAccess` по умолчанию false.

`npc` по умолчанию: `adapter: scripted`, `maxConcurrent: 1`, `maxUnfinished: 4`, `timeoutMs: 30000`, `streamTimeoutMs: 30000`, `options: {}`. Оба общих timeout допускают1–300000мс; Make `NPC_TIMEOUT=60` задаёт секунды1–300 на запуск для обоих полей, без записи config/profile. Без override явно заданный streamTimeoutMs сохраняется отдельно. Клиент получает effective npcTimeoutMs из `/api/game-config` и ждёт плюс2000мс, остальные pending10с. Для реальных Ollama/MLX concurrency допускается только1; для scripted конфиг сохраняет1–2, unfinished1–4. `language` по умолчанию: `adapter: test`, `options: {}`. Профиль concurrency 2 для реальной модели требует отдельной квалификации. Опции заглушки: `delayMs` (300), `failEvery` (0). Неизвестные опции отклоняются. Новый адаптер реализует [NpcResponder](src/npc/NpcResponder.ts), регистрируется в `src/npc/adapters/index.ts` и проходит [контрактные тесты](test/responderContract.ts). Заглушка демонстрирует доставку сохранённой истории, не адаптивность ИИ.

## HTTP и граница frontend

- `GET /` — сборка клиента; публичные `maps/` и `assets/models/`, traversal, листинги и выходящие за корень symlink недоступны.
- `GET /config.json` — `{session: "online", serverUrl: null, mapId, chunkRadius: null, debug: false}` из настроек сервера.
- `GET /api/health` — публичный статус готовности; ready не доказывает качество/скорость реальной модели.
- `GET /api/game-config` — только `{npcTimeoutMs}` из эффективной конфигурации, no-store/обычный CORS; без model paths/options/pins.
- `GET /operator`, `GET /api/operator/status`, `GET /api/operator/history`, `GET /api/operator/metrics` — экран администратора и его данные, только с loopback.
- `/api/operator/npcs`, `/api/operator/world`, `/api/operator/journal(.csv)`, `/api/operator/accounts`, `/api/operator/account` — правка, создание и удаление NPC на ходу поверх `content/npcs.json` (правки в SQLite, «сбросить» возвращает файл), сброс живой сцены, журнал изменений с CSV и карточка аккаунта; только loopback, изменения — с `Origin` сервера и `X-Operator: 1`. Контракт — [ADMIN-SRV](../specs/server-admin-content.md). У NPC рынка без `assetId` фигура нарисована в чанке: их можно переименовать, сменить тему, характер и приветствие или выключить, но не переместить.
- `POST /api/telemetry/client` — отчёты клиента об ошибках (10/мин) и `perf` (`fps`, `visible`, по желанию `frameMs`, `drawCalls`; 12/мин), Bearer-сессия, OBS-011.
- `POST /api/auth/guest`, JSON `{name}` — совместимость development/test; production требует парольного login. Регистрация/login/logout/password/dev и ограничения описаны в [AUTH](../specs/server-auth.md).
- `GET /world/*` — только Bearer действующей сессии и решение `GameRuntime.worldFile` набора A; 401 без сессии, 404 без доступа к ресурсу.

Имя 1–32 символа после trim, без управляющих символов. Регистр не меняет идентичность; отображаемое имя сохраняется с первого входа. В development guest допускает вход по чужому имени: это риск dev-режима, не защита production. HTTP LAN не шифрует токен. Сессии случайные, в БД только SHA-256; UI очищает токен и запрашивает отзыв серверной сессии; ошибка подтверждения отзыва отображается отдельно. Токены и полные тексты диалогов не попадают в operational-логи. После reload токен не восстанавливается автоматически.

Frontend использует корневой shared и формы регистрации и парольного входа. Demo guest-вход по имени отделён от парольной регистрации. Повторный вход восстанавливает игрока; другая вкладка того же аккаунта перехватывает управление. Выход доступен до прогулки и в меню. Ошибки сети и сессии показываются текстом; после истечения нужен новый вход. Механики BABEL описаны ниже; клиент пока не использует поток NPC. Реальные Ollama/MLX выбираются оператором, не включаются автоматически и ещё не квалифицированы на целевом оборудовании.

Локальная прогулка и mock-сеть доступны в отдельно запущенном клиентском демо. Серверная поставка закрывает публичные maps/models, поэтому эти режимы в ней не могут загрузить мир; публичного fallback нет. Скрытие этих режимов в серверной поставке — клиентская задача (OFFLINE-014), Bearer-защита не ослабляется.

## Данные и восстановление

```sh
npm --prefix server run inspect
npm --prefix server run inspect -- --config /absolute/path/config.json
npm --prefix server run backup -- /absolute/path/backup.sqlite
npm --prefix server run backup -- /absolute/path/backup.sqlite --config /absolute/path/config.json
```

`inspect` открывает БД read-only, показывает путь, аккаунты, позиции, количество действующих сессий, число диалогов и последние вопросы (до 60 символов). Токены, хеши и полные ответы не выводятся. WAL допускает чтение при работающем сервере.

`backup` открывает исходную БД read-only (отсутствующий файл не создаётся), выполняет параметризованный `VACUUM INTO` и требует новый файл: существующая копия не перезаписывается. При остановленном сервере можно копировать файл БД вместе с имеющимися файлами `-wal` и `-shm` как единый комплект. Не копируйте только основной файл работающей WAL-БД.

Для проверки восстановления используйте отдельный каталог и отдельный JSON с `dbPath` на копию. Сначала выполните `inspect --config …`, затем проверку `PRAGMA integrity_check` локальным SQLite-инструментом; если запускаете вторую копию сервера, укажите другой порт. Текущая БД не заменяется. Автотесты проверяют согласованную копию, чтение после перезапуска и целостность после SIGKILL. Периодическое и grace-сохранение проверены через реальный A+B; при SIGKILL между сохранениями с интервалом 10 с измерено окно 5159 мс, восстановлена последняя committed-позиция. Ручной сценарий: `node server/test/crash-recovery.ts` из корня на Node 24.

На пару игрок/NPC хранятся последние 50 ответов; ответчик получает последние шесть в хронологическом порядке. Вопрос/ответ фиксируются одной транзакцией до разрешения ответа владельцу. Отмена и timeout не создают историю. При зависшем после abort ответчике слот остаётся занятым; через две секунды пишется ошибка. Сессии, истёкшие более суток назад, очищаются при запуске и раз в час. SQLite и backup не зашифрованы, доступ к ним ограничивает локальный оператор.

## Сценарий защиты

В отдельном клоне проверены два запуска make demo с подготовленными зависимостями и сохранением игроков/истории. В браузерных тестах проверены вход, мир demo/market, две вкладки, чат и память NPC после перезапуска. Полная шестиминутная репетиция, физическая LAN и отключение Wi-Fi остаются отдельными проверками.

1. До защиты: подготовить зависимости, выполнить тесты и полный `check`, собрать клиент/мир. Проверить `make demo`, localhost- и LAN-адреса в stdout, затем повторить запуск с той же БД.
2. 00:30–02:00: открыть напечатанный адрес, войти как «Аня», пройти рынок. Включить `logWorldAccess`, показать запросы ближайших ресурсов; дальние ресурсы — 404.
3. 02:00–03:00: открыть вторую вкладку/ноутбук, войти как «Борис» и показать двух игроков и чат. Один и тот же логин перехватывает управление, а не создаёт второго игрока.
4. 03:00–04:00: спросить пастуха «Что ест козлёнок?», переподключиться, штатно перезапустить сервер и повторить вопрос от «Ани». Показать ссылку на прошлый вопрос и другое объяснение. Прямо назвать ответчик заглушкой порта для будущей локальной модели.
5. 04:00–05:00: показать [диаграмму](../architecture.md), `inspect`, позицию/счётчик диалогов, лог размеров карты, окно до25чанков и payload guard64MiB.
6. При сбое: повторить вход под тем же именем; проверить `/api/health` и `inspect`. Если NPC unavailable, показать сохранённую историю и статус порта. Не объявлять недоступную функцию работающей.

Физический второй ноутбук и действительно выключенный Wi-Fi — отдельная приёмка TASK-016. Компонентные проверки B с тестовым GameRuntime отделены от интеграционных тестов реального createGame и браузерных сценариев.


## Дополнение BABEL

Карта `market` использует серверные группы 1–4, языки, покупки/кормление, общие камни и личный словарь. Данные добавляет миграция `002.sql`; существующая 001 сохранена, миграции применяются последовательно и атомарно. Перед обновлением рабочей БД используйте описанный выше backup. После входа открывается кабинет с обликом и языками; отдельные create/join создают или продолжают задание. Миграция 006 сохраняет профиль до группы, а проверка схемы восстанавливает недостающие поля старых dev-баз с пересечением версий; прежние карты сохраняют свой NPC/chat v1.

`POST /api/babylon` защищён Bearer-сессией, игровые действия требуют управляющего Socket.IO-соединения. Контракт — [PROTO-009](../specs/protocol.md). По умолчанию явно выбран TestLanguagePort: известные тестовые переводы и подготовленные NPC-ответы, произвольные фразы возвращают ошибку. Этот режим не доказывает качество реальной LLM.

Явный `language.adapter: local` создаёт borrowed `LanguagePort` над уже созданным Ollama/MLX responder ([NPC-009](../specs/server-npc-dialogue.md)). У него нет отдельного start/stop модели: lifecycle и recovery остаются у NPC runtime. `translate` — отдельная IPC-операция без NPC persona/истории; `answer` использует серверный en/es и отфильтрованную AUTH-историю. Одна GenerationQueue: 4 unfinished, 1/player, concurrency 1; последовательные переводы расходуют один исходный монотонный бюджет. При отказе нет перехода в test и автоматического повторения вопроса. Четвёртый аргумент `startApplication` остаётся для тестов. Технически доступные ru/en/es для перевода и en/es для NPC не означают квалификацию качества. Политика данных и текущие wire-лимиты — [BABEL](../specs/game-babylon.md), SQLite — STORE-012.

Для подготовленной модели измените **только** `defaultMap` на `market` и `language` на `{ "adapter": "local", "options": {} }` в своём `server/config.json`; не заменяйте файл целиком и не теряйте существующие `npc`, пути, hashes или каталог профилей. Запуск — прежний `make start` (при использовании profiles: например `make start BACKEND=ollama MODEL=2b`). В игре выберите изучаемый en или es. Текущий BABEL-клиент ждёт HTTP-запрос 30 секунд: увеличение серверного `NPC_TIMEOUT` само по себе не увеличивает это клиентское ожидание. Scripted responder не совместим с local-мостом и даёт явную конфигурационную ошибку. Старые конфиги без `language` по-прежнему выбирают test. Настоящая модель на этом этапе не запускалась: проверены fake workers/оркестрация, а не реальное качество или скорость.

## Движение MOVE

Игровой Socket.IO использует v3; клиент и сервер поставляются вместе, v1/v2 получают VERSION. Формы NPC npc-question/npc-answer и HTTP BABEL v2 сохраняются.

## Потоковый ответ NPC

`npc-question` с `stream: true` получает до финального `npc-answer` временные `npc-partial {requestId, targetId, seq, text}` — весь текст на данный момент, не чаще 10 раз/с, volatile; `npc-cancel {questionId}` отменяет вопрос и подтверждается `npc-cancelled`. Без `stream` всё как раньше, поэтому текущий клиент ничего не замечает. Дедлайн потокового вопроса — `npc.streamTimeoutMs`. Адаптер модели стримит, вызывая `onPartial(textSoFar)` в `NpcResponder.answer`; заглушка `scripted` уже выдаёт три растущих префикса. Контракт — [PROTO-007](../specs/protocol.md), [NPC-008](../specs/server-npc-dialogue.md). Space — однократный прыжок, удержание Shift — спринт с авторитетной выносливостью. Общая симуляция в shared/movement; перекрытия берутся из подготовленного manifest без импорта client/. Новую карту нужно подготовить командой сборки клиента до запуска сервера. SQLite получает безопасную опору; после рестарта незавершённый прыжок не воспроизводится.

### Браузерная проверка панели

После подготовки серверных зависимостей и Playwright из `client/package.json`:

```sh
node server/test/operator.browser.mjs
```

Запуск из корня создаёт временный мир/SQLite, поднимает настоящий сервер и проверяет Chromium; после выполнения сервер и временные данные удаляются. `OPERATOR_BROWSER_PACKAGE` позволяет указать абсолютный путь к другому установленному `package.json` с Playwright, `OPERATOR_CHROMIUM_EXECUTABLE` — к уже подготовленному Chromium. Скриншоты — `tasks/evidence/admin-panel/`. Проверка порогов и HTTP-сбоев использует явно заданные ответы API; это не замер железа или FPS клиента.
