# Сервер: платформа и данные

Набор B: HTTP, mock-вход, SQLite v1 и очередь NPC с детерминированной заглушкой. Контракт с набором A — `src/contracts.ts`; он не изменён. Полный игровой запуск пока заблокирован: в базовом `main` нет `src/game/index.ts` с `createGame`, realtime и NPC-контента. `make server` сообщает об этой зависимости и завершается с кодом 1. Подмена игрового сервера заглушкой в поставке не используется.

## Подготовка и команды

Закреплён **Node 24.15.0** (`.node-version`, `engines >=24.15.0 <25`), npm и Make. Проверяйте `node --version`, а не только имя каталога runtime. Зависимости готовятся до отключения интернета:

```sh
npm --prefix server ci
npm --prefix client ci
make server-test
npm --prefix server run check:platform
npm --prefix server run check
```

`check:platform` проверяет типы набора B, чистый shared без DOM/Node и импорты всех модулей. Это промежуточная проверка; она **не заменяет** обязательный полный `check`. Последний пока падает на коде A из main (подробности в evidence).

После слияния готового A:

```sh
make demo
# либо после подготовки сборки клиента и мира:
make server
```

`make demo` устанавливает зависимости только при отсутствии `node_modules`, собирает клиент вместе с миром и запускает сервер. Миграции применяются до открытия HTTP-порта. Повторный запуск использует ту же БД. Runtime не обращается в интернет; установка npm-пакетов требует сети либо заранее подготовленного кеша. `make demo` до готовности A не считается принятым.

## Конфигурация

Отсутствующий стандартный `server/config.json` означает документированные defaults. Для своей конфигурации скопируйте `config.example.json` в `config.json`; файл исключён из git. Иной путь:

```sh
npm --prefix server start -- --config /absolute/path/config.json
```

Относительные пути разрешаются от каталога JSON, не cwd. Неизвестные ключи, неверные типы и недопустимые лимиты отклоняются до открытия порта. Полная таблица defaults — [SERVER-004](../specs/server-foundation.md): `0.0.0.0:8080`, `../client/dist`, `../client/public`, карты market/demo/science, `content/`, `data/game.sqlite`, четыре игрока, TTL 12 часов, симуляция/рассылка 20/10 Hz, сохранение 10 секунд. `corsOrigins: []` означает same-origin; для Vite укажите точный origin, например `http://localhost:5173`. `logWorldAccess` по умолчанию false.

`npc` по умолчанию: `adapter: scripted`, `maxConcurrent: 1`, `maxUnfinished: 4`, `timeoutMs: 8000`, `options: {}`. Допустимы concurrency 1–2, unfinished 1–4, timeout 1–9000 мс. Профиль concurrency 2 для реальной модели требует отдельной квалификации. Опции заглушки: `delayMs` (300), `failEvery` (0). Неизвестные опции отклоняются. Новый адаптер реализует [NpcResponder](src/npc/NpcResponder.ts), регистрируется в `src/npc/adapters/index.ts` и проходит [контрактные тесты](test/responderContract.ts). Заглушка демонстрирует доставку сохранённой истории, не адаптивность ИИ.

## HTTP и граница frontend

- `GET /` — сборка клиента; публичные `maps/` и `assets/models/`, traversal, листинги и выходящие за корень symlink недоступны.
- `GET /config.json` — `{session: "online", serverUrl: null, mapId, chunkRadius: null, debug: false}` из настроек сервера.
- `GET /api/health` — `{status: "ok", protocol: 1, npc: "ready" | "unavailable"}`.
- `POST /api/auth/guest`, JSON `{name}` не больше 1 KiB — ровно `{token, expiresAt}`; неверное имя/лишние поля — 400 `{error: {code: "INVALID", message}}`.
- `GET /world/*` — только Bearer действующей сессии и решение `GameRuntime.worldFile` набора A; 401 без сессии, 404 без доступа к ресурсу.

Имя 1–32 символа после trim, без управляющих символов. Регистр не меняет идентичность; отображаемое имя сохраняется с первого входа. Любой участник может войти под чужим именем: это принятый риск mock-входа. HTTP LAN не шифрует токен. Сессии случайные, в БД только SHA-256; локальный выход клиента не отзывает серверную сессию. Токены и полные тексты диалогов не попадают в operational-логи.

Frontend уже использует корневой shared, но пока не вызывает `/api/auth/guest` из UI. [TASK-028](../tasks/028-client-guest-login.md) описывает недостающий вызов и критерии; ручная вставка токена не считается приёмкой. Инвентарь, камень, словарь, перевод, потоковый PROTO v2 и реальная LLM сюда не входят.

## Данные и восстановление

```sh
npm --prefix server run inspect
npm --prefix server run inspect -- --config /absolute/path/config.json
npm --prefix server run backup -- /absolute/path/backup.sqlite
npm --prefix server run backup -- /absolute/path/backup.sqlite --config /absolute/path/config.json
```

`inspect` открывает БД read-only, показывает путь, аккаунты, позиции, количество действующих сессий, число диалогов и последние вопросы (до 60 символов). Токены, хеши и полные ответы не выводятся. WAL допускает чтение при работающем сервере.

`backup` открывает исходную БД read-only (отсутствующий файл не создаётся), выполняет параметризованный `VACUUM INTO` и требует новый файл: существующая копия не перезаписывается. При остановленном сервере можно копировать файл БД вместе с имеющимися файлами `-wal` и `-shm` как единый комплект. Не копируйте только основной файл работающей WAL-БД.

Для проверки восстановления используйте отдельный каталог и отдельный JSON с `dbPath` на копию. Сначала выполните `inspect --config …`, затем проверку `PRAGMA integrity_check` локальным SQLite-инструментом; если запускаете вторую копию сервера, укажите другой порт. Текущая БД не заменяется. Автотесты проверяют согласованную копию, чтение после перезапуска и целостность после SIGKILL. Временное окно потери позиций проверяется с периодическим сохранением набора A при TASK-026.

На пару игрок/NPC хранятся последние 50 ответов; ответчик получает последние шесть в хронологическом порядке. Вопрос/ответ фиксируются одной транзакцией до разрешения ответа владельцу. Отмена и timeout не создают историю. При зависшем после abort ответчике слот остаётся занятым; через две секунды пишется ошибка. Сессии, истёкшие более суток назад, очищаются при запуске и раз в час. SQLite и backup не зашифрованы, доступ к ним ограничивает локальный оператор.

## Сценарий защиты

Это сценарий **для репетиции после интеграции A и TASK-028**; полный браузерный прогон пока не выполнен.

1. До защиты: подготовить зависимости, выполнить тесты и полный `check`, собрать клиент/мир. Проверить `make demo`, localhost- и LAN-адреса в stdout, затем повторить запуск с той же БД.
2. 00:30–02:00: открыть напечатанный адрес, войти как «Аня», пройти рынок. Включить `logWorldAccess`, показать запросы ближайших ресурсов; дальние ресурсы — 404.
3. 02:00–03:00: открыть вторую вкладку/ноутбук, войти как «Борис» и показать двух игроков и чат. Один и тот же логин перехватывает управление, а не создаёт второго игрока.
4. 03:00–04:00: спросить пастуха «Что ест козлёнок?», переподключиться, штатно перезапустить сервер и повторить вопрос от «Ани». Показать ссылку на прошлый вопрос и другое объяснение. Прямо назвать ответчик заглушкой порта для будущей локальной модели.
5. 04:00–05:00: показать [диаграмму](../architecture.md), `inspect`, позицию/счётчик диалогов, лог размеров карты и лимит кеша 10%.
6. При сбое: повторить вход под тем же именем; проверить `/api/health` и `inspect`. Если NPC unavailable, показать сохранённую историю и статус порта. Не объявлять недоступную функцию работающей.

Физический второй ноутбук и действительно выключенный Wi-Fi — отдельная приёмка TASK-016. Проверки B с тестовым `GameRuntime` доказывают только границу платформы, не реальную синхронизацию мира.
