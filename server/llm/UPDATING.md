# Обновление подготовленной LLM-установки после rebase

Это не новая установка. Сохраните модели, tokenizer, pins, venv, `~/kuda-llm/profiles.json`, `server/config.json` и рабочую БД. Не скачивайте модели повторно и не запускайте `make llm-import` для обычного обновления. Новая установка описана в [SETUP](SETUP.md).

## Перед обновлением

1. Остановите игру штатно. При неподтверждённом cleanup не запускайте второй runtime.
2. На прежнем коде проверьте активное окружение и путь рабочей БД. Создайте согласованный backup в новый файл:

   ```sh
   npm --prefix server run backup -- "$HOME/kuda-llm/game-before-rebase.sqlite"
   ```

   Для нестандартного config добавьте `--config /absolute/game.json`. Не перезаписывайте существующую копию. Если источник не найден или путь неизвестен, остановитесь и уточните его. Сохраните отдельно копии config и profiles; не публикуйте их в git.
3. Проверьте `git status --short`. Сохраните собственные изменения отдельно и согласуйте их перенос. Не выполняйте `git reset` или `git clean`; не удаляйте ignored config, веса или БД.

## Обновление

После `git fetch origin` проверьте имя нужной удалённой ветки. Если `git pull --ff-only` невозможен из-за переписанной истории, не сбрасывайте старую ветку. При чистом tracked worktree создайте новую локальную ветку от проверенной удалённой ветки:

```sh
git switch -c local/llm-rebased origin/npc-llm-clean-start
```

Если remote ref или имя локальной ветки отличается, проверьте его и выберите другое свободное имя. Старая ветка остаётся нетронутой. Обновите npm dependencies по lockfile только при необходимости, используя подготовленный кеш или сеть на этапе подготовки. Не переустанавливайте Python или модель автоматически.

Клиент, сервер и generated world нужно обновлять вместе: игровой протокол — v3. Перед первым запуском убедитесь, что backup проверенной рабочей БД доступен. Main сохраняет миграции 003–008; интеграция NPC scope использует 009 и reconciliation старой branch-схемы версии 4. Не считайте проверку обновления БД пройденной до фактического результата интеграции. Откат только кода поверх обновлённой БД не является восстановлением backup.

```sh
npm --prefix client run build
HOST=127.0.0.1 make server NPC_TIMEOUT=120
```

`make server` использует development; `make start` и `make demo` — production с парольным входом. Клиент поддерживает парольные формы и logout; полная browser-приёмка остаётся открытой. Без явного `dbPath` development использует `server/data/dev.sqlite`, production — `server/data/game.sqlite`. Для прежних данных после backup укажите проверенный путь прежней БД в config; не заменяйте её пустой базой.

`NPC_TIMEOUT=120` задаёт 120 секунд на запрос, включая очередь; клиент получает срок от сервера и ждёт дополнительно 2 секунды. На рынке `language.adapter: test` остаётся явным тестовым режимом. Явный `language.adapter: local` использует общий локальный NPC responder и очередь без второй модели; он не является автоматическим fallback. После сборки обновите вкладку и проверьте конфигурацию и готовность runtime.

Качество, RAM, производительность и физические offline/LAN-проверки выполняются отдельно. Обновление не квалифицирует модель или оборудование.
