# Timeout NPC при запуске: целые секунды в Make

Для уже подготовленной игры из корня checkout:

```sh
make server BACKEND=ollama MODEL=2b NPC_TIMEOUT=60
```

Это **60 секунд на весь вопрос**, включая FIFO-очередь. `NPC_TIMEOUT` принимает целое число **1–300**, без `s`, `m`, дробей, `0` или `Infinity`. Например, `NPC_TIMEOUT=15` —15с, `NPC_TIMEOUT=120` —2минуты. Ошибка значения останавливает запуск понятным сообщением; значение не обрезается молча.

Если подготовленный выбор уже сохранён, модель можно не указывать:

```sh
make server NPC_TIMEOUT=60
```

`BACKEND/MODEL` требуют подготовленного профиля; разовый перенос существующих файлов описан в [PROFILES](PROFILES.md). Если profiles.json уже существует, importer повторно не запускать. Timeout сам по себе не требует импорта, новой модели, весов, venv или reinstall.

`make demo BACKEND=ollama MODEL=2b NPC_TIMEOUT=60` передаёт тот же срок, но demo сохраняет свою подготовку dependencies/build/world. Для обычного запуска уже собранной игры использовать server: он ничего не устанавливает и не скачивает.

## Приоритет и сохранение

1. CLI `--npc-timeout 60` (секунды), затем Make `NPC_TIMEOUT` / env `KUDA_NPC_TIMEOUT` (секунды).
2. `npc.timeoutMs` в server config (миллисекунды1–300000).
3. Default30000мс, если поле в config отсутствует.

```sh
npm --prefix server start -- --npc-timeout 60
```

Override действует **только на текущий запуск**, не записывает config, profiles.json или сохранённый выбор. Смена модели не сбрасывает timeout. Импорт сохраняет допустимый timeout, например60000; только прежний явно описанный перенос legacy8000→30000 остаётся исключением. При неверном base config приложение всё равно отказывает, override не скрывает ошибки остальных полей.

При следующем запуске без NPC_TIMEOUT применяется config/default, а не прошлый Make override. Значение устанавливает оператор сервера, не игрок и не модель. Для смены срока остановить сервер через Ctrl+C, дождаться освобождения процессов и запустить заново. Горячее изменение не реализовано.

## Обновить уже подготовленный Mac один раз

После обновления ветки npc-llm-clean-start с этой реализацией требуется **одна новая сборка клиента**, даже если прежний32с клиент уже был собран:

```sh
npm --prefix client run build
```

Node24/dependencies должны быть уже подготовлены. Новый clone/install/model pull не нужен. Нестандартный clientDir должен указывать на эту новую сборку. Затем:

```sh
make server NPC_TIMEOUT=60
```

Лог `Выбран профиль NPC` для реального адаптера должен показать `timeoutMs:60000`, затем дождаться `NPC готов к вопросам`. Открыть/перезагрузить страницу игры. **После этой однократной сборки** для другого timeout достаточно нового Make запуска, без пересборки клиента.

## Что ограничено

- Весь серверный запрос от приёма, включая очередь, подготовку и генерацию. Если из минуты20с потрачено в очереди, остаётся40с, не новая минута.
- Клиент получает публичный `/api/game-config` с effective npcTimeoutMs от фактического serverUrl при connect/reconnect и ждёт ещё2с на доставку. При60с серверного бюджета клиентский pending62с. Остальные запросы10с.
- Если timing metadata не получена/невалидна, NPC запрос недоступен с понятной ошибкой. Клиент не угадывает старый32с предел. Join/мир/чат не должны блокироваться. Старые ответы на metadata после disconnect/dispose игнорируются.
- Progress и перевод системных часов назад не добавляют время. На deadline ответ не сохраняется, поздний финал не становится успешным. Physical cleanup/quarantine и один unfinished запрос игрока сохраняются; timeout не означает мгновенную выгрузку модели.
- Memory4GB, token/output limits, queue≤4/concurrency1, ownership/cleanup и recovery policy не меняются. Длинный срок может увеличить ожидание других игроков, не повышает качество и не квалифицирует p95.
- Operator-only diagnose.mjs сохраняет отдельный30с срок тестового вопроса, не наследует минуту из Make и не меняет игровой config. Настоящий Ollama/MLX, diagnostic CLI или скачивание весов на сервере с Pi запрещены; реальные проверки выполняет оператор на Mac.

Fixture/type/browser checks не доказывают реальную скорость, качество, peak RAM или успешный ответ модели в игре. TASK030/017/018 остаются незавершёнными до соответствующей приёмки.
