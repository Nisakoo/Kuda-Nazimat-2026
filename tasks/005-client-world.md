## Результат
Реализованы HttpMapSource, ChunkManager, AssetManager и WorldBudget. Выбранная метрика 10% и отдельный memory-cap записаны в MAP. Резервирование всего чанка атомарно до HTTP; ресурсы учитываются до последнего CPU/GPU-владельца. Рендер и транспорт разделены; устаревшие ответы отменяются, при нехватке бюджета сокращается предзагрузка, ближайший переход вытесняет дальнюю предзагрузку. HTTP использует no-store, ограниченное чтение и проверку объявленных размеров. Защищённый источник требует серверную сессию и обрабатывает 401/403, без публичного fallback.

Авторский демо-мир: 1024 чанка по 32 м, площадь и два тематических района, общие GLB, уникальные видимые таблички; collision bitmap выводится из геометрии GLB. Генератор считает фактические уникальные файлы (одинаковые collision dedup по SHA): 17 593 661 байт, лимит 1 759 366 байт. Генерируемые JSON/BIN/metadata исключены из git и восстанавливаются predev/prebuild/pretest/check. В JS только небольшой bootstrap, полный мир не встраивается.

Проверки 2026-10-31: `make client-test` — 102/102, `npm --prefix client run check` — 0 ошибок/предупреждений, `check:imports` — 53 модуля / 134 зависимости без нарушений. `PLAYWRIGHT_CHANNEL=chrome npm --prefix client run test:browser` — 13/13; `test:render` — 4/4. Проверены медленный переход между районами без замены canvas/сессии, ожидание у границы, повтор manifest после 503, радиус 0, ограниченные запросы и бюджет; прежний маршрут обоих NPC и пять перезапусков проходит. Unit-тесты проверяют concurrency 2, отмену/поздние ответы, освобождение владельцев, атомарный отказ бюджета и загрузку окружения заданной сохранённой позиции вместо spawn (S6 клиентского планировщика).
