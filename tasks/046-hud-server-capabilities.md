# Недостающие серверные возможности HUD

## Цель и изменения требований
Последнее указание пользователя разрешает backend-функции, требуемые UI. Не оставлять функции unavailable только из-за отсутствующего контракта. Дополнить PROTO/STORE в границах словаря, инструментов и map/HUD. NEXT-006/010/011/015 не реализовывать и не импортировать из другой ветки.

## Реализация
- [x] Личный learned и пример/перевод примера с серверным сохранением, read/migrate legacy словаря и строгой валидацией.
- [x] Серверные инструменты «Сумка»/«Кувшин», фактическое содержимое и одна подтверждённая выбранная вещь в руках; авторитетное обновление видимое другим игрокам.
- [x] Серверное краткое название задания и сохранённый прогресс; роли/список пастуха не раскрываются.
- [x] Серверный BABEL `partyPositions` передаёт только реальные market-позиции текущих участников задания по stable playerId, даже вне AOI/загруженных чанков. Массив ограничен 4, исключает self и отсутствующие акторы, не обращается к account lookup/SQLite positions. Клиентская интеграция объединяет его с более свежим WorldSnapshot по `party.members`; вне задания координаты не выдаются.

## Приёмка
- [ ] HUD S3/S5: equip подтверждается сервером, виден второму клиенту; learned/заметка/пример сохраняются после рестарта и приватны.
- [ ] Legacy SQLite/JSON словарь читается без потери записей; новые поля/длины/authorization проверены.
- [ ] Карта показывает свои/партнёрские серверные позиции, zoom/center и цель; чужие AOI исключены.
- [ ] Server/client type/import/unit/build/browser проверки и отдельные сравнения с PNG.

## Открытые вопросы
- HUD-009 не задаёт нормативную ёмкость инструментов (3 ячейки — пример макета), transfer вне scope. Не менять существующий BABEL лимит 8 единиц каждого из 5 items. Серверный bag/jug view должен быть проекцией фактического инвентаря, не второй копией предметов.
- HUD-010 и NEXT-011: новое equip tool должно занимать один слот. Яблоки/поднятие F не входят в этот scope; при будущей интеграции NEXT нужна единая модель рук, без 2 независимых занятых слотов.
- HUD-015: исходного примера для старой записи нет. Показывать пустой блок/предложение добавить пример, не генерировать ложную цитату. Пользовательские примеры сохраняются сервером.
- Фонтан/ворота на карте отсутствуют в world. Не создавать фальшивую цель и не менять несвязанные world features.

## Результат
HUD-013 backend дополнен обязательным `partyPositions:[{id,name,x,z}]` в shared BABEL state, строгой валидацией membership/уникальности/границ/полей и runtime-портом активных позиций. `BabylonDeps.peerLocation?(playerId)` связан через `GameRuntime.playerLocation?` с `GameService.playerLocation`, который читает только живой World actor без DB/account fallback. Проверки privacy/schema/bounds и настоящий HTTP outside-AOI сценарий добавлены в server tests. Фактические команды и результаты — [evidence/task-046-party-positions.md](evidence/task-046-party-positions.md). Client integration/browser/full suite остаются основному агенту.
