# Настраиваемые backend LLM в существующем игровом сервере

> До синхронизации main эта задача называлась TASK-030. Номер изменён на TASK-045 из-за занятого в main TASK-030 world-next-stage; старые commit IDs и численные результаты ниже — исторические. Актуальная интеграция PROTO v3/GenerationQueue/env/AUTH/OBS описана в [TASK-046](046-llm-docs-main-sync.md).

## Цель и изменения требований

По запросу владельца подключить локальную LLM непосредственно к игре: оператор выбирает Ollama или MLX, а не получает жёстко выбранный backend/отдельный чат. Добавлен LLM-015: явная конфигурация, диагностика и интеграция v1. MLX технически требует Apple Silicon; несовместимость не приводит к скрытой смене backend. Wire shapes PROTOv1 сохраняются: один полный ответ. После отдельного согласования пользователя общий deadline увеличен с8–9с до30с, клиентский NPC pending с10с до32с; остальные pending10с. Полная потоковая система по-прежнему требует v2.

## Отмена блокирующего worker и различение ошибок метрики

- Дополненный пользователем operational-log установил последовательность: timeout03:59:24; warningstop03:59:26; recovery startup03:~04:00 завершился `memory_unavailable` в04:00:29.845. Это ошибка достоверного сбора метрики, **не доказательство resource_limit/превышения4GB**. Поздний валидный ps snapshot не устанавливает, почему сбор не удался под нагрузкой.
- Code review подтвердил отдельный lifecycle дефект LLM-011: блокирующий Python HTTP-read не читает IPC stop, а defaultSIGTERM завершает Python без finally. Supervisor правильно запрещает сигналы stalePGID после выхода лидера; преждевременный выход worker может поэтому сорвать500мс escalation для owned group и растянуть stop. Данный механизм требует исправления с subprocess fixtures; конкретный survivor на пользовательском2с snapshot не наблюдался и не выдумывается.
- Реализован Ollama-only контролируемый SIGTERM: внутренний BaseException прерывает blocking HTTP и запускает finally/owned daemon cleanup/reap. Контекст spawn откладывает исключение до присваивания Popen handle; повторные SIGTERM не обрывают unwind/cleanup; предыдущий handler восстанавливается, импорт его не устанавливает. Запрет stalePID/group сигналов, quarantine и удержание слота до физического подтверждения не менялись.
- Добавлены subprocess/loopback fixtures без Ollama/весов: blocked startup/answer HTTP, cooperative reap, TERM во время Popen до assignment, повторный TERM, EOF/IPC stop и stubborn direct child с500мс groupKILL при живом лидере. Linux fixture использует изолированный subreaper и child watchdog против running-orphan при regression. Квалификация macOS/all-descendants/escaped processes/2с не подменяется этими тестами: при раннем выходе daemon остающийся native descendant всё ещё требует group confirmation/quarantine.
- Добавлены7 фиксированных безопасных memory_sample кодов для command timeout/error/buffer, parse/missing row/invalid metric и watchdog deadline; неизвестные ошибки/не-Error rejection остаются memory_unavailable без исходного текста. Внутренний command-callback seam напрямую проверяет реальные classification/parser, bounded command args и conservative RSS composition; он недоступен из config и не подменяет Node module глобально. Пределы500мс/600мс/3.5GB и игровой deadline не увеличены.
- Промежуточные Node-прогоны обнаружили race самого fixture: ранний отказ memory guard успевал остановить настоящий OS-child до записи JS spawn-event; getter pid ошибочно читал отсутствующий event. Исправлено наблюдением фактического owned PID через существующий memoryBytes(group) seam, без задержки production cancel и без ослабления проверок гибели процесса. После исправления итоговый serial прогон прошёл; промежуточные red прогоны не выдаются за PASS.
- Финальная serial проверка: `npm --prefix server run check` PASS (48 modules/130 dependencies); `make server-test` **158 passed, 1 skipped** (отсутствует built real-world fixture); Python discovery **52 passed**; docs checker (24 specs/29 tasks/238 requirements) и `git diff --check` PASS. Node умеет split/coalesced frames, проверяет весь доступный batch до terminal settlement и не продлевает deadline от progress. MLX не получает выдуманную Ollama-диагностику.

Повторный read-only review признал blocker устранённым в коде; итоговый прогон подтвердил localHTTP fixtures (premature Content-Length/chunked EOF, valid body, progress-before-EOF/cancel), без настоящей модели. ## Диагностика memory_sample_ps_timeout на Mac

Пользователь подтвердил реальный `make server NPC_TIMEOUT=120`: выбран prepared-profile Ollama/2B CPU2threads, numGpu0, timeout120000. Log selection07:57:11.087, ready07:57:45.887, HTTP07:57:47.506. На вопрос торговцу фруктами «привет» UI получил «Собеседник сейчас недоступен»; service зарегистрировал memory_sample_ps_timeout07:58:47.478, повторный ready07:59:27.955. Это время обнаружения service, не доказанное время самого замера: watchdog не писал немедленный log. Не установлено, началась ли generation. Ни RAMexcess, ни ответ120с, ни прохождение качества/скорости не доказаны. Saved2B профиль и применение Make override теперь подтверждены.

Пользователь отдельно измерил тот же `/bin/ps`/NodeexecFile options:12успехов,34–44мс,449строк, killedfalse/code0. Это baseline отдельного Node процесса без новой inference; он не опровергает прежний transient timeout и не устанавливает причину. Diff ed7532c/2f609e5 не менял500мсps/600мсobserver bounds/cleanup/250мспаузы; memory_sample_ps_timeoutкатегориясуществовала в3bacf02. Hostpressure/Nodecallbackdelay/OSlatency остаются гипотезами.

**План остановлен пользователем до изменения кода.** Пользователь сообщил «вроде заработало» локально, но не прислал текст ответа или timing завершённой generation. Это сообщение не квалифицирует игровой ответ и не доказывает причину сбоя после вопроса о Тайване. Никаких доказательств блокировки по политической теме нет; зарегистрирован технический отказ замера памяти. Описанный ниже observability patch был предложен, но **не реализован и не входит в текущий код**.

- Отложенное предложение по LLM-007/015: добавить немедленный безопасный error log из существующего watchdog через optional platformlogger (root app→adapter). ## Результат

- Файлы: `server/src/npc/adapters/localLlm.ts` и регистрация обоих backend; `NpcResponder` optional status/lastFailure; service lifecycle/health recovery; config restriction concurrency1; Python workers/common, отдельные requirements; `server/llm/manifest.mjs`; 2 config examples; документация игры/архитектуры. Общий `contracts.ts`, game/realtime, shared и клиент не менялись. npm-зависимости не добавлялись. Это не восстановление старого standalone-установщика.
- Supervisor fixtures реализованы настоящими Node subprocess без inference: bounded IPC/UTF-8, один слот, exact deadline/монотонные часы, memory failures, startup/cancel/stop, cleanup quarantine, stale PID guard и Unicode-history trimming. Оба backend подключены к общему responderContract с real timers. Реальная память измеряется best-effort RSS Node+потомков/owned-group, soft3.5e9; это не hardcap/unified memory gate.
- Два положительных game integration scenarios используют новый supervisor с Node worker fixture и настоящие HTTP/Socket.IO/GameRuntime/SQLite: ответ доставлен после записи, следующие вопросы получают историю, другой игрок её не видит. Это интеграция порта, **не настоящий Ollama/MLX ответ**. Два дополнительных сценария используют реальные зарегистрированные factory с отсутствующими пакетами: мир/чат продолжают работать, NPC health unavailable, scripted fallback и фиктивной истории нет.
- Python mocks проверяют настоящий общий compiler, non-callable MLX TokenizerWrapper API, broken startup template, manifests/blobs, bounded HTTP/NDJSON, отказ thinking, calibration/count telemetry. MLX API изучен по официальному исходнику0.32.2, не проверен на Apple Silicon. Ollama требует совпадения count в3пробах и вкаждом ответе. **Остаточный gate:** эти пробы не доказывают универсальную HF/GGUF эквивалентность; фактический prompt_eval_count приходит после generation, значит точный admission до вычисления (LLM-004) для Ollama всё ещё unverified. Отказ по telemetry не считается доказательством, что лишние токены не обрабатывались. Prompt cache semantics также требуют настоящего runner.
- Read-only review закрыл блокирование startup мира при бесконечном cleanup (startup rejects, owned runtime остаётся quarantined) и отсутствие проверки template при MLX readiness. Разрушительные сигналы не посылаются после выхода лидера группы; незавершённый answer остаётся pending до подтверждения освобождения. Stuck runtime не вызывает бесконечный restart/replay.
- Последний полный прогон: `npm --prefix server run check` — PASS (server+shared TypeScript и import boundaries: 47 modules/128 dependencies). `npm --prefix server test` — **124 passed, 1 skipped** (11 test files passed); из них supervisor43, game integration8, lifecycle/network7, manifest4. Пропущенный `a-real-world.test.ts` требует собранного реального map fixture; отсутствие конфигурации не засчитывается за pass. `make` в среде отсутствует: выполнен прямой npm эквивалент `make server-test`.

Checker дополнен поддержкой диапазона README `010–012`; исходный ложный mismatch TASK-026 был ошибкой checker, не зависимостей проекта. `git diff --check` — PASS. Клиент и shared не менялись; клиентские тесты/браузерный real-model smoke в этом срезе не запускались.
