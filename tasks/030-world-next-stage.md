# Следующий этап: реализация и проверка

## Цель и изменения требований

Ввести NEXT-001–014 из сборной спеки: личный словарь, раздельный спавн, неизменяемый камень, LAN/соло, будущий UI, новая локация, языки, миграции, HTTPS, жизнь мира, подбор и перевод через backend. ### Команды и доказательства

Для будущих изменений клиента: `make client-test`, `npm --prefix client run check`, `npm --prefix client run check:imports`, `npm --prefix client run build`; применимые браузерные сценарии — `PLAYWRIGHT_CHANNEL=chrome npm --prefix client run test:browser`, рендер/профиль — `PLAYWRIGHT_CHANNEL=chrome npm --prefix client run test:render`.

Для изменений сервера/shared: `make server-test`, `npm --prefix server run check`; изменения общего контракта также проверяются на клиенте. Миграции и конкурентные операции проверять на временных реальных SQLite-БД. Автоматические прогоны не заменяют физические S4–S5 и доверие HTTPS на целевых машинах.

В каждом доказательстве записать ревизию, команду/шаги, оборудование и браузер, режим backend/LLM, ожидаемый и фактический результат, путь к артефактам. Отдельно записать непройденные проверки и причину; отсутствие модели, сертификата или второго ноутбука не означает успех.
