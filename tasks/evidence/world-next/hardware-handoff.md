# Оставшаяся аппаратная и слуховая приёмка

Это **план проверки**, не выполненные результаты. Текущие неудачи/ограничения — [acceptance.md](acceptance.md). Параметры реально подготовленной сцены — [scene-parameters.json](scene-parameters.json), источник `shared/world-life/market.ts`.

## Подготовка до отключения интернета

1. На серверном ноутбуке установить Node 24 и заранее подготовить `npm --prefix client ci`, `npm --prefix server ci`, Chromium/Chrome для автоматизации. `make demo` генерирует мир, собирает клиент и запускает настоящий сервер; не выбирайте LocalSession/mock для серверной приёмки.
2. Записать commit ID, ОС, CPU/RAM/GPU, браузер/версию, viewport/DPR, параметры карты и профиля. Настройку renderer взять из WebGL/debug, не угадывать по названию ноутбука.
3. Подготовить копию рабочей SQLite/backup штатным runner. Не редактировать сохранённые яблоки вручную и не удалять БД ради успешного restore.
4. Открыть настоящую игру четырьмя разными именами/профилями, минимум на двух физических ноутбуках. Использовать LAN без WAN; отдельно проверить соло на серверном ноутбуке с физически выключенным Wi-Fi. Не отключать проверки auth/TLS или защиту браузера ради Pointer Lock.

## S7 / каталог и переходы

- Пройти рынок → пастбище → двор → рынок с штатной камерой, затем с замедленной загрузкой границы. Проверить, что ожидание видно, персонаж не пересекает неподготовленную границу, сессия/данные не теряются.
- Записать максимум ready chunks (≤25) и полезных данных (≤67 108 864 bytes), а также причины deferred/ошибки. Не путать payload budget с RSS/VRAM.
- Отдельный JSON-стенд каталога: `client/e2e/catalogue-placement.json`, render case `NEXT data-only catalogue placement`. Проверить ID, разные координаты/повороты двух bench, общие ресурсы, отсутствие новых игровых правил, освобождение владельцев после unload.

## S11 / общая сцена, горшки и профиль

- Два клиента рядом должны видеть сон, прогулку и умывание трёх кошек. Проверить безопасные маршруты/опору и отсутствие интерактивного животного/лишнего препятствия. Координаты и маршруты взять из JSON, не подбирать у камеры.
- Дождаться пролёта 5 птиц, войти поздним клиентом во время следующего пролёта. Сверить общие sceneId/epoch/definition и фазу; локальная камера не запускает собственную стаю.
- Посмотреть умеренность пальм/травы/ткани/вывесок и редких воздушных следов; каменные конструкции не качаются, ветер не толкает физические тела.
- Два игрока толкают один допустимый горшок. Позиция общая; стены, другие тела, границы и проходы остаются защищены; разрушения нет. Reconnect сохраняет RAM-позицию живого сервера, restart возвращает все 4 исходных положения.
- Четыре игрока в полной сцене: записать ≥60 s FPS/время кадра/draw calls, server step и ресурсы с аудио. Не смешивать это с headless Socket.IO-профилем. Пороги/методика клиентского профиля — [QUALITY](../../../specs/client-quality.md): ≥30 FPS, P95 frame interval ≤50 ms, ≤500 draw calls, 5 s warm-up, 60 s route и 5 cycles. Профиль M4/16 GiB/1280×800/DPR1 не заменяет другой ноутбук.

## S12 / руки и сохранность

- Каждая роль поднимает каждое из 5 яблок по физической F в допустимом радиусе. Проверить один слот, удержание/repeat, закрытый стеной/дальний предмет, декор, занятую/воздушную/краевую точку опускания. Первый rising-шаг тоже не разрешает place.
- Гонка двух игроков: один успех/один отказ. Retry и потеря ответа после commit не повторяют действие; изменённый intent под тем же ID даёт конфликт. Яблоко не входит в сумку BABEL и не кормит коз.
- Записать свои и удалённые pickup/carry/place спереди и сбоку: обычная ходьба, sprint, jump, 30/60 FPS. Яблоко остаётся в ладони, позы не ломают MOVE и не проходят через землю. Частичный `completed:false` clip не подтверждает цикл.
- Reconnect и настоящий restart с яблоком в руках, затем place. Сверить все 5 уникальных ID и единственное состояние каждого. Дальний reconnect за исходным home-чанком не должен терять модель переносимого предмета.

## S15 / звук, повторные циклы и прослушивание

- После явного входа человек прослушивает ветер, птиц, траву, шаг/спринт/прыжок и мягкое неразборчивое бормотание новых вопросов/ответов на полном маршруте. Записать имя проверяющего, устройство вывода и замечания. Native source starts без прослушивания не дают PASS слышимости/качества.
- Нет шагов в упоре/воздухе, второго jump sound от held Space после приземления, звука старой истории при polling/reconnect/reopen. Инструкции кормления козы не являются новой репликой; реальная подготовленная локальная NPC-реплика может звучать.
- 30% по умолчанию, изменение, 0% тишины и reload. Autoplay denial/ошибка WAV не останавливают игру. Механизм unlock использует настоящий пользовательский жест, не браузерный bypass.
- Пять завершённых restart/входов в той же прогретой точке. Измерить sources/buffers/pending/WorldBudget, native contexts, geometry/texture counters и heap по QUALITY. Учитывать legitimately warmed audio buffers отдельно, а не выдавать «ниже cap» за отсутствие утечек.
- Все runtime-ресурсы локальны. Нет browser → inference endpoint и внешних запросов; реальные LLM-качество/RAM/очереди этим блоком не квалифицируются.

## Команды повторения

```sh
make client-test CLIENT_TEST_CMD='npm --prefix client test -- --pool=threads --maxWorkers=1'
VITEST_MAX_WORKERS=1 make server-test
npm --prefix client run check
npm --prefix client run check:imports
npm --prefix client run build
npm --prefix server run check
PLAYWRIGHT_PORT=4291 NEXT_BROWSER_VIDEO=1 npm --prefix client run test:browser
PLAYWRIGHT_RENDER_PORT=5291 npm --prefix client run test:render
node server/test/world-next-profile.ts
node server/test/world-life-startup-diagnostic.ts
```

Заранее установленный browser можно выбрать через `PLAYWRIGHT_EXECUTABLE_PATH` или `PLAYWRIGHT_CHANNEL`. Не занимать чужие порты/сессии; reuse existing server остаётся false. Functional NEXT fixture по умолчанию использует 3 observer-клиента с radius0 и одного carrier с default25-window; это не полный 4-GPU профиль. Для аппаратной проверки использовать четыре полноценных default-window клиента отдельно и зафиксировать результаты.
