## Предварительные находки

### R-01 · P2 · ENTRY-002, ENTRY-004 — настройки перекрыты на узком входе

- **Ожидается:** видимая кнопка настроек справа снизу, доступная мышью и клавиатурой.
- **Факт сохранённого кадра:** на `../ui-redesign-2026-07-02/real-entry/login-390x844.png` и `registration-390x844.png` виден только нижний край белой плашки; шестерёнку закрывает табличка. На mode/languages того же размера кнопка видна.
- **Основание source:** `global.css` header z-index 2, `entry.css` login-screen z-index 5; панель действительно перекрывает фиксированную кнопку. Bounding-box проверка results помечает кнопку внутри viewport и не обнаруживает occlusion.
- **Статус:** визуально подтверждено в сохранённых real-entry кадрах; свежая pointer/Tab проверка нужна. Это не просто отличие серверных данных.

### R-02 · P2 · AVATAR-004, ENTRY-002 — у выбора облика отсутствуют логотип и настройки

- **Ожидается:** логотип слева сверху, настройки справа снизу, как на `oblik_page.png`.
- **Факт исторического кадра:** `../ui-redesign-2026-07-02/avatar-1622.png` не содержит обоих элементов.
- **Основание текущего source:** `AvatarSelection.svelte` не создаёт их; `.avatar-backdrop` в `avatar-selection.css` закрывает viewport непрозрачным фоном при z-index 25, header остаётся z-index 2. Native modal дополнительно делает внешний header inert.
- **Статус:** сильное source/историческое подтверждение; не объявлять проверенным на текущем production до свежего кадра.

### V-01 · P2 художественное расхождение · ENTRY-001–003, ENTRY-006, ENTRY-011

- `autorize.png`/`track.png` показывают объёмные low-poly здания, мягкий свет/тени, выразительную перспективу и жителей; текущие real-entry кадры — плоская SVG-иллюстрация с жёсткими геометрическими силуэтами.
- Сохранены ворота, пальмы, цветные навесы, сосуды, ящики, светлые шапочки, пергамент, ромбы и указатели. Поэтому это не отсутствие всех обязательных мотивов.
- Панель меньше/выше относительно общего кадра; typography/толщина иконок/декоративная пластика отличаются. Дополнительный явно обозначенный demo-вход увеличивает панель; сам demo-вход разрешён согласованными границами.
- Решение static/3D открыто; static SVG само по себе не нарушение. Однако успешные tests не подтверждают художественное соответствие.

### V-02 · P2 художественное расхождение · AVATAR-009, CHAR-002

- На отдельных финальных GLB-кадрах все 4 облика узнаваемы: нужные волосы/очки/цвета/манжеты/бантик/светлые штаны/ботинки, без шапочек.

- На Ksu есть светлые обводки глаз, которых нет у остальных; оценивать вместе с крупным fresh preview. Отдельный кадр не доказывает игровой масштаб, idle, 360°, плавность walk или clipping предмета.

### H-01 · требуется перепроверка · AVATAR-007, UI-002

`../ui-redesign-2026-07-02/avatar-390.png` обрезает правую колонку карточек и правую часть preview. Кнопки внизу за прокруткой. ### H-02 · недостаточно доказательств · ENTRY-004, ENTRY-007, ENTRY-011–013

На всех 640×480 исходных real-entry кадрах основные действия ниже viewport. `real-entry-results.json` прямо перечисляет outsideViewport controls. Контейнеры имеют overflow-y:auto: само нахождение ниже fold не дефект. Нужны свежие scrolled кадры и keyboard traversal до каждой кнопки. При этом `documentWidth/Height === viewport` не доказывает отсутствие внутреннего overflow.

## Открытые вопросы

- HUD-011 требует фонтан и ворота; согласованный world их не содержит. Честная схема реального рынка допустима по TASK-042, но не закрывает художественную приёмку иллюстрации. Добавлять вымышленные координаты нельзя.
- HUD-017 требует аватары сообщений; AVATAR оставляет связь с обликом напарника открытой. Декоративный verified portrait и выдуманный участник — разные вещи; нельзя подставлять фиктивную личность.
- ENTRY-001 дневной город/чиби и существующий world на закате имеют разные художественные основания. Static/3D и единое время суток ещё не согласованы.
- Счёт задания 1/3 из макета, имя «Мира», набор слов/предметов и шаг про фонтан — примеры, а не основание подменять реальный server state.
- Ёмкость инструментов и перенос содержимого не определены. Три пустых ячейки не доказывают server capacity; NEXT unified hands не входит в эту поставку.
- Клавиши закрытия словаря против I-инвентаря остаются открытыми. Нельзя считать произвольный новый hotkey обязательным без согласования.

## Непроверенное оборудование и ограничения

Не проверены 4 физических LAN-клиента, Wi-Fi-off, аппаратный Pointer Lock, real MLX/Ollama, 30/60 FPS, P95/heap/500 draws на целевом ноутбуке. SwiftShader-кадры и кинематические JSON их не заменяют. Нет окончательного результата 47+8 checks в этом отчёте.

## Следующий шаг

Дождаться явного разрешения основного агента после GPU-run. Затем использовать отдельный реальный browser context без fixtures, API/DOM injection, снижения DPR/контента и автоматического Pointer Lock. Сохранить **свежие** кадры каждого экрана/окна/модели в этой папке, зафиксировать bundle/hash, реальные действия, ошибки и persistence; отдельно независимо перепроверить исправления. До этого итоговый full-scope отчёт остаётся незавершённым.
