## Художественные решения и остаток

- V-01 существенно улучшен: реальная композиция входа содержит ворота, рынок, пальмы, жителей, тени и глубину. Это воспроизводимый статический bake, **не** живой world/FPS evidence. **V-01b / P3, ENTRY-001/011:** actual composite показывает 2 смещённые центральные стойки: тёмную стойку настоящего UI и более широкую оранжевую стойку bake. На 390 видны также 2 смещённых навершия. Это подтверждённый визуальный артефакт совмещения, не функциональная ошибка. Reference содержит 1 стойку. Сравнить `correction-static/mode-390x844.png`, `friends-1622x970.png` и `specs/images/track.png`. До полного визуального закрытия V-01 нужно устранить дублирование либо явно принять это отличие. Новая игровая сцена/координаты не требуются.
- V-02 по геометрии закрыт в ранее утверждённом объёме V4. Теперь те же точные GLB увидены в актуальном chooser. Лица/волосы/кисти значительно ближе к 4 refs, руки не выглядят прежними лопатками. Ksu имеет слоистый бок/затылок. Без нового фактического дефекта утверждённая геометрия не переоткрывается.
- **P3, AVATAR-006/009 / CHAR presentation:** на действительном frontal preview остаются мелкие светлые точки на ткани, заметнее на бирюзовой/оливковой тунике. Примеры `correction-avatar/lukas-1622x970.png`, `nic-1622x970.png`, `ksu-1622x970.png`. Они не исчезли от публикации V4. Причина не установлена; нельзя приписывать их GPU, теням, z-fighting или геометрии без отдельного доказательства. Это остаток rendering/presentation, а не отзыв геометрического approval.
- Дополнительное P3-наблюдение по фокусу: `correction-avatar-results.json.initialFocus` непосредственно после открытия chooser, до готовности GLB и до действий пользователя, содержит `A / Вавилон — главная / inModal:true`. Это начальный native focus на chrome, а не на stage. После готовности предусмотрен stage focus, а тест с открытыми Settings подтвердил отсутствие позднего перехвата. Спецификация не задаёт точную начальную цель; Enter по логотипу в этот короткий интервал отдельно не проверялся. Поэтому это наблюдение для явного UX-решения, а не установленный новый P2/не доказанное нарушение AVATAR-012.
- Mobile/640 скриншоты после поворота и сохранённого фокуса показывают ту же Ksu с боку/сзади. Их текущий scroll не равен началу страницы. Это намеренно сохранённое состояние; отдельные `chooser-controls-*` показывают доступные настоящей прокруткой кнопки. Отсутствие заголовка в таком crop не трактуется как его отсутствие из UI.

## Ошибки проверяющего, сохранённые отдельно

- `correction-static-attempt1*`: `.check()` уже выбранного solo не переводил фокус; ArrowRight проверял не тот фокус. Исправлено реальным `.click()`, без force.
- `correction-static-attempt2*`: точный старый locator подписи размера не соответствовал декоративной подписи. Исправлен role/regex locator. Ошибки не являются дефектами продукта. Первая попытка закрыла context без явно подтверждённого server revoke; последующие cleanup не доказывают отзыв всех её токенов.
- `correction-avatar-attempt1*`: `.check()` по скрытому radio пересекался с видимым portrait img. Реальный клик по карточке работает и выбирает radio. Это ошибка цели проверяющего, не установленный дефект пользовательского выбора. Cleanup первой AVATAR-попытки подтвердил logout 204.
- В первой AVATAR-попытке response regex смотрел старый `/avatars/`, поэтому `models: []` не означал отсутствие GLB. Итоговый regex учитывает настоящий `/api/avatar/models/`; данные совпали с независимым receipt.

## Открытые вопросы

- Назначение reference-портретов в HUD/чате и связь с текущим персонажем остаётся вопросом спецификации; AVATAR явно сохраняет этот вопрос открытым.
- Сравнение live world, map, tool-in-hand и R-06 требует отдельного текущего world-потока. Настоящий chooser не доказывает принятие этих требований.
- Полный старый browser 15/47 и render 4/8 не становятся успешными из-за этой локальной проверки ENTRY/AVATAR. Требуется новый честный прогон; 5-секундные deadline нельзя заменять диагностическими 90 секундами.
