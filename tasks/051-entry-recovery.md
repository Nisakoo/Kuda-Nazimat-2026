# Продолжение игры и восстановление после ошибок

## Цель и изменения требований

Исправить тупик на присланном скриншоте: наличие сохранённой игры не должно вести к бесконечному повтору create. Уточняются HUB-009 и S5: прямое продолжение из кабинета и указателя, известный конфликт виден до команды; сохранённый прогресс не сбрасывается. Повтор доступен для временного/неопределённого отказа, а не для постоянного серверного запрета.

## Реализация

- [x] Прямое продолжение сохранённой игры, пояснение режима и присоединение к ожидающей группе.
- [x] Разделить постоянные ошибки и безопасный повтор; не терять ошибку команды из-за polling, игнорировать устаревший отказ polling.
- [x] Проверить связанные проблемы формы подключения: случайный submit при повторе, нормализация адреса и несохранённые языки.
- [x] Сохранить черновик слова из чата при polling; поздний предложенный перевод не затирает ручной ввод.

## Приёмка

- [x] Сохранённая игра продолжается одной кнопкой, режим/инвентарь сохраняются; создание не отправляется при известном конфликте.
- [x] Постоянный отказ не предлагает повтор; сетевой отказ повторяет тот же requestId, поздний polling не портит результат команды.
- [x] Черновик слова из чата и ручной перевод переживают несколько обновлений сервера.
- [x] make client-test, check, imports, build и браузерные сценарии на временном реальном сервере проходят; evidence записан.

## Результат

- В кабинете и на указателе есть прямое продолжение своей игры; при ожидающей группе — присоединение. Известное состояние блокирует заведомо конфликтный create, сохраняя выбор radio и прежнюю группу.
- BabylonClient отличает постоянные HTTP 400/401/403/409 от временных 408/429/5xx и неопределённого сетевого отказа. Только последние дают повтор с исходным requestId. Ошибка команды не исчезает при polling; поздний отказ старого polling игнорируется. При смене экрана ошибка очищается.
- У кнопки повтора в форме явный type=button: она больше не отправляет другой IP/порт вместе с повторяемой командой. Адрес сравнивается после нормализации; для текущего сервера несохранённые языки требуют сохранения.
- Back и шестерёнка отменяют проверку другого сервера. Старые сообщения формы/поздние отказы отменённой попытки не возвращаются на новый экран.
- Расширенный прогон воспроизвёл сброс предложенного перевода в словаре на обновлении props. Черновик инициализируется один раз для выбранного слова; ручной перевод защищён от позднего предложения. Переход к другому слову/выход из словаря сбрасывает маркер, а не пользовательские поля на каждом polling.
- Сборка производится в отдельном временном каталоге, затем ресурсы копируются с сохранением прежних hash-файлов, index.html заменяется атомарно. Текущий сервер пользователя не останавливается и не перезапускается.

Промежуточный прогон: 19/20 сценариев. Отдельный сценарий покупок остановился вне радиуса NPC из-за допуска маршрута ±0,3 м; целевая точка тестового подхода перенесена внутрь радиуса, правило взаимодействия игры не менялось. Окончательный прогон на финальной неизменной сборке прошёл: 20/20 сценариев.

Проверка существующего localhost:8080 в ходе приёмки получила connection refused; lsof не нашёл listener. Агент постоянный процесс не останавливал и не запускал. Это состояние запуска пользователя, не успешная проверка health. Проверки игровых сценариев выполнены на отдельных временных серверах с отдельными SQLite-базами.
