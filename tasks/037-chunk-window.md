# Окно из 25 чанков вместо процентного лимита кеша

## Цель и изменения требований

По прямому указанию пользователя заменить ограничение кеша долей общего мира хранением окрестности игрока. MAP-006 меняется: размер обычного набора ограничивает радиус (0–2, максимум 25 чанков), общий аварийный лимит полезных данных — 64 MiB. Для market по умолчанию радиус 2; для demo/science сохраняется 1. Общие модели учитываются один раз, дальние чанки освобождаются, отменённые данные не возвращаются. Размер мира больше не ограничивает совокупный кеш; метаданные PROTO v1 отдельных файлов остаются совместимыми.

Связанные требования CLIENT-008, CHAR-013, SCENE-025, DEMO-004, NEXT-006 и SERVER-WORLD-004 ссылаются на новую политику MAP вместо прежних 10%/32 MiB. SERVER-DEMO-004 больше не требует печатать вычисленный процентный лимит в стартовом логе. Идентификаторы требований сохранены, новых требований нет.

## Результат

WorldBudget больше не принимает worldBytes и не вычисляет процентный лимит: он учитывает уникальные ресурсы и ограничивает только консервативную память 64 MiB. Выбор набора по радиусу остаётся в ChunkManager. Default market — радиус 2; явные 0/1/2 сохраняются. Диагностика показывает память и состояние чанков. Бинарные модели и формат ресурсов не менялись; в генераторах и стартовом логе сервера убрана только устаревшая печать процентного лимита.

- `npm --prefix client run check`, `check:imports`, `build`: проходят. Bundle 906,47 kB / gzip 245,67 kB, прежнее предупреждение о размере JS остаётся.

- Новый сценарий настоящего сервера с изолированной SQLite подтверждает 25 чанков на рынке и у башни, 0 pending/deferred и отсутствие отказов `/world/`.
