# Сервер: HTTPS/WSS с самоподписанным сертификатом

## Цель
Серверная часть NEXT-009 по [TLS](../specs/server-tls.md): все запросы и ответы между браузером и сервером идут по TLS, сервер выпускает самоподписанный сертификат, игроки один раз доверяют ему через `/setup`.

## Реализация
- [x] `server/src/tls/`: DER-кодировщик X.509 v3 и выпуск самоподписанного сертификата на `node:crypto` (TLS-001, 003, 006); хранилище файлов с атомарной записью и правами `0600` (TLS-005).
- [x] Проверка срока и покрытия адресов при запуске и в статусе, без автоматического перевыпуска (TLS-004).
- [x] Конфигурация `tls` и пресеты окружений без выключателя TLS; общий доверенный сертификат в тестах (TLS-009, 016).
- [x] Определение протокола на одном порту: `https.Server` для приложения, урезанный HTTP-обработчик `/setup`, `/server.crt`, `/api/health`, 308/426 (TLS-007, 008); `app` подключает Socket.IO к HTTPS-серверу.
- [x] Страница `/setup` и выдача `server.crt` (TLS-010).
- [x] Блок подключения, `/operator` и `/api/operator/status`: https-адреса, отпечаток, сроки, недоверяющие устройства; метрика и лог рукопожатий (TLS-011, 012).
- [x] CLI `tls status|init|renew --yes|export`, `make prepare`, `lan:check` (TLS-014, 015).
- [x] Документация: README (запуск, доверие на каждой ОС, диагностика «симптом → действие»), architecture, OFFLINE/AUTH/SERVER по разделу «Изменения связанных требований», статус спеки.

## Приёмка
- [x] Vitest S1, S3–S7 (S5 — предупреждения без перевыпуска; S6 — отказ запуска в store-тестах) спеки TLS на временных каталогах и реальном `https`/`socket.io-client` с самоподписанным сертификатом как единственным доверенным.
- [ ] `make server-test`, `npm --prefix server run check` проходят: `tsc`, `depcruise`, vitest выполнены; осталось 3 падения, которые были и до изменений (building-height, два теста занятого порта в llm-diagnostic).
- [ ] Ручной запуск `make start` на ноутбуке-сервере: блок подключения, `/setup`, `/operator`, вход в браузере этого ноутбука после доверия сертификату.
- [ ] S8 (два физических ноутбука, R1 и R3) — совместно с TASK-098; без него NEXT-009 не считается выполненным.
