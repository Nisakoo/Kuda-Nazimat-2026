# Локальный runtime MLX и Ollama

## Цель и изменения требований

Реализовать новые LLM-001–014 в отдельном серверном проекте. Два backend и Qwen3.5-2B 4-bit выбраны в спецификации; не реализовывать сервер внутри этого репозитория. Функциональные тесты не заменяют квалификацию оборудования и модели.

## Реализация

- [ ] Проверить версии MLX LM/Ollama и подготовить воспроизводимые локальные snapshots, digest/хеши, tokenizer/template и notices. Для MLX проверить text-only загрузку/конвертацию, не подменять её непроверенным VLM-пакетом.
- [ ] Реализовать общий LlmPort, MlxAdapter с локальным worker и OllamaAdapter, readiness/token counting/stream/cancel/shutdown. Указать владение daemon/worker и способы офлайн-установки. Реализовать приватный IPC либо защищённую локальную HTTP-границу и process-aware изоляцию native Ollama без обхода proxy; проверить браузерные Origin/Host и DNS rebinding на каждой целевой ОС.
- [ ] Реализовать единственный активный backend, очередь/лимиты, ограниченный prompt/output, non-thinking, backpressure и контролируемую выгрузку перед переключением.
- [ ] Реализовать и документировать memory admission/monitoring и платформенные средства ограничения; протестировать ошибки/пики, не обещать строгий лимит по размеру файла или редким сэмплам.
- [ ] Обновить серверную документацию по реальным командам, конфигурации, пакетам и ограничениям ОС.

## Приёмка

- [ ] LLM-001–005, 008–013 / S1–S4: оба адаптера проверены с реальными локальными runtime, включая отмену вычислителя, недоступный артефакт, приватность endpoint, очередь, timeout, повторный stop/start и переключение. Контрактные fakes проверяют ошибки отдельно и не считаются запуском модели.
