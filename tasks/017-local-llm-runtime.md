# Локальный runtime MLX и Ollama

## Цель и изменения требований

Реализовать LLM-001–015; уточнены LLM-002, 006–008, 010–011 и 014 для 4 игроков, общей памяти, ограниченной очереди и накопительных снимков. Реализовать их в сервере (`server/`) адаптером порта NpcResponder (NPC-005). Два backend и Qwen3.5-2B 4-bit выбраны в спецификации. Функциональные тесты не заменяют квалификацию оборудования и модели.

## Реализованный срез

- [x] Зарегистрировать Ollama/MLX в существующем NpcResponder; интегрировать POSIX supervisor, приватный bounded IPC, owned native process, cancel/quarantine и удержание слота. Это покрытие кодом/fixtures, не реальная OS/model qualification.
- [x] Добавить prepared-profile selector (Ollama/2b Q4_K_M, Ollama/0.8b Q8_0, MLX/2b), create-only importer и NPC_TIMEOUT в целых секундах 1–300 без runtime-download/fallback. Лимиты/эффективный срок и single-final metadata описаны в LLM-015.
- [x] Сохранить main: Socket.IO v3/MOVE, production password/dev guest, APP_ENV, observability, offline/operator, одну GenerationQueue для NPC/BABEL, серверный opt-in PROTO-007 и scripted-поток. Клиентские TASK-041/044 и реальный LanguagePort не закрыты этим срезом.

## Оставшаяся реализация

- [ ] Проверить версии MLX LM/Ollama и подготовить воспроизводимые локальные snapshots, digest/хеши, tokenizer/template и notices. Для MLX проверить text-only загрузку/конвертацию, не подменять её непроверенным VLM-пакетом.
- [ ] Завершить полный streaming/lifecycle-план поверх существующих worker-адаптеров: readiness/token counting/stream/cancel/shutdown. Реальные workers пока передают operational progress и один финал, не игровые partial. Указать владение daemon/worker и способы офлайн-установки. Реализовать приватный IPC либо защищённую локальную HTTP-границу и process-aware изоляцию native Ollama без обхода proxy; проверить браузерные Origin/Host и DNS rebinding на каждой целевой ОС.
- [ ] Реализовать один backend/модель с общими весами; базовый `maxConcurrentGenerations=1`, профиль 2 только после проверки поддержки, изоляции и измеренного улучшения без регрессий RAM/игры. Ограничить незавершённые запросы, включая stopping, до 4 глобально и 1 на игрока независимо от вкладок; FIFO, очередь 30 с, generation 30 с, абсолютный deadline 60 с в расширенном AI-плане; не выдавать это за текущий настраиваемый single-final timeout (default 30 с, максимум 300 с, включая очередь). Проверять монотонное время при первом тексте/конце inference и сериализовать completion с timeout, не полагаться только на timer handler. При неподтверждённой остановке за 2 с перезапустить общий runtime и выдать терминальные статусы всем затронутым запросам.
- [ ] Ограничить вход 1792 токенами, контекст 2048, обычный выход 128 и расширенный 256 токенами. Реализовать накопительные best-effort `partial`, не более одного pending-снимка, без ACK и replay фрагментов; ограничить суммарный буфер приложения/транспорта 64 КиБ на запрос, envelope 32 КиБ, текст 16 КиБ. Проверить ограничитель транспорта и медленного потребителя.
- [ ] Реализовать и документировать memory admission/monitoring и платформенные средства ограничения; протестировать ошибки/пики, не обещать строгий лимит по размеру файла или редким сэмплам.
- [ ] Обновить серверную документацию по реальным командам, конфигурации, пакетам и ограничениям ОС.

## Приёмка

- [ ] LLM-001–005, 008–013 / S1–S4: оба адаптера проверены с реальными локальными runtime, включая отмену вычислителя, недоступный артефакт, приватность endpoint, очередь, timeout, stop grace/restart и статусы, ограничение транспортных буферов при медленном потребителе, повторный stop/start и переключение. Для профиля 2 проверить реальную изоляцию отмены второго запроса. Контрактные fakes проверяют ошибки отдельно и не считаются запуском модели.
- [ ] LLM-006–007 / S2, S5: метод учёта всех процессов и unified memory описан; проверены cold/max-input/cancel пики, все контексты в общем лимите 4 000 000 000 байт и soft threshold на имеющемся стенде. Отсутствующее железо помечено unverified, а не pass.
- [ ] LLM-013–014: начальные profiles/pins/метрики записаны; если любой требуемый backend реально не проверен, задача не done. Полная оценка на целевом железе, учебных материалах и с NPC выполняется в TASK-018; до неё LLM остаётся partial, не complete.
- [ ] Проверки сервера (`make server-test`) проходят; установка/сборка/команды зафиксированы фактически. Клиентские изменения при наличии проходят `make client-test`.
