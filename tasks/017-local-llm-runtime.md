# Локальный runtime MLX и Ollama

## Цель и изменения требований

Реализовать LLM-001–014; уточнены LLM-002, 006–008, 010–011 и 014 для 4 игроков, общей памяти, ограниченной очереди и накопительных снимков. Реализовать их в отдельном серверном проекте. Два backend и Qwen3.5-2B 4-bit выбраны в спецификации; не реализовывать сервер внутри этого репозитория. Функциональные тесты не заменяют квалификацию оборудования и модели.

## Реализация

- [ ] Проверить версии MLX LM/Ollama и подготовить воспроизводимые локальные snapshots, digest/хеши, tokenizer/template и notices. Для MLX проверить text-only загрузку/конвертацию, не подменять её непроверенным VLM-пакетом.
- [ ] Реализовать общий LlmPort, MlxAdapter с локальным worker и OllamaAdapter, readiness/token counting/stream/cancel/shutdown. Указать владение daemon/worker и способы офлайн-установки. Реализовать приватный IPC либо защищённую локальную HTTP-границу и process-aware изоляцию native Ollama без обхода proxy; проверить браузерные Origin/Host и DNS rebinding на каждой целевой ОС.
- [ ] Реализовать один backend/модель с общими весами; базовый `maxConcurrentGenerations=1`, профиль 2 только после проверки поддержки, изоляции и измеренного улучшения без регрессий RAM/игры. Ограничить незавершённые запросы, включая stopping, до 4 глобально и 1 на игрока независимо от вкладок; FIFO, очередь 30 с, generation 30 с, абсолютный deadline 60 с. Проверять монотонное время при первом тексте/конце inference и сериализовать completion с timeout, не полагаться только на timer handler. При неподтверждённой остановке за 2 с перезапустить общий runtime и выдать терминальные статусы всем затронутым запросам.
- [ ] Ограничить вход 1792 токенами, контекст 2048, обычный выход 128 и расширенный 256 токенами. Реализовать накопительные best-effort `partial`, не более одного pending-снимка, без ACK и replay фрагментов; ограничить суммарный буфер приложения/транспорта 64 КиБ на запрос, envelope 32 КиБ, текст 16 КиБ. Проверить ограничитель транспорта и медленного потребителя.
- [ ] Реализовать и документировать memory admission/monitoring и платформенные средства ограничения; протестировать ошибки/пики, не обещать строгий лимит по размеру файла или редким сэмплам.
- [ ] Обновить серверную документацию по реальным командам, конфигурации, пакетам и ограничениям ОС.
