## Полная реализация и исправление сбоев подключения

- Влит origin/main (ea4e6f9) коммитом ec9f574, сохранены рабочие UI-правки, авторизация, экипировка, новая серверная расстановка игроков и NPC streaming. Клиентская потоковая подача NPC остаётся отдельной TASK-041.
- Авторизация открывает кабинет с именем/обликом/языками. Первичный облик выбирается из кабинета, Back/Esc возвращают туда. Языки сохраняются независимо от задания. Три действия остаются в одной строке на 390 и 1280 px. Портреты используют публичные локальные UI-изображения: запрос в защищённую папку моделей давал 404.
- Указатель открывается только для создания. Режимы переключаются мышью, стрелками/Enter, сохраняются при возврате в кабинет. Серверные create/join не сбрасывают существующую группу или прогресс; неопределённый результат повторяется с тем же requestId.
- IP/порт валидируются (IPv4/IPv6, 1–65535). Проверка /api/health выполняется без credentials/redirect, сообщает несовместимую версию. Исходный no-cors + redirect:error Chrome отвергал до обращения к серверу — этот дефект воспроизведён и устранён. Публичный health имеет wildcard CORS без credentials; остальные API не расширены.
- При смене сервера прежняя сессия отзывается, открывается origin целевого сервера с намерением join; его авторизация обязательна, исходный bearer не пересылается. Отмена проверки гасит позднюю навигацию. Страница игрового сервера берёт свой адрес из его конфигурации; устаревшая browser preference больше не подменяет его.
- Вместо языка/intro/«Начать прогулку» показана загрузка. Готовность включает сетевой снимок, коллизии, ресурсы и анимацию. VisualChunks скрывает неподготовленные группы, поднимает готовые с −3 м за 600 мс с ease-out, не меняя физику. Поздние чанки анимируются отдельно, показанные повторно не поднимаются. Reduced motion оставляет группы на штатной высоте. Отмена освобождает ресурсы; поздние модели уничтожаются.
- До готовности начального окна сервер удерживает safe spawn и игнорирует движение/прыжок без prepared chunks. После загрузки автоматически открывается HUD; отказ браузера или Esc/потеря фокуса оставляют явное восстановление управления и возврат в кабинет. Ввод загрузки не накапливается.
- **Реальная БД:** server/data/game.sqlite имела записи миграций 1–6, но players не содержала avatar_id. Сама SQLite цела; старые dev-ветки использовали те же номера для других изменений. При старте теперь проверяется фактическая схема 003–006, недостающие поля/таблица/nullable party_id восстанавливаются транзакционно без удаления посторонних таблиц и данных. Ошибка открытия выводит SQL-причину.
- Перед ремонтом создана согласованная SQLite backup: server/data/backups/game-before-schema-repair-1793521399397.sqlite. Сохранены все 11 игроков, integrity_check=ok, foreign_key_check пуст. На отдельной копии исправленной рабочей БД проверены запуск приложения, password-регистрация, сохранение облика и языков до задания; исходная БД этим smoke не менялась.
