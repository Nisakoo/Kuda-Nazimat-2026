# Команды отрисовки декора и следов

## Цель и изменения требований

Второй этап ROPT после принятого baseline M4. Требования не меняются. До выбора метода — инвентаризация фактических main/shadow draws, а не количества узлов GLB. Существующие generator merging и WindInstances сохраняются.

## Метрики и варианты до кода

- Исходная серия RPERF: calls-медианы low 226, balanced 333, high 385–388; максимум high 561. На отметках 10/20/30 с присутствует 96 отдельных следов, использующих одну геометрию и материал. Каждый след пока отдельный Mesh. Это гипотеза совместимой группы, не доказательство количества видимых команд.
- Приоритетный кандидат — InstancedMesh следов внутри владельца поверхности; разные владельцы сохраняют отдельные transforms/visibility/lifecycle. Instancing статического декора оценить по inventory; разные геометрии — существующий merge, BatchedMesh только при подтверждённых совместимых дорогих группах.
- Целевая метрика: draw calls насыщенного следами рынка при прежнем виде, **≥10% и больше разброса трёх повторов**. Также полный маршрут RPERF ≥60 с, три чередующиеся A/B на профиль; P95 не хуже 5%. Изменение команд не выдаётся за рост FPS.
- Прототип: ≤96 следов / 30 с, ≤96 владельцев. Предварительный консервативный резерв дополнительных CPU/GPU instance-буферов и bookkeeping ≤256 KiB через общий WorldBudget; активные matrix capacities суммарно <192, переходная переаллокация <288. Геометрия/материал остаются прежними общими; после опустошения/выгрузки владельца его batch освобождается.
- Контроль: поворот/первое лицо, движущиеся поверхности, невидимые wind sources, unload/reload, два владельца общей геометрии, overflow/TTL и пять завершённых входов. Стандартный WebGL2 instancing не требует multi-draw; fallback без ускоряющих расширений проверяется отдельно.

## Результат

Инвентаризация: три профиля × три ракурса, callbacks main/shadow сверены с фактическими calls. Выбран подтверждённый набор 96 следов одной geometry/material на одной поверхности. Принятый результат: **low 326→231 (−29,1%), balanced 476→381 (−20,0%) команд** в насыщенном кадре; по три чередующиеся ≥60 с A/B-пары на профиль, худшее изменение P95 +0,6%. Ускорение FPS/CPU/GPU не заявлено. Static merging/BatchedMesh рассмотрены по inventory, не внедрены и не названы проверенным ускорением.

High исследован в шести A/B-парах, включая продление после дополнительного 120-секундного прогрева. Команды 544→449, но gate P95 нарушался (16,8→33,3 мс); **обычный high сохраняет Mesh-путь**. Нет blanket-PASS для всех кандидатов. Исходный путь также используется при невозможности резерва. Причина межсерийного дрейфа не установлена, выводы не переносятся на другое оборудование.

`PelletMarks` владеет ≤96 marks/owners, TTL 30 с, активной matrix capacity <192 и консервативными affine bounds; заранее резервирует 256 KiB в общем WorldBudget. Геометрия/материал общие, бюджет окна ≤128 MiB. Очистка вызывается и в презентации, и непосредственно при unload/replacement/scene reset, поэтому занятый GPU не удерживает отсоединённые модели. Модели, generator, коллизии, shared/server не менялись.

Финальные unit **482/482**, check **0 errors/warnings**, imports **214 модуля, без нарушений**, build PASS; WebGL **16/16**, включая отсутствие multi-draw, GPU-busy unload и пять циклов; regular browser **4/4** (профили, GPU backpressure, FPS-график, стрельба/камера/reload). Логи, условия, raw/summary/сравнение, PNG, оговорки и точные команды — evidence (артефакт удалён); источник принятого кода — `accepted-source.tar.gz` рядом. `git diff --check` чист, server/shared не изменены; исходный локальный pasture.glb сохранил SHA-256 из TASK-110.
