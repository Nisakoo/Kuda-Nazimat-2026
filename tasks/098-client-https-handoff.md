# Клиент: работа по HTTPS/WSS (передача от сервера)

## Цель и изменения требований
Сервер переходит на HTTPS/WSS на том же порту 8080; сервер выпускает самоподписанный сертификат, устройство игрока один раз доверяет ему через страницу сервера `/setup` ([TLS](../specs/server-tls.md)). PROTO v3, формы запросов/ответов, токен в памяти и порядок входа не меняются. Клиентские требования клиентская команда уточняет сама.

Что сервер делает и что видит клиент:
- Всё приложение (статика, `/config.json`, `/api/*`, `/world/*`, Socket.IO `/game`) — только `https://` и `wss://`.
- Открытый HTTP на том же порту: `GET/HEAD` → `308` на https; `POST`, Socket.IO и прочее → `426 Upgrade Required` без обработки. `/setup`, `/server.crt` и `/api/health` доступны и по HTTP.
- `config.json` по-прежнему `serverUrl: null` → клиент работает с адресом, с которого загружен.
- HTTP-режима у сервера больше нет ни в одном окружении, включая development (`https://localhost:8080`); в `corsOrigins` development вместо `http://localhost:5173` теперь `https://localhost:5173`, поэтому Vite dev тоже должен работать по HTTPS. Сертификат и ключ сервера для Vite: `server/data/tls/server.{crt,key}` (использовать в `server.https` Vite; не коммитить, ключ не копировать за пределы машины). Сертификат привязан к адресам в нём: если IP сменился, ошибка имени — это штатное предупреждение, администратор выпускает новый (`tls renew --yes`), игроки проходят `/setup` заново.

## Реализация
- [ ] Клиентская команда решает объём и обновляет свои спеки.
- [ ] Проверить, что нигде нет жёстких `http://`/`ws://` к игровому серверу; Socket.IO выбирает `wss` по протоколу `serverUrl`.
- [ ] Ручной ввод IP/порта (EntrySetup, Settings): по умолчанию `https` и порт 8080; адрес `http://…` к удалённому серверу не принимать молча.
- [ ] Сетевая ошибка при обращении к другому серверу (fetch `TypeError`, браузер не сообщает причину TLS): показать подсказку «Возможно, это устройство не доверяет сертификату сервера — откройте http://<IP>:<порт>/setup».
- [ ] Перевести Vite dev на HTTPS с сертификатом сервера (иначе CORS development не пропустит запросы).
- [ ] Необязательно: в secure context доступен `crypto.randomUUID` (запасной путь TASK-049 можно оставить).
