# Настраиваемые backend LLM в существующем игровом сервере

## Цель и изменения требований

По запросу владельца подключить локальную LLM непосредственно к игре: оператор выбирает Ollama или MLX, а не получает жёстко выбранный backend/отдельный чат. Добавлен LLM-015: явная конфигурация, диагностика и интеграция v1. MLX технически требует Apple Silicon; несовместимость не приводит к скрытой смене backend. PROTO v1 сохраняется: один ответ в общем дедлайне 8–9 с. Полная потоковая система по-прежнему требует v2.

## Реализация

- [x] Зарегистрировать `ollama` и `mlx`, валидировать доверенные options, обеспечить readiness/отказ без остановки мира.
- [x] Реализовать owned Python worker: bounded IPC, точная токенизация, один ответ, физическая отмена, освобождение процессов, без runtime-загрузок и fallback.
- [x] Ollama: выделенный локальный runner, CPU/GPU-профиль оператора, pin версии/digest, raw prompt, bounded HTTP.
- [x] MLX: Apple Silicon, локальный text-only snapshot, pinned runtime, точный template, bounded generation.
- [x] Проверять budget и memory soft threshold; не выдавать sampled RSS за доказательство hard cap.
- [x] Связать недоступность/восстановление backend с сервисом/health; не повторять неудавшийся вопрос автоматически.
- [x] Общий контрактный набор разрешает подтверждённый loopback, но запрещает внешнюю сеть; интеграционные тесты game/HTTP/config.
- [x] Документировать конфигурацию обоих backend, подготовку до игры, один запуск игрового сервера и реальные границы.

## Отмена блокирующего worker и различение ошибок метрики

- Дополненный пользователем operational-log установил последовательность: timeout03:59:24; warningstop03:59:26; recovery startup03:~04:00 завершился `memory_unavailable` в04:00:29.845. Это ошибка достоверного сбора метрики, **не доказательство resource_limit/превышения4GB**. Поздний валидный ps snapshot не устанавливает, почему сбор не удался под нагрузкой.
- Code review подтвердил отдельный lifecycle дефект LLM-011: блокирующий Python HTTP-read не читает IPC stop, а defaultSIGTERM завершает Python без finally. Supervisor правильно запрещает сигналы stalePGID после выхода лидера; преждевременный выход worker может поэтому сорвать500мс escalation для owned group и растянуть stop. Данный механизм требует исправления с subprocess fixtures; конкретный survivor на пользовательском2с snapshot не наблюдался и не выдумывается.
- Реализован Ollama-only контролируемый SIGTERM: внутренний BaseException прерывает blocking HTTP и запускает finally/owned daemon cleanup/reap. Контекст spawn откладывает исключение до присваивания Popen handle; повторные SIGTERM не обрывают unwind/cleanup; предыдущий handler восстанавливается, импорт его не устанавливает. Запрет stalePID/group сигналов, quarantine и удержание слота до физического подтверждения не менялись.
- Добавлены subprocess/loopback fixtures без Ollama/весов: blocked startup/answer HTTP, cooperative reap, TERM во время Popen до assignment, повторный TERM, EOF/IPC stop и stubborn direct child с500мс groupKILL при живом лидере. Linux fixture использует изолированный subreaper и child watchdog против running-orphan при regression. Квалификация macOS/all-descendants/escaped processes/2с не подменяется этими тестами: при раннем выходе daemon остающийся native descendant всё ещё требует group confirmation/quarantine.
- Добавлены7 фиксированных безопасных memory_sample кодов для command timeout/error/buffer, parse/missing row/invalid metric и watchdog deadline; неизвестные ошибки/не-Error rejection остаются memory_unavailable без исходного текста. Внутренний command-callback seam напрямую проверяет реальные classification/parser, bounded command args и conservative RSS composition; он недоступен из config и не подменяет Node module глобально. Пределы500мс/600мс/3.5GB и игровой deadline не увеличены.
- Промежуточные Node-прогоны обнаружили race самого fixture: ранний отказ memory guard успевал остановить настоящий OS-child до записи JS spawn-event; getter pid ошибочно читал отсутствующий event. Исправлено наблюдением фактического owned PID через существующий memoryBytes(group) seam, без задержки production cancel и без ослабления проверок гибели процесса. После исправления итоговый serial прогон прошёл; промежуточные red прогоны не выдаются за PASS.
- Финальная serial проверка: `npm --prefix server run check` PASS (48 modules/130 dependencies); `make server-test` **158 passed, 1 skipped** (отсутствует built real-world fixture); Python discovery **52 passed**; docs checker (24 specs/29 tasks/238 requirements) и `git diff --check` PASS. В текущем окружении make доступен и выполнен; поздние правки документации проверены повторно. Ни Ollama, ни веса на сервере разработки не запускались/не скачивались.
