# Сервер: целевое поведение и память NPC

## Цель и изменения требований

Реализовать AI-001–011 и [NPC-AI](../specs/npc-character-behavior.md) поверх существующих NpcResponder/LanguagePort и единственной GenerationQueue. Текущий игровой протокол — v3, HTTP BABEL — v2; новый AI lifecycle не означает возврат Socket.IO к v2. Адаптеры Ollama/MLX уже существуют в TASK-045, но market LanguagePort остаётся test. Наличие этих адаптеров не реализует новое поведение или его аппаратную квалификацию.

Согласование [TASK-058](058-npc-behavior-specs.md) заменяет старые цели этой задачи: память только в scope AUTH sessionId/playerId/npcId, без пользовательского reset; ответы en/es A2, авторские характер/знания/исторические рамки, три состояния отношения только для речи, модельное приветствие, ограниченный архив и компактная память, игровые локальные сообщения при техническом сбое без ложного completed. Кандидат 4096/256 токенов не становится рабочим профилем автоматически.

## Проектные условия до реализации

- [ ] Согласовать wire-схемы и исполняемые валидаторы открытия/языка/результата/статуса неудачи. Не добавлять вымышленные поля в существующий PROTO-007; миграцию версии/совместимость описать явно.
- [ ] Спроектировать миграцию истории/памяти/отношений/receipt к server-owned AUTH scope. Legacy-тексты без sessionId не назначать текущему входу. Согласовать bounded квоты, срок очистки закрытых сессий/ledger и поведение на границе хранения.
- [ ] Выбрать проверяемый алгоритм компактной памяти и извлечения намерения, provenance, безопасное поведение при неопределённости; определить атомарный trigger отношения относительно успешного ответа/отмены. Если нужен модельный вызов, он учитывается в той же очереди/deadline/RAM, не запускается скрыто в обход квот.
- [ ] Утвердить карточки/корпус/aliases для реальных NPC Вавилона, роль-доступ к знаниям и совместимость проверки содержания с показом partial. Новая документация не подтверждает безопасный streaming неподтверждённых фрагментов.

## Реализация

- [ ] Применить [руководство автора](../docs/npc-authoring.md): brief → карточка/материалы/примеры → одобрение автора → данные и проверки. Не создавать отдельную модель/очередь/плагинную архитектуру для каждого NPC.
- [ ] Реализовать локальный KnowledgeSource и поиск подходящих старых эпизодов с фильтрацией session/player/NPC/роли до получения кандидатов. FTS5 и aliases без отдельной embedding-модели; поиск проверяется отдельно от генерации.
- [ ] Развить NpcDialogueService, PromptBuilder и хранение: текущий вопрос, авторские правила/карточка, разрешённые game-facts, отношение, компактная память, выбранные источники и последние реплики. Игрок/цитаты/история не становятся системными инструкциями; факты игры не выводятся из текста модели.
- [ ] Реализовать en/es A2 по серверной настройке, ограничения вопроса/ответа и вывода, модельное приветствие как NPC-only запись. Повторное открытие не генерирует повтор; все модельные этапы используют существующую очередь и таймаут.
- [ ] Реализовать обычное/недовольное/дружелюбное отношение с серверной проверкой переходов. Извинение из недовольного возвращает обычное, не дружбу. Цитаты, сомнительная интерпретация и технический сбой не ухудшают отношение; нет изменений цен/заданий/инвентаря.
- [ ] Реализовать транзакционный финал и bounded receipt/result без replay generation. Закрытие окна/потеря связи отменяют запрос, не очищая действующую сессию; новая AUTH-сессия получает новую память. Старые pending/summary/cache/result не попадают в новый scope. Не освобождать квоту до физической остановки.
- [ ] Показать локальную игровую fallback-фразу как неудачную попытку с явным повтором, не содержательный completed-ответ/факт памяти/оценку языка. Техническая причина остаётся в безопасной диагностике. При недоступной модели нет нового вызова ради fallback.
- [ ] Обновить документацию по фактическому результату, отдельно указать текущий профиль и ещё не квалифицированные цели.

## Приёмка

- [ ] Проверить сценарии AI/NPC-AI/STORE с SQLite, fake worker и затем реальным выбранным backend. Один NPC различает двух игроков; два NPC не обмениваются историей; две AUTH-сессии одного игрока также изолированы.
- [ ] Проверить меню/reconnect/рестарт с той же действующей сессией против нового login/expiry/revoke. Новая память не сбрасывает словарь, аккаунт, задания и инвентарь. Reload без сохранённого токена не выдаётся за восстановление прежней сессии.
- [ ] Проверить обе очередности commit/cancel/revoke, старую generation после новой сессии, сбой БД, receipt повторного приветствия/извинения и физическое удержание слота. Ошибка/неопределённый commit не вызывает вторую generation.
- [ ] Проверить авторские рамки, современные вопросы, бытовой вымысел, ролевые секреты, эмодзи/длину, en/es A2, оскорбления/цитаты/извинения и формат fallback. Fixtures не объявляются семантической квалификацией модели.
- [ ] Выполнить server/shared tests и type/import checks; при клиентских изменениях client-test/type/import/build и релевантные browser checks. Проверить ограничение очереди≤4/1player, прежний RAM-budget и текущий реальный параллелизм 1.
- [ ] Полную языковую/скоростную/RAM-квалификацию выполнить по TASK-018; профиль 4096/256 не принять по прошлым измерениям 2048/128. Неисполненные проверки явно отметить.
