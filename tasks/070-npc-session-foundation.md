# Первый этап реализации: проверенная AUTH-область разговоров NPC

## Цель и разрешённый объём

После документального согласования пользователь поручил начать реализацию. Этот этап устраняет пересечение NPC-истории между AUTH-сессиями в обычном Socket.IO и market BABEL. Он не объявляет реализованными полный архив, сжатие, отношения, модельные приветствия или en/es A2.

Существующее ограниченное окно 50/6 осталось временной границей текущего пути; оно не становится целевой политикой архива NPC-AI-011. Предел суммарный: обычный путь — 50 пар на игрока/NPC по всем AUTH-сессиям; BABEL — 50 ответов на игрока по всем NPC/сессиям вместе с retained legacy. Новые записи могут вытеснять старые и legacy по прежнему скользящему правилу, поэтому полное сохранение истории сессии пока не обещается. Новые квоты, очистка, классификация/атомарность отношения и идентичность приветствия предложены пользователю отдельно и до ответа не считаются принятыми. Новая миграция не должна неявно выбрать срок хранения через каскадное удаление AUTH-записей.

Параллельно клиентская работа по TASK-044 устраняет блокировку production-входа и добавляет серверный logout. Этот этап не обещает сохранение токена после reload: это должно быть реализовано явно, а новый login не восстанавливает старую NPC-память.

## Реализация

- [x] Передать проверенный server-owned AUTH sessionId от gateway/HTTP в NPC-сервис; клиент не задаёт scope.
- [x] Ограничить чтение и запись обычной NPC-истории session/player/NPC; legacy без sessionId не подмешивать новому входу.
- [x] Исключить чужую сессионную историю из BABEL prompt, polling/snapshot и результата повторной операции. Сохранить прочие поля профиля, словарь, инвентарь, задания и языковые настройки.
- [x] Проверить отмену обоих транспортных владельцев при отзыве AUTH; перед результатом повторно проверить доступ, актуальность и монотонный срок. Слот сохраняется до физической остановки.
- [x] Сохранить общую очередь ≤4 unfinished и ≤1/playerId, текущий профиль, отсутствие автоматического replay generation и отсутствие отдельного runtime для BABEL.

## Приёмка

- [x] SQLite и fake responder: две действующие сессии одного игрока, два игрока и два NPC изолированы; та же действующая сессия продолжает историю после reconnect/рестарта.
- [x] Legacy-данные не приписываются текущему входу и не теряются из-за угадывания sessionId.
- [x] BABEL snapshot/polling и replay старого NPC requestId не открывают старый ответ новой сессии; словарь/инвентарь/задание не сброшены.
- [x] Expiry/revoke/takeover и поздний результат не создают записи или доставки в другом scope; физические квоты не освобождаются преждевременно.
- [x] `make server-test`, серверные type/import checks; клиентские проверки для независимой TASK-044. Результаты и недоступные проверки записать отдельно.
- [x] Обновить текущее/целевое описание после фактического результата. Не объявлять всю NPC-AI реализованной по этому срезу.

## Результат

Первый ограниченный срез реализован. В исходной ветке миграция 004 сохраняла legacy без выдуманного sessionId и без session FK cascade. При интеграции main этот срез переносится в миграцию 009 с reconciliation прежней branch-схемы версии 4; её проверка остаётся отдельной. Проверенный AUTH scope проходит оба маршрута; BABEL snapshot пересобирается для каждого вызывающего даже после общего pending не-NPC запроса. Чужой/legacy NPC replay возвращает отказ без новой генерации. Другие данные аккаунта сохранены.

BABEL-работа привязана к конкретному управляющему сокету (`babel:socket:<id>`), не только к сессии: позднее закрытие прежнего соединения не отменяет работу нового. Logout, expiry, disconnect и takeover отменяют нужное вычисление, но квота удерживается до физического завершения. Проверки AUTH/control/role/range выполняются до модели, commit и доставки, включая отложенный partial и последнюю HTTP-границу после await. Не требующий перевода BABEL-путь сохраняет монотонный бюджет без занятия модельного слота.
