Панели в стиле inventar.png/dictionary.png/chat.png; существующий GameApp и BabylonClient остаются источниками состояния. Расширения словаря, slot рук и task-scoped map по новому поручению вынесены в TASK-046. База и ветка — TASK-040.

## Реализация
- [x] Постоянные логотип, задание, языки и нижняя панель.
- [x] Единственное окно, переключение, Esc/крестик, native dialog focus; явное продолжение Pointer Lock.
- [x] Чат/камни, серверный словарь, фактический инвентарь без локальных успехов.

- [ ] HUD S1–S3/S5–S7 проверены на реальном сервере; сохранения проверены повторным входом.
- [ ] Скриншоты сравнены с макетами на desktop/narrow; сетевой текст безопасен.
- [ ] Тесты, типы, импорты, сборка и browser-проверки проходят; результаты сохранены.

## Открытые вопросы
- Закрыто TASK-046: сервер хранит один closed bag/jug/null slot; подтверждение применяется через AOI. Содержимое — проекция настоящих BABEL counts, не вторая копия. NEXT pickup/transfer не реализуется и не импортируется.
- Закрыто TASK-046: learned/example/exampleTranslation сохраняются сервером, legacy records получают безопасные defaults; «Запомнил» сначала сохраняет редактируемую заметку/пример. Статус не кодируется в заметке.
- HUD подсказка I/Esc в словаре против I inventory: TASK-041 сохраняет I только для inventory, Esc для всех окон; новые M/K горячие клавиши не назначать без согласования.
- HUD-002: раскрытые шаги не определены; TASK-041 показывает существующий серверный task и fed, не сочиняет шаги.
- HUD-003: где менять родной язык, не определено. TASK-041 сохраняет окно пары языков, learning selector использует серверные доступные языки.
- HUD-018: сообщения без перевода (BABEL-008) не должны получать ложную пометку перевода. Показывать фактический translated.
- HUD-019/020: отдельный вход в камень не согласован; существующий вход сохраняется, кнопка чата открывает тот же неизменяемый draft.
- HUD-008: язык названий предметов не согласован; сохраняются существующие метаданные, новые переводы не придумывать.
- Физический Pointer Lock, LAN/4 устройства, Wi-Fi off и реальная LLM требуют отдельной аппаратной приёмки.

План создан до реализации. Контракты реализованы; полная визуальная/аппаратная и browser-приёмка остаётся открытой до подтверждения доказательствами.
