# Учебный 3D-мир

Образовательный мир в браузере для максимум **4 одновременно активных игроков**. Один локальный сервер хранит игроков и запускает адаптивных ИИ-персонажей; клиенты работают через LAN/Wi-Fi. Игра должна работать и на серверном ноутбуке с выключенным Wi-Fi, без интернета.

Мир состоит из тематических районов, соединённых переходами; данные загружаются чанками вокруг игрока. Район и чанк — разные понятия. Состав районов, размеры чанков и метрика лимита 10% ещё не утверждены.

В `client/` реализована основа: **TypeScript strict, Vite, Svelte 5, Three.js и Vitest**, техническая сцена, пауза/перезапуск, обработка недоступного WebGL и публичная конфигурация. Socket.IO Client установлен для будущего сетевого адаптера, но пока не используется. Core, игровые сессии, карта и игровой ввод ещё не реализованы. Сервер с Socket.IO и SQLite будет отдельным проектом; его спеки хранятся здесь. Будущая LocalSession — локальное демо клиента, а не замена полной системы.

## Локальные NPC и LLM

Основная модель выбрана документально: **Qwen3.5-2B 4-bit**, Apache 2.0. Два backend — **MLX LM на Apple Silicon** и **Ollama на поддерживаемых Windows/macOS**, в том числе Intel Mac с CPU inference. Текущий Ollama требует macOS 14+; любой старый Mac автоматически не поддерживается. Один backend/модель обслуживает всех NPC. Резервный кандидат Qwen3-1.7B не включается автоматически.

Общий пиковый бюджет LLM — **4 000 000 000 байт RAM**, включая процессы, веса, все контексты и AI-буферы/кеши. На запрос — контекст 2048, вход ≤1792 токенов, стандартный выход до 128 и расширенный до 256; thinking выключен. Всего **4 незавершённых запроса**, по одному на игрока. Базовая параллельность — **1**, профиль **2** включается только после проверки backend, изоляции, памяти и лучшего обслуживания четверых без регрессии игры; два экземпляра весов не запускаются.

Цели прогретого свободного сервиса: p95 первого видимого текста ≤2 с, стандартного полного ответа ≤8 с. Для 4 одновременных запросов отдельно измеряется худший игрок каждого burst: p95 первого текста ≤26 с, сохранённого финала ≤32 с, без штатных busy/queue_timeout. Очередь ограничена 30 с, generation 30 с, общий deadline обработки 60 с; это аварийные пределы, не целевая скорость. Цели — критерии будущих замеров, не достигнутые результаты.

История сообщений и компактная память игрока/NPC хранятся отдельно в SQLite. Ответ стримится временными полными partial-снимками без per-fragment ACK/replay и получает успешный финал только после commit; повтор запроса не создаёт новый ответ. История по умолчанию ограничена 30 днями/1000 запросами на player/NPC, память — 16 небольшими записями. Поиск знаний MVP — SQLite FTS5 и локальные aliases для ru/en/es, без отдельной embedding-модели. Полный архив в prompt не отправляется. Сбой/отмена одного запроса не смешивает контексты; общий restart AI не останавливает мир. Квоты и сохранение не обходятся дополнительными вкладками. Основной нагрузочный прогон — все 4 игрока одновременно задают вопросы, включая измерения игрового шага и браузера на серверном ноутбуке.

Модели не установлены, совместимость MLX text-only артефакта, русский диалог, память и скорость не проверены. Целевые машины и утверждённые учебные материалы ещё нужны; AI/LLM/LLM-QA остаются draft с implementation: not-started. Установка/запуск сервера появятся только после проверки в отдельном проекте.

## Команды

Для разработки нужны Node.js 22.12+ в ветке 22 либо Node.js 24+, npm и GNU Make. Для просмотра готовой сборки нужен современный браузер с WebGL 2 и локальная HTTP-раздача. Зависимости и браузер для тестов подготавливаются заранее, до отключения интернета.

Из корня проекта:

```sh
npm --prefix client ci
make client
```

Vite слушает `0.0.0.0:5173` и печатает адрес для LAN; если порт занят, выводит выбранный порт. На другом ноутбуке открывается напечатанный LAN-адрес сервера. Это сервер разработки клиента; игрового сервера пока нет. `make` / `make help` показывают справку. Команды Make можно переопределить через `CLIENT_RUN_CMD` / `CLIENT_TEST_CMD`; пустое значение и ошибки не скрываются.

Проверки и сборка:

```sh
make client-test
npm --prefix client run check
npm --prefix client run check:imports
npm --prefix client run build
npm --prefix client run preview -- --host 0.0.0.0 --port 4173 --strictPort
```

`make client-test` запускает Vitest без watch и обязателен для клиентских изменений. `check` проверяет Svelte и TypeScript strict, `check:imports` — циклы, разрешение импортов и границы UI/рендера. Проверка Svelte-графа использует скомпилированный компонент; его type-only импорты дополнительно проверяются при ревью. `build` создаёт `client/dist/`, `preview` раздаёт её для локальной проверки. Для демонстрации готовую `dist/` должен раздавать локальный сервер; Vite preview не заменяет будущий игровой сервер.

Браузерные проверки готовой сборки:

```sh
cd client
npx playwright install chromium
npm run test:browser
```

Если уже установлен Google Chrome, установка Chromium не нужна: из корня можно выполнить `PLAYWRIGHT_CHANNEL=chrome npm --prefix client run test:browser`. Этот вариант проверен на macOS; Chromium-вариант в текущем окружении не запускался. Браузерные тесты пересобирают клиент, поднимают HTTP-раздачу на `127.0.0.1:4173`, проверяют WebGL, resize, паузу, пять перезапусков и ошибки; снимки экрана сохраняются в `client/test-results/`. В основном сценарии внешние запросы блокируются. Физическое отключение Wi-Fi и второй ноутбук остаются отдельными непроверенными сценариями.

Команды установки из lockfile, тестов, типизации, проверки импортов, сборки, Vite dev и браузерного прогона проверены; точная среда и результаты — в задаче 002. Сборка сообщает о JS-чанке больше 500 kB; бюджет производительности пока не установлен.

## Модули и конфигурация клиента

- `client/src/main.ts` — загрузка настроек и монтаж Svelte, очистка при HMR.
- `client/src/app/` — GameApp, подписки состояния, единственный цикл кадров, resize/visibility и проверка настроек.
- `client/src/render/` — RenderAdapter и минимальный ThreeRenderer; геометрия, материалы, canvas и WebGL-контекст освобождаются при завершении.
- `client/src/ui/` — интерфейс поверх сцены, пауза, продолжение, перезапуск и сообщения об ошибках; обновления каждого кадра в UI не передаются.

Остальные модули из архитектуры появятся по своим задачам. Сцена содержит процедурный куб и площадку; карт, моделей GLB, фоновой загрузки мира и серверных файлов в поставке нет. Лимит 10% для игрового мира этим не подтверждён.

Публичные настройки находятся в `client/public/config.json` и копируются в `client/dist/config.json`. Готовая сборка читает их при открытии с `cache: no-store`, поэтому настройки в `dist/config.json` можно изменить без пересборки. Секреты и игровые данные туда не помещаются.

| Поле | Значение по умолчанию | Поведение на этапе foundation |
|---|---|---|
| `session` | `local` | Техническая сцена; `online` показывает сообщение о недоступности. Игровых LocalSession/OnlineSession ещё нет. |
| `serverUrl` | `null` | Вычисляется из origin страницы; можно задать HTTP(S)-адрес или относительный путь. Соединение пока не создаётся. |
| `mapId` | `demo` | Идентификатор для будущей карты; загрузки не вызывает. |
| `chunkRadius` | `null` | Не задан до согласования MAP; целое неотрицательное значение проходит валидацию, но пока не применяется. |
| `debug` | `false` | Форма настройки предусмотрена; метрики добавляются на следующих этапах. |
