# Учебный 3D-мир

Браузерный клиент образовательного мира в сеттинге Вавилона: прогулка от третьего лица, тематические районы, NPC и общение игроков. Клиентский прототип реализован на **TypeScript strict, Vite, Svelte 5, Three.js, Socket.IO Client и Vitest**.

По умолчанию открывается «Рынок Вавилона»: три лавки, четыре торговых персонажа, пастбище с четырьмя козами, закатный свет и локальный маршрут покупок/кормления. Меню содержит сумку, задание, камень и словарь. Это клиентский стенд: данные сбрасываются при перезапуске, перевода и серверной синхронизации нет.

Работают локальная прогулка, GLB/glTF и анимации, потоковая карта с коллизиями и лимитом кэша, Pointer Lock, настройки и OnlineSession. Тестовый сетевой режим позволяет вручную проверить чат, ответы NPC, потерю связи и повторный вход без сервера; он явно обозначен в UI. Сервер с входом, SQLite и авторитетным миром создаётся в `server/` (раздел «Сервер»); адаптивный ИИ подключается к нему отдельным адаптером. Проверка двух физических ноутбуков и реально отключённого Wi-Fi ещё не выполнена.

## Запуск

Нужны Node.js 22.12+ в ветке 22 либо 24+, npm, Make. Для игры — настольный браузер с WebGL 2, Pointer Lock, клавиатура и мышь. Зависимости и браузеры для автоматических проверок подготавливаются до отключения интернета.

Из корня:

```sh
npm --prefix client ci
make client
```

Откройте [http://localhost:5173/](http://localhost:5173/) либо адрес/порт из вывода Vite. Он слушает `0.0.0.0` и печатает адрес для LAN. Это раздача клиента, не игровой сервер. Полный мир генерируется автоматически перед запуском, сборкой и тестами; вручную — `npm --prefix client run world:generate`.

Готовая сборка:

```sh
npm --prefix client run build
npm --prefix client run preview -- --host 0.0.0.0 --port 4173 --strictPort
```

`client/dist/` раздаётся обычным локальным HTTP-сервером; file:// не требуется. Все JS, CSS и модели локальны, CDN/облачные API/внешние шрифты не используются. Vite preview не заменяет будущий игровой сервер.

## Ручная проверка рынка

1. Закройте вводное окно и нажмите **Начать прогулку**. WASD — идти, мышь — камера, E — взаимодействие, Esc — меню.
2. Фрукты — слева, керамика — справа, ткани — слева дальше. Подойдите к продавцу сбоку от прилавка и нажмите E; кнопки «Взять» добавляют предметы в локальную сумку. Покупки бесплатны.
3. Пройдите прямо к лестнице и между домами на пастбище. Пастух рассказывает приметы и корм четырёх коз.
4. Выберите предмет в сумке либо в окне козы. Финики — белой с колокольчиком, красные плоды — чёрной с рогами, жёлтые — рыжей пятнистой, вода — серому козлёнку. Неверный корм не расходуется. Четыре кормления открывают итоги.
5. Из меню откройте **Камень**: рисуйте, закройте и откройте окно — черновик остаётся; «Высечь» переносит неизменный рисунок в локальную историю. **Словарь** позволяет добавить, изменить и удалить запись вручную.
6. При перезапуске сцены локальный прогресс очищается. Совместные роли, перевод и восстановление серверного прогресса здесь не имитируются.

Исходная площадь и тестовая сеть остаются доступны в настройках: карта `demo` или `science`. Новая карта `market` работает локально; серверные сценарии требуют отдельной реализации.

## Ручная проверка исходной площади (`demo`)

1. Дождитесь подготовки окрестностей и нажмите **Начать прогулку**. Управление включается после подтверждения захвата мыши.
2. **WASD** или стрелки — движение относительно камеры; физические коды работают при русской раскладке. **Мышь** постоянно вращает камеру без удержания кнопки; **колесо** меняет расстояние от третьего лица.
3. Подойдите к Лее слева или Марку справа и нажмите **E**. В локальной прогулке ответы подготовлены заранее. До Леи в начальной камере: W около 1,5 секунды, затем A около 1,2 секунды.
4. **Esc** освобождает мышь и открывает меню; в диалоге закрывает его. **Продолжить** снова запрашивает захват. Blur/скрытие/потеря захвата очищают зажатые клавиши. При отказе доступны повтор и выход.
5. Клавишей **S** пройдите через передние ворота в Сады науки: меняются чанки и название района, сессия сохраняется. При медленной загрузке граница задержит движение до готовности.
6. В **Настройках** выберите карту `science`, радиус 0–2 и диагностику. Применение завершает прежнюю сессию и открывает выбранную карту. Радиус 0 готовит только текущую область и ближайший переход.
7. Выберите **Тестовый сетевой режим**. После входа откройте меню → **Общение**, отправьте текст и увидите тестовую доставку. Ввод не двигает персонажа, HTML-подобные строки остаются текстом. NPC отвечают через тот же сетевой протокол с явной пометкой теста.
8. Меню → **Проверить разрыв связи** → **Повторить подключение**. Дождитесь нового снимка и снова нажмите **Начать прогулку**. Старые действия не воспроизводятся. **Выйти из сессии** тестового режима возвращает локальную прогулку.

Режим **Локальный сервер** требует готовой серверной сессии; без неё игровой канал не открывается. `GameApp.provideServerSession({token, expiresAt})` — граница будущей интеграции входа, не замена демонстрационной авторизации. Ручная вставка токена не считается приёмкой NET-007.

## Проверки

```sh
make client-test
npm --prefix client run check
npm --prefix client run check:imports
PLAYWRIGHT_CHANNEL=chrome npm --prefix client run test:browser
PLAYWRIGHT_CHANNEL=chrome npm --prefix client run test:render
```

`make client-test` запускает Vitest без watch. `check` проверяет Svelte/TypeScript strict и `check:core` — Core, session и GameLoop без DOM/Node. `check:imports` проверяет циклы и границы модулей. Браузерный прогон пересобирает production и запускает HTTP на `127.0.0.1:4173`; отдельный render-стенд использует порт 5174 и не входит в production. Артефакты — `client/test-results/` и `client/render-test-results/`.

Вместо установленного Chrome можно заранее выполнить `cd client` → `npx playwright install chromium`, затем `npm run test:browser` / `npm run test:render`. Этот вариант здесь не запускался. Проверенная среда: macOS 26.3 arm64, Node 25.6.0, npm 11.8.0, Chrome 156.0.8078.79, Playwright 1.64.1.

Финальный результат: **125 unit-тестов, 17 браузерных сценариев, 4 WebGL-сценария**; типизация и импорты проходят. Профиль Apple M4 / 16 GiB / ANGLE Metal, 1280×800, DPR 1: 60 секунд после прогрева, минимум 59,8 FPS, P95 ≤17,5 ms; после пяти перезапусков 14 геометрий / 13 текстур, рост retained JS heap ≈1,63 MiB. Подробности и исходные измерения — [TASK-008](tasks/008-client-verification.md) и [JSON-профиль](tasks/evidence/client-profile-2026-10-31.json). Это профиль клиента на указанной машине, не результат другого ноутбука или сервера.

Раскладка интерфейса дополнительно проверена в Chrome при 1280×800, 1024×600 и 640×480: панели прокручиваются в пределах окна, кнопки меню и игровых действий не перекрываются, селектор радиуса отображает выбранное значение. После исправлений — 20 браузерных сценариев; подробности и повторные проверки финального изменения — [TASK-021](tasks/021-client-ui-layout.md).

Сборка сообщает о JS-чанке 837,25 kB (gzip 224,10 kB). Критерии измеренного профиля выполняются; instancing/LOD не вводились. Блокировка внешних запросов проверена автоматически, физическое выключение Wi-Fi и LAN-проверка второго ноутбука остаются неподтверждёнными.

Демо — 1024 чанка по 32 м, общие авторские GLB, тематические районы и уникальные видимые таблички. Collision bitmap получается из GLB, одинаковые BIN адресуются по SHA. Лимит кэша 10% измеряется уникальными сериализованными байтами статического мира, с резервированием до запроса и до последнего CPU/GPU-владельца. У исходного demo 17 593 661 байт, лимит 1 759 366 байт; у market 18 738 211 байт, лимит 1 873 821 байт; отдельно ограничены консервативные полезные данные 32 MiB. Это не полный RSS браузера/драйвера. Подробности — [MAP](specs/client-world-streaming.md).

## Конфигурация

`client/public/config.json` копируется в dist и читается с no-store. Настройки готовой сборки можно менять без пересборки. В нём нет секретов/токенов.

| Поле | По умолчанию | Поведение |
|---|---|---|
| session | local | Локальная прогулка; online требует серверной сессии |
| serverUrl | null | Origin страницы; разрешён HTTP(S)-адрес или относительный путь |
| mapId | market (config.json) | Локально доступны market, demo и science; онлайн — ID серверной карты |
| chunkRadius | null | Радиус 1; допустимы 0–2 |
| debug | false | Координаты, FPS/время кадра, draw calls, ресурсы и кэш |

PROTO v1: namespace `/game`, событие `game`, auth `{version:1, token}`. Защищённый HTTP — `<serverUrl>/world/` с тем же Bearer token, без публичного fallback. Ограниченные retry/очереди, корреляция и восстановление — [PROTO](specs/protocol.md). Сессия хранится только в памяти. Вход (mock по имени) и проверка доступа — на сервере `server/` (раздел «Сервер»).

## Сервер

Сервер — `server/` этого репозитория: **Node 24, TypeScript strict, Socket.IO, node:sqlite, Vitest**, модульный монолит с чистыми слоями (домен → сервисы → адаптеры, единственный composition root). Общий исполняемый контракт клиента и сервера (протокол v1, сущности, формат карты, проходимость) — корневой `shared/`. Сервер реализует PROTO v1, на котором уже работает клиент, и не меняет `client/`.

## Локальные NPC и LLM

Основная модель выбрана документально: **Qwen3.5-2B 4-bit**, Apache 2.0. Два backend — **MLX LM на Apple Silicon** и **Ollama на поддерживаемых Windows/macOS**, в том числе Intel Mac с CPU inference. Текущий Ollama требует macOS 14+; любой старый Mac автоматически не поддерживается. Один backend/модель обслуживает всех NPC. Резервный кандидат Qwen3-1.7B не включается автоматически.

Общий пиковый бюджет LLM — **4 000 000 000 байт RAM**, включая процессы, веса, все контексты и AI-буферы/кеши. На запрос — контекст 2048, вход ≤1792 токенов, стандартный выход до 128 и расширенный до 256; thinking выключен. Всего **4 незавершённых запроса**, по одному на игрока. Базовая параллельность — **1**, профиль **2** включается только после проверки backend, изоляции, памяти и лучшего обслуживания четверых без регрессии игры; два экземпляра весов не запускаются.

Цели прогретого свободного сервиса: p95 первого видимого текста ≤2 с, стандартного полного ответа ≤8 с. Для 4 одновременных запросов отдельно измеряется худший игрок каждого burst: p95 первого текста ≤26 с, сохранённого финала ≤32 с, без штатных busy/queue_timeout. Очередь ограничена 30 с, generation 30 с, общий deadline обработки 60 с; это аварийные пределы, не целевая скорость. Цели — критерии будущих замеров, не достигнутые результаты.

История сообщений и компактная память игрока/NPC хранятся отдельно в SQLite. Ответ стримится временными полными partial-снимками без per-fragment ACK/replay и получает успешный финал только после commit; повтор запроса не создаёт новый ответ. История по умолчанию ограничена 30 днями/1000 запросами на player/NPC, память — 16 небольшими записями. Поиск знаний MVP — SQLite FTS5 и локальные aliases для ru/en/es, без отдельной embedding-модели. Полный архив в prompt не отправляется. Сбой/отмена одного запроса не смешивает контексты; общий restart AI не останавливает мир. Квоты и сохранение не обходятся дополнительными вкладками. Основной нагрузочный прогон — все 4 игрока одновременно задают вопросы, включая измерения игрового шага и браузера на серверном ноутбуке.

Модели не установлены, совместимость MLX text-only артефакта, русский диалог, память и скорость не проверены. Целевые машины и утверждённые учебные материалы ещё нужны; AI/LLM/LLM-QA остаются draft с implementation: not-started. Адаптер модели подключается к порту `NpcResponder` сервера (NPC-005).

## Документация и этапы

[AGENTS.md](AGENTS.md) — правила проекта; [architecture.md](architecture.md) — границы; [SDD](.agents/skills/sdd/SKILL.md) — порядок работы. `specs/` содержит требования, `tasks/` — реализацию и доказательства. `status` спеки описывает готовность документа, `implementation` — фактическую реализацию; готовая спека не означает готовую систему.

PROTO-007 отнесён к v2, NPC-часть UI-005/NET-004 для v1 уточнена (`npc-question`/`npc-answer`); повторная приёмка — за клиентской командой. TASK-002 сохраняет незавершённую физическую проверку CLIENT S4. NET-007 / TASK-016, серверные TASK-010–015, 024–026 и системная автономная демонстрация не выполнены.
