# Учебный 3D-мир

Браузерный клиент образовательного мира в сеттинге Вавилона: прогулка от третьего лица, тематические районы, NPC и общение игроков. Клиентский прототип реализован на **TypeScript strict, Vite, Svelte 5, Three.js, Socket.IO Client и Vitest**.

По умолчанию открывается «Рынок Вавилона»: три лавки, четыре торговых персонажа, пастбище с четырьмя козами, закатный свет и локальный маршрут покупок/кормления. Меню содержит сумку, задание, камень и словарь. В запуске `make client` это локальный стенд со сбросом данных. `make demo` включает настоящий сервер, роли 1–4, сохранения, общие камни и личный словарь; переводчик/NPC по умолчанию тестовые; явный `language.adapter: local` использует общую локальную модель.

Работают локальная прогулка, GLB/glTF и анимации, потоковая карта с коллизиями и лимитом кэша, Pointer Lock, настройки и OnlineSession. Тестовый сетевой режим позволяет вручную проверить чат, ответы NPC, потерю связи и повторный вход без сервера; он явно обозначен в UI. Сервер с входом, SQLite и авторитетным миром реализован в `server/` (раздел «Сервер»); адаптивный ИИ подключается к нему отдельным адаптером. Проверка двух физических ноутбуков и реально отключённого Wi-Fi ещё не выполнена.

## Запуск

Для клиента нужны Node.js 22.12+ в ветке 22 либо 24+, npm, Make; совместный запуск с сервером требует Node 24.15+ в ветке 24. Для игры — настольный браузер с WebGL 2, Pointer Lock, клавиатура и мышь. Зависимости и браузеры для автоматических проверок подготавливаются до отключения интернета.

Из корня:

```sh
npm --prefix client ci
make client
```

Откройте [http://localhost:5173/](http://localhost:5173/) либо адрес/порт из вывода Vite. Он слушает `0.0.0.0` и печатает адрес для LAN. Это раздача клиента, не игровой сервер. Полный мир генерируется автоматически перед запуском, сборкой и тестами; вручную — `npm --prefix client run world:generate`.

Готовая сборка:

```sh
npm --prefix client run build
npm --prefix client run preview -- --host 0.0.0.0 --port 4173 --strictPort
```

`client/dist/` раздаётся обычным локальным HTTP-сервером; file:// не требуется. Все JS, CSS и модели локальны, CDN/облачные API/внешние шрифты не используются. Vite preview раздаёт локальный стенд; игровой сервер запускается через `make demo`.

## Ручная проверка рынка

В **Настройки → Качество графики** доступны обычное (по умолчанию: DPR ≤1, тени 1024), облегчённое (без теней и сглаживания) и высокое (DPR ≤2, тени 2048). Выбор сохраняется в браузере и применяется кнопкой «Применить и открыть карту». Разрешение интерфейса не снижается. Диагностика показывает частоту отправленных кадров отдельно от частоты цикла и пропусков из-за занятого GPU. Изменения и измерения — [TASK-079](tasks/079-low-end-render.md).

1. Закройте вводное окно и нажмите **Начать прогулку**. WASD — идти, мышь — камера, E — взаимодействие, Esc — меню.
2. Фрукты — слева, керамика — справа, ткани — слева дальше. Подойдите к продавцу сбоку от прилавка и нажмите E; кнопки «Взять» добавляют предметы в локальную сумку. Покупки бесплатны.
3. Пройдите прямо к лестнице и между домами на пастбище. Пастух рассказывает приметы и корм четырёх коз.
4. Выберите предмет в сумке либо в окне козы. Финики — белой с колокольчиком, красные плоды — чёрной с рогами, жёлтые — рыжей пятнистой, вода — серому козлёнку. Неверный корм не расходуется. Четыре кормления открывают итоги.
5. Из меню откройте **Камень**: рисуйте, закройте и откройте окно — черновик остаётся; «Высечь» переносит неизменный рисунок в локальную историю. **Словарь** позволяет добавить, изменить и удалить запись вручную.
6. При перезапуске сцены локальный прогресс очищается. Совместные роли, перевод и восстановление серверного прогресса здесь не имитируются.

Исходная площадь и тестовая сеть остаются доступны в настройках: карта `demo` или `science`. Карта `market` поддерживает как локальный стенд, так и серверный BABEL-режим.

## Серверный Вавилон и башня

```sh
make prepare   # один раз, с интернетом
make start     # без интернета; make demo — синоним, PORT=9000 меняет порт
```

Сервер печатает блок подключения с адресами для этого компьютера и для других устройств; экран администратора — `http://localhost:8080/operator` (только на самом сервере). Первый этап новой панели содержит обзор, сервер, клиентов и действия с аккаунтами; история метрик, FPS и редактирование NPC пока недоступны ([TASK-083](tasks/083-admin-panel-foundation.md)). Самопроверка без запуска — `npm --prefix server run lan:check`. Подробности и диагностика — [server/README.md](server/README.md), [OFFLINE](specs/offline-multiplayer.md).

Откройте [http://localhost:8080/](http://localhost:8080/) (или LAN-адрес из вывода сервера). Зарегистрируйтесь с именем и паролем, подтвердите облик, выберите режим и два разных языка. Для существующего аккаунта используйте вкладку «Вход». В режиме «С друзьями» можно выбрать 2–4 игроков. Первый участник задаёт размер группы, остальные присоединяются. В соло доступны все шаги; в совместном задании первый игрок у пастуха получает список, остальные покупают и кормят. Группа стартует после заполнения ролей. Повторный вход восстанавливает данные. Отдельная кнопка «Демонстрационный вход по имени» открывает тестовый гостевой вход без пароля.

Сервер должен оставаться запущенным в терминале. Если `localhost:8080` отказывает в соединении, запустите `make start` (подготовленная сборка и сервер) или `make server` (если клиент уже собран). `make client` запускает отдельный локальный стенд на порту 5173.

Новый вход создаёт новую область памяти NPC; продолжение той же действующей AUTH-сессии сохраняет её ограниченное окно истории.

Меню содержит языки, информацию, задание, сумку, общение, камень и личный словарь. Кнопки покупки/кормления обращаются к серверу, неверный корм не расходуется. Слово в задании, переводе или ответе NPC открывает словарь с предложением перевода; запись можно исправить. Штрихи камня не стираются, закрытие окна сохраняет черновик, высеченные камни видит вся группа. Закройте панель и нажмите **Продолжить**, чтобы снова включить управление.

**По умолчанию переводчик и NPC тестовые.** Для подготовленного Ollama/MLX в существующем `server/config.json` задайте `defaultMap: "market"` и `language: { "adapter": "local", "options": {} }`, сохранив свои `npc`/профили и пути моделей. Затем запустите привычный `make start` с нужными `BACKEND`/`MODEL`, если используете каталог профилей. Выберите изучаемый **en или es**, подойдите к NPC и задайте вопрос. BABEL заимствует ту же модель и очередь, без второго worker и fallback в test. Реальный запуск/качество на целевом компьютере ещё требуют проверки; инструкция A2 и fixture-тесты их не доказывают. Подробности — [сервер](server/README.md), [PROTO-009](specs/protocol.md).

Башню можно смотреть и в локальном стенде: от начальной точки рынка идите налево по боковому проходу (Z≈9) в **Двор Вавилонской башни**. Пять ярусов, двор, навес и портал; справа наружная лестница поднимается на площадку 3 м. Верхние террасы и дверь закрыты. В меню есть **Символы над башней**. Исходник — `client/scripts/generate-market-models.mjs`, модель — `client/public/assets/models/market/main-building.glb`.

Проверки BABEL — `client/e2e/babylon.spec.ts` с реальным HTTP/Socket.IO/SQLite и рестартом, башни — `client/e2e/main-building.spec.ts`. Результаты и незакрытые аппаратные проверки: [сервер BABEL](tasks/032-babylon-server.md), [клиент BABEL](tasks/033-babylon-client.md), [здание](tasks/034-main-building.md).

## Живой мир, руки и звук

В серверном режиме `make demo` карта задаёт три кошки (сон, прогулка, умывание), общую редкую стаю, умеренный визуальный ветер, четыре толкаемых горшка и пять отдельных яблок. Общие seed/расписание/опорное время приходят от сервера, поздний вход не запускает личную стаю у камеры. Горшки двигаются от допустимого касания при MOVE, не разбиваются, переживают reconnect в живой сервер и возвращаются к данным карты после рестарта.

Физическая **F** поднимает ближайшее доступное яблоко в пределах 2 м без преграды либо кладёт переносимое яблоко перед персонажем. В руках одно яблоко; оно не попадает в сумку задания и не кормит коз. Подсказка, ожидание и отказ отражают ответ backend. Ходьба, Shift и Space остаются доступны с предметом. SQLite сохраняет пять ID и принадлежность; повтор запроса не создаёт второе действие. Поднимать декор, бросать, продавать и есть яблоки нельзя. LocalSession остаётся отдельным стендом: она не имитирует эти серверные полномочия или сохранения; явный сетевой mock проверяет только контракт клиента.

**Настройки → Громкость** — один уровень для всего набора, 30% по умолчанию, 0% даёт тишину. Значение сохраняется в браузере. Локальные оригинальные WAV содержат ветер, птиц, траву, шаг/спринт/прыжок и короткое неразборчивое бормотание новых показанных реплик. Браузер разблокирует аудио по действию пользователя; ошибка файла или autoplay не останавливает игру. Происхождение и права: `client/public/assets/audio/PROVENANCE.md`.

Игровой MOVE остаётся PROTO v3; расширение `world-life` использует отдельный валидируемый подконтракт v1. Обновляйте клиент, сервер и generated world одной поставкой. Новые поля не маскируются под старые пакеты; автоматического fallback в mock нет. Каталог отдельных моделей и размещения данными хранится в `shared/world-life/market.ts`, генераторы — `client/scripts/generate-market-{models,world}.mjs`. Миграция SQLite `008.sql` добавляет предметы/receipts; совместимость прежних схем описана в STORE-013.

Фактическое прослушивание, физические LAN/Wi-Fi off и профиль на целевых ноутбуках пока **unverified**. Автоматические результаты, незавершённые проверки и видеоматериалы записываются в [матрице приёмки](tasks/evidence/world-next/acceptance.md); реализация не означает полной приёмки.

## Ручная проверка исходной площади (`demo`)

1. Дождитесь подготовки окрестностей и нажмите **Начать прогулку**. Управление включается после подтверждения захвата мыши.
2. **WASD** или стрелки — движение относительно камеры; физические коды работают при русской раскладке. **Мышь** постоянно вращает камеру без удержания кнопки; **колесо** меняет расстояние от третьего лица. **Space** — прыжок по нажатию, удержание любого **Shift** при движении — спринт; запас показан кольцом.
3. Подойдите к Лее слева или Марку справа и нажмите **E**. В локальной прогулке ответы подготовлены заранее. До Леи в начальной камере: W около 1,5 секунды, затем A около 1,2 секунды.
4. **Esc** освобождает мышь и открывает меню; в диалоге закрывает его. **Продолжить** снова запрашивает захват. Blur/скрытие/потеря захвата очищают зажатые клавиши. При отказе доступны повтор и выход.
5. Клавишей **S** пройдите через передние ворота в Сады науки: меняются чанки и название района, сессия сохраняется. При медленной загрузке граница задержит движение до готовности.
6. В **Настройках** выберите карту `science`, радиус 0–2 и диагностику. Применение завершает прежнюю сессию и открывает выбранную карту. Радиус 0 готовит только текущую область и ближайший переход.
7. Выберите **Тестовый сетевой режим**. После входа откройте меню → **Общение**, отправьте текст и увидите тестовую доставку. Ввод не двигает персонажа, HTML-подобные строки остаются текстом. NPC отвечают через тот же сетевой протокол с явной пометкой теста.
8. Меню → **Проверить разрыв связи** → **Повторить подключение**. Дождитесь нового снимка и снова нажмите **Начать прогулку**. Старые действия не воспроизводятся. **Выйти из сессии** тестового режима возвращает локальную прогулку.

Режим **Локальный сервер** показывает вкладки **Вход / Регистрация** с именем и паролем. Запросы `/api/auth/register` и `/api/auth/login` возвращают сессию; пароль не сохраняется клиентом. После входа открывается личный кабинет: имя, выбор одного из 4 обликов и языки. Для нового аккаунта сервер запрещает join до подтверждения персонажа. «Создать игру» открывает выбор режима; «Подключиться» — IP и порт. На другом сервере нужно войти заново. Сохранённая игра продолжается кнопкой «Продолжить игру» в кабинете или на указателе, без повторного ввода адреса и сброса прогресса/инвентаря. После загрузки мир открывается автоматически, чанки поднимаются снизу; при отказе браузера захватить мышь доступно «Вернуть управление».

**Демонстрационный вход по имени** — явно отдельный guest-маршрут без пароля, не регистрация. Он не позволяет войти в защищённый парольный аккаунт или присвоить занятое гостевое имя через регистрацию. **Выйти** / **Выйти из сессии** очищают токен клиента и запрашивают серверный отзыв. Ошибка подтверждения отзыва показана отдельно. Токен остаётся только в памяти, между перезагрузками не сохраняется. Браузер запоминает только проверенный публичный адрес сервера.

В мире доступны нижняя панель, **I — Инвентарь**, карта, словарь и чат. Окна используют native dialog; закрытие не захватывает мышь автоматически. Сумка/кувшин занимают 1 подтверждённый сервером слот рук. Содержимое — проекция BABEL counts, не новая система transfer. Словарь хранит learned, заметку и примеры; карта раскрывает только участников текущего задания. Смена облика — **Настройки → Изменить облик персонажа**.

Обновлённые клиент и сервер необходимо развёртывать вместе: старые строгие v3-клиенты не понимают новое поле equipment, старые BABEL v2 — новые поля состояния.

Режимы входа определяются через `/api/auth/mode`: development дополнительно разрешает guest/dev. После reload токен не восстанавливается, а новый вход создаёт новую AUTH-сессию.

## Проверки

```sh
make client-test
npm --prefix client run check
npm --prefix client run check:imports
PLAYWRIGHT_CHANNEL=chrome npm --prefix client run test:browser
PLAYWRIGHT_CHANNEL=chrome npm --prefix client run test:render
```

В изолированных worktree можно задать отдельные порты `PLAYWRIGHT_PORT` и `PLAYWRIGHT_RENDER_PORT` (по умолчанию 4173/5174); тесты не используют чужой dev-сервер. `PLAYWRIGHT_EXECUTABLE_PATH=/usr/bin/chromium` выбирает заранее установленный Chromium вместо browser channel. Проверки исходящих запросов по-прежнему разрешают только точный тестовый origin.

`make client-test` запускает Vitest без watch. `check` проверяет Svelte/TypeScript strict и `check:core` — Core, session и GameLoop без DOM/Node. `check:imports` проверяет циклы и границы модулей. Браузерный прогон пересобирает production и запускает HTTP на `127.0.0.1:4173`; отдельный render-стенд использует порт 5174 и не входит в production. Артефакты — `client/test-results/` и `client/render-test-results/`.

Вместо установленного Chrome можно заранее выполнить `cd client` → `npx playwright install chromium`, затем `npm run test:browser` / `npm run test:render`. Историческая аппаратная приёмка ниже: macOS 26.3 arm64, Node 25.6.0, npm 11.8.0, Chrome 156.0.8078.79, Playwright 1.64.1. Она не подтверждает новую UI/AVATAR поставку.

Для UI/AVATAR в этой ветке: `npm --prefix client run build`, затем `cd client && npx playwright test --config playwright.ui.config.ts`. Suite сам запускает настоящий сервер на свободном localhost-порту с отдельной временной SQLite БД. Это не LAN/LLM/аппаратная приёмка. Linux/Node 24/Chromium SwiftShader даёт долгие GPU stalls; диагностика и фактические результаты — [TASK-047](tasks/047-render-backpressure.md) и `tasks/evidence/ui-redesign-2026-07-02/`. Визуальное сравнение, а не наличие файлов, определяет принятие макетов.

`client/scripts/generate-avatar-models.mjs` воспроизводит оригинальные локальные GLB и автоматически входит в world:generate/prebuild/pretest. Опциональный `node client/scripts/generate-avatar-models.mjs --portraits` создаёт портреты через установленный локальный Chromium. Описание источника, общей rig/клипов и визуальные ограничения — `tasks/evidence/avatar-models-2026-07-02/README.md`. Клиентские TASK-073–077 и TASK-045–048 остаются in-progress, пока не закрыты обязательные сценарии/визуальные и аппаратные вопросы.

V4 geometry имеет независимое разрешение точных байтов и новый strict golden с сохранением старого. Canonical CPU после публикации: **client289/289, server160/160**, Svelte0 errors/0 warnings, TS/core/import/shared/build/world exit0. ## Конфигурация

`client/public/config.json` копируется в dist и читается с no-store. Настройки готовой сборки можно менять без пересборки. В нём нет секретов/токенов.

| Поле | По умолчанию | Поведение |
|---|---|---|
| session | local | Локальная прогулка; online требует серверной сессии |

## Локальные NPC и LLM

Python-зависимости локального ИИ готовятся через **uv**: `uv python install 3.12`, затем `make llm-prepare BACKEND=mlx` (Apple Silicon) или `BACKEND=ollama`. Команда устанавливает пакеты по отдельному lock, но не скачивает веса и не включает ИИ автоматически. Полный маршрут с инструментами, моделями и конфигурацией — [скилл install-local-ai](.agents/skills/install-local-ai/SKILL.md). Node 24 остаётся под nvm/существующим менеджером, JS-зависимости — npm.

**Установка на своём компьютере с нуля:** [server/llm/SETUP.md](server/llm/SETUP.md). [Справочник runtime](server/llm/README.md), [подготовленные профили](server/llm/PROFILES.md), [timeout в секундах](server/llm/TIMEOUT.md). На уже подготовленной машине не нужно повторять скачивание моделей, установку Python или импорт профилей.

В `NpcResponder` зарегистрированы `scripted`, `ollama`, `mlx`. Реальные варианты: **Ollama Qwen3.5-2B Q4_K_M**, явный кандидат **0.8B Q8_0**, либо **MLX text-only Qwen3.5-2B 4-bit/group64** на Apple Silicon. Native supervisor работает для macOS/Linux POSIX; Windows-версия не реализована. Автоматического выбора, скачивания или fallback нет. `language.adapter: local` подключает BABEL к тому же responder/worker; `test` остаётся явной заглушкой по умолчанию. Один лишь выбор `npc.adapter: ollama` не меняет BABEL.

```sh
make server NPC_TIMEOUT=60                         # текущая подготовленная модель, development
make server BACKEND=ollama MODEL=2b NPC_TIMEOUT=120 # при наличии prepared-профиля
```

`NPC_TIMEOUT` — целые **1–300 секунд на весь вопрос, включая очередь**, только на текущий запуск. Без override применяется `npc.timeoutMs` из config (default30000мс). Клиент получает эффективный срок от сервера и ждёт плюс2с; остальные pending10с. Клиент и сервер необходимо один раз обновить/собрать вместе: игровой протокол теперь **v3**, старая вкладка v1/v2 несовместима. После сборки смена timeout не требует пересборки.

**Окружения:** `make server` сохраняет development-вход по имени. `make start` / `make demo` запускают production, где имя без пароля не принимается. Парольные формы и серверный logout подключены; объём проверок и оставшаяся работа — [TASK-044](tasks/044-client-auth-observability-handoff.md). Для разработки и локальной проверки LLM используйте `make server` с loopback; работа формы не означает аппаратной квалификации модели или всей production-поставки.

Текущий runtime: одна модель, concurrency строго1, общая `GenerationQueue` для NPC/BABEL с ≤4 unfinished и ≤1/player; контекст2048, вход≤1792, выход≤128токенов, thinking выключен. Русский prompt просит1–2предложения/до20слов как мягкую цель, не жёсткую обрезку. SQLite хранит последние50пар на игрока/NPC, в prompt идут не более6; финал сохраняется до доставки, timeout/отмена не создают историю. Слот остаётся занят до подтверждённого cleanup.

Целевой общий пик RAM≤4 000 000 000байт; sampled RSS watchdog с soft threshold3 500 000 000байт **не является гарантированным hard cap**. Скорость p95 полного стандартного ответа≤8с и burst-критерии четверых остаются целями квалификации, не достигнутыми результатами. Длинный timeout их не заменяет.

Серверный opt-in `npc-partial`/`npc-cancel` уже есть (PROTO-007), scripted умеет выдавать partial. Текущий клиент не включает stream ([TASK-041](tasks/041-client-npc-stream.md)); реальные LLM workers возвращают финал и только внутренние числовые стадии, не stream текста игроку. FTS5 grounding, утверждённый корпус, расширенные настройки/ledger и компактная память остаются планом AI, не описанием работающей модели. Первый срез [TASK-070](tasks/070-npc-session-foundation.md) изолирует ограниченную историю по AUTH sessionId/playerId/npcId, включая BABEL snapshot/replay. Пока сохранены прежние суммарные окна 50/6, не полный архив; новая сессия не получает прежние NPC-тексты.

**Согласованная цель, реализована лишь частично:** [NPC-AI — характер, знания, отношения и сессионная память](specs/npc-character-behavior.md), [руководство автору/агенту](docs/npc-authoring.md). NPC отвечает на en/es A2, обычно 2–4 коротких предложения без эмодзи, допускает бытовую беседу в рамках авторского Вавилона. Память изолирована по AUTH sessionId/игроку/NPC; новый вход начинает знакомство заново, меню/reconnect с той же сессией — нет. Отношение влияет только на речь, извинение снимает недовольство. Приветствие генерируется, а технический сбой допускает локальную игровую фразу без ложного успешного ответа/запоминания. Цель — по 800 кодовых точек Unicode для вопроса/ответа; кандидат 4096/256 токенов требует квалификации; текущие лимиты выше не изменились. Состояние проектирования и проверки документов — [TASK-069](tasks/069-npc-behavior-specs.md).

На пользовательском Intel Mac подготовлены и запускались2B/0.8B; сохранённый2B и timeout120с подтверждены логом. Были isolated-ответы и технический отказ измерения памяти; сообщение пользователя «локально заработало» без текста/timing не квалифицирует качество, p95/RAM, offline/OS-изоляцию или стабильную игру. Здесь реальные модели/веса не запускались. Факты и ограничения — [TASK-067](tasks/067-configurable-game-llm.md), синхронизация с main — [TASK-068](tasks/068-llm-docs-main-sync.md).

Проверки и оставшаяся LAN-приёмка — [TASK-029](tasks/029-character-presentation.md).

[MOVE — движение, прыжки и выносливость](specs/character-movement.md) — проект следующего улучшения: скольжение вдоль стен без отхода назад, Space для прыжка, Shift для спринта, круговой индикатор выносливости и анимации этих действий. Реализуются общая кинематика и согласованный игровой v3; прыжок — физический Space, спринт — удержание любого Shift. Старые игровые клиенты v1/v2 несовместимы: клиент и сервер обновляются вместе. Полная приёмка MOVE ещё не завершена; состояние и ограничения — в задачах. Работы разделены на [shared/сервер](tasks/038-character-movement-server.md) и [клиент с общей приёмкой](tasks/039-character-movement-client.md).

Клиентские TASK-001, 003–005, 019–020 выполнены в их границах. TASK-006–009 сохраняют результаты предыдущей приёмки, но после rebase остаются in-progress: поддержка потокового NPC в клиенте не реализована. PROTO-007 теперь — совместимый подконтракт v3 (`stream: true`, `npc-partial`, `npc-cancel`), сервер его реализует; повторная приёмка — за клиентской командой. TASK-002 сохраняет незавершённую физическую проверку CLIENT S4. Ручная офлайн-приёмка на устройствах (TASK-016) и системная автономная демонстрация не выполнены. Поэтому CLIENT/NET/PROTO и архитектура остаются partial там, где требуется реальная интеграция; RENDER/MAP и прежний объём UI/QUALITY имеют собственную подтверждённую приёмку.

`make help` показывает команды; CLIENT_RUN_CMD/CLIENT_TEST_CMD можно переопределить, пустые значения и ошибки не скрываются. Серверные решения по runtime, входу и сохранениям — в серверных спеках; локальный ИИ — в AI/LLM.

При обновлении старой dev-БД сервер сверяет не только номера миграций, но и поля профиля/персонажа. Отсутствующие поля добавляются без сброса данных. Перед ручными операциями с БД сохраните согласованную резервную копию (команда `npm --prefix server run backup -- /absolute/path/backup.sqlite`); удаление game.sqlite для исправления входа не требуется.
