# SHARED — Общие контракты клиента и сервера

## Цель

Одна исполняемая копия всего, что клиент и сервер обязаны понимать одинаково: типы и runtime-валидация PROTO v3, формы сущностей, формат manifest/чанков и правило проходимости. Клиент и сервер импортируют один общий контракт; клиентские команды и адаптеры в него не входят.

## Требования

- **SHARED-001:** Каталог `shared/` в корне репозитория. Состав:
  - `shared/protocol/` — `types.ts`, `validate.ts`, `fixtures.json` (PROTO v3);
  - `shared/babylon/` — типы и runtime-парсеры отдельного HTTP-дополнения BABEL (PROTO-009);
  - `shared/world/` — `Entity`, компоненты, `WorldSnapshot`, `Vector3`, `Direction`, `EntityId`;
  - `shared/map/` — типы manifest/чанка/bootstrap, парсер manifest и чанка, правило проходимости.

  - `shared/movement/` — чистая общая кинематика MOVE, профиль, контакт, опора, прыжок и выносливость.

  Игровые правила сервера, Socket.IO, HTTP, SQLite, рендер и UI сюда не входят.
- **SHARED-002:** Код — TypeScript strict для ES2022 без npm-зависимостей, без DOM- и Node-типов и глобалов (`window`, `process`, `Buffer` и т. п.). Импорты только внутри `shared/`, относительные, с явным расширением `.ts`. Только стираемый синтаксис: без `enum`, `namespace` и parameter properties. Так сервер запускается встроенным удалением типов Node, а клиент собирается Vite. Импорты ацикличны. Отдельный `shared/tsconfig.json` проверяет это профилем `lib: ["ES2022"]`, `types: []`, `erasableSyntaxOnly`.
- **SHARED-003:** Исходная версия переносится из клиентской ветки `feat-base-client` без изменения wire-поведения: `client/src/shared/protocol/*`, типы данных из `client/src/core/types.ts` (без `GameCommand`/`WorldEvent` клиента), `parseManifest` и разбор чанка из `client/src/map/HttpMapSource.ts`, формула коллизий из `client/src/map/ChunkManager.ts`. Поля, лимиты (`LIMITS`), коды и тексты ошибок совпадают. Допустимы только изменения, нужные SHARED-002 (например, `ProtocolError` без parameter property). Любое изменение wire-контракта — это изменение [PROTO](protocol.md) и версии протокола.
- **SHARED-004:** `fixtures.json` — общий набор валидных и невалидных пакетов для обеих сторон: `{direction: client|server, valid, packet, code?}`. Каждый fixture проверяется тестом. Серверные уточнения PROTO v1 (сообщение `error` с `requestId: "server"`, чат другого игрока с requestId отправителя, delta без изменений не отправляется) получают fixtures.
- **SHARED-005:** Функция проходимости по manifest, collision-bitmap чанка и позиции XZ возвращает «проходимо/нет» по тем же правилам, что movement guard клиента:
  - весь квадратный след ±0.25 м по X/Z, включая клетки между четырьмя углами;
  - индекс чанка `floor((p − origin) / chunkSize)`;
  - ячейка `floor((p − origin − index·chunkSize) / chunkSize · collisionResolution)`;
  - ненулевой байт — препятствие; отсутствующий в manifest или незагруженный чанк — непроходимо.

  Сервер и клиент используют общий swept-путь: пересечение отрезка центра с расширенными клетками bitmap, а не только конечную точку. Скольжение сохраняет допустимую составляющую и не увеличивает длину шага.
- **SHARED-006:** Пока клиент содержит собственную копию контракта, тест сервера прогоняет клиентский `client/src/shared/protocol/fixtures.json` (если файл есть в рабочем дереве) через shared-парсеры и требует совпадения valid/invalid и кода ошибки. Отсутствие файла фиксируется в результате как непроверенная совместимость, а не как успех. После перехода клиента на `shared/` клиентская копия удаляется. Переход выполняет клиентская задача; серверные задачи `client/` не меняют.

- **SHARED-007:** Manifest v1 допускает дополнительный `heightSurfaces`: до 128 непересекающихся прямоугольников `{minX,maxX,minZ,maxZ,startY,endY}`; конечные координаты в пределах ±100000, положительные размеры, модуль уклона по Z ≤1. Общий `surfaceHeight` линейно интерполирует Y между minZ/maxZ, вне поверхности возвращает землю. Отсутствие поля сохраняет прежнюю плоскую карту. Авторитетный сервер и локальная сессия используют эту формулу как опору; подъём обычного шага >0,35 м запрещён, доступный перепад вниз начинает падение по MOVE. Воздушный Y вычисляется отдельно; онлайн-клиент получает его из снимка.

## Сценарии

- **S1 · SHARED-001–002:** Given `shared/`; When выполняется `tsc -p shared` в профиле без DOM/Node и проверка импортов/синтаксиса; Then нарушений нет, Node 24 импортирует модули без сборки.
- **S2 · SHARED-003–004, 006:** Given fixtures клиента и shared; When они разбираются обеими реализациями; Then результаты (valid/invalid, код ошибки) совпадают, включая новые серверные fixtures.
- **S3 · SHARED-005:** Given demo-manifest и его коллизии; When проверяются точки у стены, в проходе, на границе чанков и за краем карты; Then результат совпадает с клиентским guard на тех же данных.

## Ограничения и вне scope

- Workspaces и монорепозиторный инструментарий не создаются; клиент и сервер импортируют исходники относительным путём.
- Типы `shared/` не заменяют runtime-валидацию: входящие данные всегда проходят через парсеры.

## Граница клиентского импорта

Vite разрешает импорт корневого `shared/`, TypeScript — `allowImportingTsExtensions`. Проверка зависимостей разрешает Core/session импорт чистого shared, но запрещает зависимости shared от Node/DOM, адаптеров и сторонних библиотек. Общий профиль использует ESNext/Bundler; shared/package.json содержит ESM-маркер, без зависимостей и scripts. Исходники импортируются напрямую.


## Открытые вопросы

- Прежний полный запрет npm-пакета расходится с `shared/package.json`, добавленным в A для ESM. Нужен ли этот маркер при ESNext/Bundler — отдельное решение; интеграция сохраняет его. Публикация пакета, зависимость по npm и workspaces не используются.

## Расширение MOVE

SHARED-007 сохраняет формулу опоры, но Y стоп и verticalVelocity в воздухе независимы от неё. Наземный подъём ≤0,35 м; доступный обрыв начинает падение. Общая кинематика вызывается существующими циклами с dt, без таймеров/IO.

Manifest v1 допускает `ceilingVolumes`: до 128 записей `{minX,maxX,minZ,maxZ,bottomY,topY}`, конечные координаты ±100000, min<max и bottomY<topY. Коллайдер игрока: ±0,25 м по XZ, 1,8 м вверх от стоп. Объём запрещает движение тела через боковую грань и подъём головы через нижнюю грань. Его верх не открывает новые ярусы. Bitmap блокирует при любой Y; heightSurfaces остаётся единственной опорой. Данные входят в manifest и его существующий бюджет; меши не участвуют в серверной физике.

Согласованное уточнение размещения: корневые ceilingVolumes сохраняют лимит 128; каждая запись manifest.chunks дополнительно допускает свои ceilingVolumes (≤128) в мировых координатах. Объёмы записи ограничены её клеткой, пересекающие границу объёмы генератор разделяет между владельцами. Выборка для шага использует существующий индекс соседних чанков; полный массив всех перекрытий не сканируется на каждом шаге. Это данные manifest, без дополнительной runtime-загрузки; их байты входят в manifestBytes/worldBytes и общий бюджет.

## SHARED-008 — Каталог и живой мир

Исполняемый модуль `shared/world-life/` содержит типы, строгие runtime-парсеры и общие fixtures нового подконтракта PROTO-010. Optional `WorldManifest.worldLife` хранит `WorldLifeDefinition` v1: mapId, seed, templates, instances, cats, flock, wind. При отсутствии поля прежние карты работают без новой сцены.

Заготовка `{id,assetId,behavior,animation}` ссылается на общий manifest.models; behavior — static/animated/pushable/pickup. Экземпляр `{id,templateId,position,rotationY,zone?}` не копирует модель/правила; zone `{minX,maxX,minZ,maxZ}` обязательна только для pushable. Яблок ровно 5 (pickup), горшков 4 (pushable), кошек 3 (animated, отдельные sleep/walk/wash). Прочий декор остаётся неподвижным и не становится товаром/заданием. Все ID уникальны в своём наборе; ссылки должны существовать; модели присутствуют в manifest.models.

Кошка `{instanceId,behavior,route,cycleMs,pauseMs}`: маршрут замкнут, ≤16 опорных точек; sleep/wash используют 1 точку, walk ≥2. Сервер проверяет маршруты по доступной опоре и bitmap. Flock `{assetId,count,route,schedule}`: 4–6 птиц, 90–150 с период, 8–12 с пролёт; маршрут ≤16 точек, высота 10–16 м и минимум 3 м над препятствиями. Ветер `{strength,gustStrength,schedule}`: только визуальный; период 45–90 с, порыв 2–4 с, сила 0–1. Schedule `{periodMs,durationMs,offsetMs}`, offset в пределах периода. Фазы общего времени — чистые функции shared без таймеров/IO. Координаты конечные в ±100000, массивы и размер пакета ограничены.

Продакшн-данные существующей карты экспортирует `shared/world-life/market.ts` как `MARKET_WORLD_LIFE`: 42 независимые заготовки, 12 новых экземпляров (4 горшка, 5 яблок, 3 кошки), мировые маршруты и расписания. Генератор карты подключает этот чистый объект как manifest.worldLife и учитывает его байты в bootstrap. Чанки не запекают подвижные экземпляры в статические меши/bitmap. Экспортированные чистые функции `schedulePhase`, `routePosition`, `catPosition` используют только переданное время сцены.
