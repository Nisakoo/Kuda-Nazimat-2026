# CORE — Core, сессия и игровой цикл

## Цель

Обеспечить тестируемую локальную симуляцию без браузера и внешних технологий.

## Требования

- **CORE-001:** Core написан на TypeScript strict и не импортирует DOM, Canvas, Three.js, Svelte, Socket.IO, HTTP, файловую систему или БД. Межмодульных циклических импортов нет.
- **CORE-002:** EntityManager хранит сущности по уникальному EntityId. Компоненты Transform, Movement, Renderable, Interactable, Character и AnimationState содержат сериализуемые данные, без объектов движка. Полноценный ECS-фреймворк не используется.
- **CORE-003:** Команды и системы выполняют движение и взаимодействия, генерируют события и применяют обновления. Повторное создание ID и обращение к удалённой сущности обрабатываются предсказуемо, без повреждения состояния.
- **CORE-004:** GameSession предоставляет одинаковый интерфейс команд, чтения состояния, подписок и завершения для LocalSession и OnlineSession. LocalSession работает без игрового сервера; NPC и имитация игроков доступны как локальные данные.
- **CORE-005:** GameApp владеет единственным GameLoop: фиксированный шаг симуляции, отдельный render и коэффициент интерполяции. Большой deltaTime и количество догоняющих шагов ограничены; после возврата во вкладку нет скачка симуляции.
- **CORE-006:** Цикл последовательно принимает ввод, формирует команды, обновляет сессию и применяет сетевые данные, планирует чанки, синхронизирует визуальные объекты и рисует. Асинхронные загрузки не ожидаются внутри кадра. Start/stop/dispose не дублируют цикл или подписки.
- **CORE-007:** В онлайн-режиме Core хранит клиентское представление, а не авторитетные игровые значения; обновления приходят через сессию. Prediction/reconciliation оставлены возможными, но не обязательны для MVP.

## Сценарии

- **S1:** CORE-001–003: Given headless-тест; When создаются, двигаются и удаляются сущности; Then состояние и события корректны, окружение браузера не требуется.
- **S2:** CORE-004: Given LocalSession; When выполняются движение и взаимодействие; Then они работают без сетевого адаптера.
- **S3:** CORE-005–006: Given управляемые часы; When меняется частота кадров, происходит долгая пауза и повторный start/stop; Then число шагов ограничено, один цикл активен, после stop обновлений нет.
- **S4:** CORE-007: Given Core и тестовый источник авторитетных обновлений; When применяется обновление; Then клиентское представление принимает его. Реальная OnlineSession проверяется в NET, а не требуется для завершения этапа Core.

## Ограничения и вне scope

Не строить универсальный ECS, физический движок или DI-контейнер.
