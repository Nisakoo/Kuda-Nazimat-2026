# SERVER-WORLD — Мир, чанки и доступ к данным

## Цель

Сервер хранит подготовленный статический мир в формате [MAP](client-world-streaming.md). Он выдаёт клиенту только нужные данные с проверкой сессии и области, а движение считает по тем же коллизиям, что видит клиент.

## Требования

- **SERVER-WORLD-001:** Мир — каталог `worldDir` с раскладкой MAP:
  - `maps/<…>/manifest.json`, чанки JSON и collision-bitmap по путям из manifest;
  - `assets/models/<…>` — GLB/glTF и их локальные зависимости.

  Реестр `maps` в конфигурации сопоставляет mapId с файлом manifest. mapId в manifest должен совпадать с ключом. Статические данные отделены от динамического состояния игроков и NPC. Демо-мир для разработки готовит клиентский `world:generate`; сервер его не генерирует.
- **SERVER-WORLD-002:** При запуске для каждой карты manifest разбирается shared-парсером, затем выполняются проверки. При ошибке сервер не запускается и называет карту и файл.
  - Каждый чанк, collision-файл и модель существуют внутри `worldDir`, их размер равен заявленному.
  - Collision-файл содержит ровно `collisionResolution²` байт.
  - JSON чанка разбирается, `id` совпадает, все `assetId` объявлены в чанке и в `models`.
  - `worldBytes` равен сумме размеров уникальных ресурсов: manifest, JSON чанков, уникальные collision-файлы и `assets`.
  - Bootstrap укладывается в лимиты PROTO v1 (`manifestBytes` и каждый ассет ≤ `worldBytes/10`, `memory` ≤ 32 MiB, ≤128 ассетов).
  - spawn проходим по SHARED-005.
- **SERVER-WORLD-003:** Bootstrap карты для `joined.world` — `{manifestUrl, worldBytes, manifestBytes, assets}`. `manifestUrl` — путь manifest относительно `/world/`, `assets` совпадает с `manifest.assets`. Bootstrap вычисляется один раз при старте. Manifest содержит данные для планирования и бюджета, но не геометрию. Клиент сверяет `worldBytes` и метаданные ассетов с bootstrap, поэтому данные другой версии карты он не примет.
- **SERVER-WORLD-004:** Правило 10% и метод расчёта общего объёма совпадают с MAP: учитываются уникальные сериализованные байты, общий ресурс считается один раз. Сервер не заменяет эту проверку числом чанков: он только публикует воспроизводимые размеры и не отдаёт весь мир.
- **SERVER-WORLD-005:** `GET /world/<path>`:
  1. путь декодируется один раз, допускаются только символы `[A-Za-z0-9_./-]`; `..`, `\`, NUL, начальный `/` и повторное кодирование отклоняются;
  2. путь должен входить в построенный при старте allowlist файлов мира — файловая система по пользовательскому пути не читается;
  3. ответ: точный `Content-Length`, `Content-Type` по расширению, `Cache-Control: no-store`, без redirect.

  Неизвестный путь — 404. Ошибка чтения — 500 без пути на диске. Сервер продолжает работу.
- **SERVER-WORLD-006:** Доступ к `/world/*` требует действующей сессии (иначе 401, AUTH-003) и активного игрока этого аккаунта на карте файла (иначе 404).
  - **Manifest, модели и их зависимости** доступны активному игроку своей карты.
  - **Чанк** доступен, если его клетка в пределах `staticChunkRadius` (по умолчанию 3, по Чебышёву) от клетки авторитетной позиции игрока. Это клиентский радиус 2 плюс запас на переход. Иначе — 404.
  - **Collision-файл** доступен, если на него ссылается хотя бы один доступный чанк.

  403 не используется для области: клиент v1 воспринимает 401/403 как потерю сессии (PROTO-008). Позицию и карту игрока модуль world получает через порт от game, без зависимости от realtime.
- **SERVER-WORLD-007:** Модуль world предоставляет game коллизии карты. Collision-bitmap загружаются в память при старте, одинаковые файлы — один раз. Проходимость точки — функция SHARED-005, где «чанк загружен» означает «чанк есть в manifest». Ограничение по preparedChunks клиента применяет game (REALTIME-003).
- **SERVER-WORLD-008:** Серверный контент NPC — `contentDir/npcs.json`: массив `{id, mapId, name, topic, persona, greeting, position {x,y,z}, rotationY, interactionRadius, assetId}`. При запуске проверяются уникальные ID по PROTO, существующий mapId, проходимость позиции, радиус 0–20, имя и тема ≤80, persona и greeting 1–500 символов. `interactable.label` сущности равен теме: клиент показывает его в заголовке онлайн-диалога. Демо-контент повторяет NPC клиентского демо (SERVER-DEMO-005):
  - `history-guide` «Лея», тема «История», позиция (−4, 0, 0);
  - `science-guide` «Марк», тема «Наука», позиция (4, 0, 0);
  - радиус 2.2, `assetId` равен id.

## Сценарии

- **S1 · SERVER-WORLD-001–003:** Given демо-мир из `client/public`; When сервер запущен; Then bootstrap demo совпадает с `DEMO_WORLD`, сгенерированным клиентом (manifestUrl, worldBytes, manifestBytes, assets). Given изменённый на 1 байт чанк; Then запуск отклонён с указанием файла.
- **S2 · SERVER-WORLD-004:** Given manifest и ресурсы; When сумма уникальных размеров считается независимо в тесте; Then она равна `worldBytes`, а повторно используемые collision-файлы учтены один раз.
- **S3 · SERVER-WORLD-005:** Given запросы `/world/../server/config.json`, `/world/maps%2F..%2F..`, `/world/maps/demo/unknown.json`, `/world/maps/demo/manifest.json/`; When они отправлены с действующим токеном; Then все получают 404, сервер продолжает отвечать.
- **S4 · SERVER-WORLD-006:** Given игрок в клетке (0,0); When запрошены чанк (2,−3), чанк (4,0), их collision-файлы и модель; Then чанк (2,−3), его collision-файл и модель отдаются, чанк (4,0) — 404. Без токена любой из них — 401. После перехода игрока к клетке (2,0) чанк (4,0) становится доступен.
- **S5 · SERVER-WORLD-007–008:** Given demo-карта; When проверяются spawn, позиция NPC и точка внутри стены courtyard; Then первые две проходимы, третья нет, результат совпадает с клиентским guard. NPC с непроходимой позицией или дублирующимся ID не позволяет запустить сервер.

## Ограничения и вне scope

- Сервер не гарантирует поведение изменённого клиента; лимит кеша подтверждается штатным клиентом и измерениями (DEMO-004).
- Высоты, лестницы и вертикальная физика вне MVP: `y` позиции не меняется.
- Генерация и редактор мира вне scope сервера.

## Открытые вопросы

- Подготовка мира для поставки и исключение `maps/` из клиентской сборки — см. SERVER, открытые вопросы.
- Отдельная карта `science` клиентского демо (`maps/demo/science.json`, spawn z=38) подключается записью в `maps`, если клиент её использует онлайн.
