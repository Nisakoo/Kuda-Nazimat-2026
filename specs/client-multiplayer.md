# NET — OnlineSession и Socket.IO

## Цель

Подготовить клиент к серверу `server/` и проверить сетевые сценарии без него.

## Требования

- **NET-001:** NetworkAdapter предоставляет connect, disconnect, send, subscribe, статус и ошибки. Socket.IO Client импортируется только внутри SocketIOAdapter; транспорт подключается явно, без автоматического соединения при создании.
- **NET-002:** OnlineSession реализует GameSession, отправляет команды и применяет авторитетные обновления согласно [PROTO](protocol.md). Буферизует и интерполирует удалённые объекты; не смешивает визуальное состояние со снимком сессии.
- **NET-003:** Статусы включают неавторизован, подключается, подключён, связь потеряна и ошибка. Реальный игровой канал открывается только с предоставленной серверной сессией; в online без сессии показывается форма mock-входа по NET-007. Пароли и регистрация вне MVP.
- **NET-004:** Автопереподключение имеет ограниченную частоту, отменяется при logout/dispose; отказ авторизации не вызывает бесконечный retry. После восстановления выполняется повторный вход и синхронизация. Для NPC в PROTO v1 вопрос без ответа до разрыва завершается ошибкой и автоматически не переотправляется. Буферы транспорта не сохраняют действия для повтора после разрыва; input допускает потерю пакета, join/chat/NPC отправляются только при действующем соединении и переживают переключение polling → WebSocket.
- **NET-005:** MockNetworkAdapter позволяет проверять снимки, события, задержки, ошибки, разрыв и переподключение без реального сервера. Тестовая авторизация существует только в mock и не отключает защиту реального адаптера.
- **NET-006:** Отсутствующий сервер не приводит к зависанию или падению. Адрес берётся из конфигурации, по умолчанию same-origin; при завершении закрываются соединения, таймеры, подписки и буферы.

- **NET-007:** На этапе интеграции с реальным сервером браузерный UI получает серверную сессию выбранным способом локального входа, передаёт её сетевому и HTTP-адаптерам и выполняет выход. Способ выбран в [AUTH](server-auth.md): mock-вход по имени, `POST <serverUrl>/api/auth/guest {name}` → `{token, expiresAt}`, ответ передаётся в `GameApp.provideServerSession()`; выход — забыть токен локально (AUTH-002). Ошибки/истечение сессии возвращают пользователя к входу и закрывают игровой обмен; ручная подстановка токена разработчиком не заменяет демонстрационный вход.

Вход по NET-007:
- Одно поле имени (1–32 символа после trim, без управляющих символов), кнопка входа и состояние ожидания. Текст поясняет, что имя сохраняет игрока, но не защищено паролем; обычные пользователи не вводят токены.
- POST идёт только на настроенный serverUrl, с JSON `{name}`. Ответ валидируется общим parseServerSession. Ошибка API отображается текстом; ошибка сети, неверный ответ и timeout 10 с оставляют форму доступной для повтора. До успешного ответа нет /game и /world.
- Одновременно выполняется один запрос входа. Смена настроек/сервера, выход, перезапуск и dispose отменяют его; поздний ответ старого запроса не создаёт сессию. Нет автоматического повторного POST.
- Токен хранится только в памяти GameApp/адаптеров, не в URL, конфигурации, localStorage или sessionStorage. Выход доступен до начала прогулки и в меню, закрывает соединение и освобождает мир. Reload снова требует входа.
- Истечение сессии, 401 мира и UNAUTHORIZED игрового канала закрывают старый обмен и возвращают форму. Причина сервера при перехвате управления показывается текстом. При сетевом разрыве действующая сессия остаётся доступной для ограниченного reconnect по NET-004.

## Сценарии

- **S1:** NET-001, 003, 005: Given нет серверной сессии; When запрошено реальное подключение; Then канал не открывается. Given mock; When предоставлен тестовый контекст; Then сценарии проверяются без сервера.
- **S2:** NET-002: Given снимки двух удалённых игроков; When приходят обновления; Then состояние обновляется по контракту, отображение интерполируется.
- **S3:** NET-004–006: Given недоступный сервер, разрыв или отказ авторизации; When соединение восстанавливается либо приложение завершается; Then статус понятен, retry контролируется, после dispose нет подписок и попыток соединения. Для NPC в v1 ожидающий вопрос получает ошибку без повтора; пропавшие действия не воспроизводятся автоматически.

- **S4:** NET-003–004, 007: Given реальный сервер и браузер; When пользователь входит, открывает мир, выходит и пытается использовать старую сессию; Then вход даёт доступ к каналу и данным мира, logout закрывает обмен и удаляет локальный токен; серверный токен остаётся действующим до expiresAt по AUTH-002. После истечения сервер отклоняет его, UI предлагает вход заново.

- **S5 · NET-007:** Given online без сессии; When отправлено пустое/невалидное имя, API вернул ошибку или ответ не пришёл за 10 с; Then видна понятная ошибка, повтор возможен, игровой обмен не открыт. При двойном submit выполняется один POST.
- **S6 · NET-006–007:** Given запрос входа выполняется; When изменён сервер/режим или приложение завершено; Then запрос отменён, поздний ответ не подключает старый сервер.
- **S7 · NET-004, 007:** Given действующая сессия; When приходит 401 мира, expiresAt или UNAUTHORIZED с причиной перехвата; Then закрыты канал и мир, показаны форма и причина, автоматического guest-входа нет.

## Ограничения и вне scope

Prediction/reconciliation — будущая возможность, не обязательная реализация. Настоящий сервер внутри клиента не создаётся. NET-001–006 входят в клиентский MVP, NET-007 реализуется клиентом после готовности AUTH; полный игровой S4 выполняется с готовым набором A в TASK-026/016. Операторские inspect/backup остаются CLI сервера и не выдаются браузеру.

## Открытые вопросы

Handshake и ограничения определены в PROTO v1, способ входа — mock по имени ([AUTH](server-auth.md)). Серверная реализация — TASK-010–014, интеграция — TASK-016; реальное end-to-end подключение не считается проверенным по mock.


- **NET-004, PROTO v2 (предложение, не критерий v1):** Временные partial-снимки не воспроизводятся: запрашивается result прежнего requestId без повторной generation по PROTO-007. Буферы Socket.IO не должны автоматически переотправлять новые вопросы/старые отмены или неограниченно копить сообщения во время offline; состояние диалога и retry контролирует сессия.
- **Local/mock из серверной поставки:** SERVER-003 закрывает публичные maps/models, тогда как LocalSession ожидает их без Bearer. Полноценная локальная прогулка остаётся отдельным Vite/preview-демо. Нужно отдельно определить, скрывать ли эти режимы в серверной поставке; запрещённый публичный fallback не добавлен.
- **Снятый конфликт NET-003/S4:** прежние формулировки исключали UI входа и требовали отзыва токена при logout. Для согласованной интеграции действует NET-007: форма guest-входа и забывание токена только в браузере; отзыв на сервере отложен вместе с настоящей авторизацией.
