# CONTENT — Каталог NPC, изменяемый на лету

## Цель

Сделать NPC управляемыми без перезапуска сервера: администратор меняет поведение (персону, тему, приветствие, радиус разговора), перемещает, выключает и удаляет NPC, а следующий вопрос игрока уже обрабатывается с новыми данными — и заглушкой, и будущей LLM. Каждое изменение записывается: кто, когда и что поменял.

Сейчас NPC — статический `server/content/npcs.json`, проверяемый при старте (SERVER-WORLD-008). Тексты и координаты NPC рынка дополнительно продублированы в `server/src/babylon/content.ts` и уже расходятся с `npcs.json` (например, тема торговца фруктами «Финики и фрукты» и «Фрукты и финики»). Модуль `content` становится единственным источником данных NPC.

## Требования

### Хранение и источник

- **CONTENT-001 (каталог):** NPC хранятся в SQLite: id, mapId, name, topic, persona, greeting, позиция `{x, y, z}`, rotationY, interactionRadius, assetId (может отсутствовать), `figure` (`entity` — рисуется клиентом по данным сервера, `map` — нарисован в модели карты), состояние (`active`, `disabled`, `deleted`), `revision` (растёт с каждым изменением), время и автор последнего изменения. Таблица добавляется миграцией без удаления данных (STORE-002).
- **CONTENT-002 (начальные данные):** `contentDir/npcs.json` становится начальными данными. При старте NPC, чьих id ещё нет в БД, добавляются с `revision: 1` и автором `seed`; уже существующие записи файлом **не перезаписываются**, а записи, которых в файле нет, остаются. Проверки файла — как SERVER-WORLD-008. `figure` берётся из файла; если не указан — `map` без assetId и `entity` с assetId. Сейчас это даёт: торговец фруктами, торговка тканями, гончар и пастух рынка — `map`; Лея и Марк площади demo — `entity`.
- **CONTENT-003 (один источник):** игровой мир (сущности NPC, AOI, проверка взаимодействия), NPC-диалог (профиль `NpcProfile` для `NpcResponder`) и BABEL (профиль для `LanguagePort.answer`, позиция и радиус для проверки «подойдите ближе», существование цели покупки и вопроса) читают текущие данные NPC из модуля `content`. В `babylon/content.ts` остаются только данные задания: товары, козы, подсказка пастуха. Тексты NPC рынка берутся из `npcs.json`; ответы тестового `LanguagePort` от персоны не зависят, поэтому поведение задания не меняется.

### Изменения на лету

- **CONTENT-004 (применение):** изменение сначала фиксируется в одной транзакции SQLite вместе с записью журнала (CONTENT-010), затем атомарно заменяет данные NPC в памяти сервера. Без перезапуска:
  - сущность NPC в AOI обновляется следующей рассылкой: позиция и поворот — `transform`, тема — `interactable.label`, радиус — `interactable.radius`; выключенный или удалённый NPC уходит из AOI через `remove`. Используется существующий контракт delta (PROTO-004/008), новых пакетов нет;
  - `interact` и `npc-question` к выключенному или удалённому NPC отвечают `error FORBIDDEN` «Собеседник недоступен»; дистанция проверяется по текущей позиции и радиусу;
  - вопрос, принятый в очередь генераций, завершается с профилем, снятым **в момент приёма**; каждый следующий вопрос — с новым профилем. Это одинаково для заглушки `scripted`, будущей LLM за `NpcResponder` и BABEL за `LanguagePort`;
  - история диалогов игроков с NPC сохраняется при любом изменении.
- **CONTENT-005 (поведение):** изменяемые поля — `persona` (1–500 символов), `topic` (1–80, игрок видит её как подпись взаимодействия), `greeting` (1–500), `interactionRadius` (0,5–10 м, шаг не ограничен). Тексты обрезаются по краям, управляющие символы отклоняются, вывод у игрока — только как текст. Можно менять одно или несколько полей за раз. `id`, `name`, `mapId`, `assetId` и `figure` в этой версии не меняются. Поведение можно менять у всех NPC, включая нарисованных в модели карты и нужных заданию BABEL.
- **CONTENT-006 (перемещение):** новая точка `{x, z}` и, по желанию, `rotationY` — только на карте этого же NPC. Высота `y` вычисляется поверхностью карты. Точка принимается, если она проходима по общему правилу (SHARED-005: весь след, все чанки есть на карте, тело не задевает перекрытия — `GameMap.isSafeSupport`) и ни один другой активный NPC не ближе 1,2 м. Иначе — ошибка «Точка непроходима или вне карты» либо «Слишком близко к другому NPC», NPC остаётся на месте.
- **CONTENT-007 (выключение):** `active` ↔ `disabled`. Выключенный NPC не виден и не отвечает (CONTENT-004), но остаётся в каталоге и включается обратно без потери данных.
- **CONTENT-008 (удаление):** мягкое: состояние `deleted`, запись и журнал сохраняются, id больше не используется. Удалённый NPC не виден, не отвечает, не показывается в списке по умолчанию и в этой версии не восстанавливается. Повторное появление этого id в `npcs.json` его не возвращает (CONTENT-002).

### Ограничения

- **CONTENT-009 (запреты):** проверяются до любой записи; запрещённое действие ничего не меняет и даёт ошибку с понятным сообщением:
  - **фигура в модели карты:** перемещение, выключение и удаление NPC с `figure: map` запрещены — «Фигура нарисована в модели карты — нужна поддержка клиента». Запрет снимается **одним флагом** конфигурации `content.mapFiguresFromServer` (по умолчанию `false`), когда клиент начнёт рисовать этих NPC по данным сервера ([TASK-065](../tasks/065-client-market-npc-entities.md)); вместе с флагом сервер начинает отправлять для них `renderable` с моделью, согласованной в той же передаче;
  - **задание BABEL (пока):** выключение и удаление NPC, от которых зависит задание BABEL (`fruit-seller`, `fabric-seller`, `potter`, `shepherd` — список берётся из данных задания, а не задаётся вручную), запрещены — «От этого NPC зависит задание BABEL: выключение и удаление пока запрещены». Перемещение таких NPC подчиняется только первому запрету; после него задание проверяет дистанцию по новой позиции (CONTENT-003).
- **CONTENT-011 (одновременные правки):** каждое изменение передаёт ожидаемую `revision`. Если NPC уже изменили (другой администратор, другая вкладка), ответ — конфликт с текущими данными, изменение не применяется. Повтор того же изменения после успеха конфликтует по revision, а не применяется дважды.

### Журнал

- **CONTENT-010 (журнал изменений):** каждое изменение, включая начальную загрузку из файла, пишется в таблицу журнала: время, NPC, действие (`seed`, `update`, `move`, `disable`, `enable`, `delete`), автор (accountId и отображаемое имя администратора; `seed` для файла), новая revision, IP запроса и изменённые поля в виде `{поле: {было, стало}}`. Тексты персоны, темы и приветствия — данные администратора, а не игроков, и хранятся в журнале БД целиком. Хранится не больше 10 000 последних записей. Одновременно в лог сервера уходит событие `content.npc.changed` (info: npcId, действие, **имена** изменённых полей, revision, автор, ip) — без самих текстов, чтобы журнал сервера оставался компактным. Отклонённое действие — `content.npc.rejected` (info: npcId, действие, причина).

## Сценарии

- **S1 · CONTENT-002–003:** Given чистая БД; When сервер стартует; Then шесть NPC из `npcs.json` в каталоге с revision 1 и записью `seed`, четыре рыночных — `figure: map`. When администратор меняет персону Леи и сервер перезапускается; Then новая персона сохранилась, файл её не вернул.
- **S2 · CONTENT-004–005:** Given игрок рядом с Леей и заглушка с задержкой 1 с; When игрок задаёт вопрос, администратор меняет персону и тему, игрок задаёт второй вопрос; Then первый ответ — со старым профилем, второй — с новым, ответчик получил новую персону, подпись взаимодействия у игрока сменилась следующей delta, перезапуска не было.
- **S3 · CONTENT-006:** Given Лея на площади demo; When её переносят в стену, за край карты, на 0,5 м от Марка и в свободную точку; Then первые три отклонены с сообщениями и Лея на месте, четвёртое принято, игроки получают новую позицию, взаимодействие проверяется по ней.
- **S4 · CONTENT-007–008:** Given Марк и игрок рядом; When Марка выключают; Then он уходит из AOI, вопрос к нему — FORBIDDEN. When включают; Then он снова виден с прежними данными. When удаляют; Then он не виден, не возвращается после перезапуска, история игроков с ним сохранена.
- **S5 · CONTENT-009:** Given флаг `content.mapFiguresFromServer: false`; When пытаются переместить, выключить или удалить гончара; Then каждое действие отклонено с сообщением про модель карты, а смена его персоны и радиуса проходит. When пытаются выключить пастуха при включённом флаге; Then отказ про задание BABEL.
- **S6 · CONTENT-011:** Given два администратора открыли Лею с revision 3; When оба сохраняют разные персоны; Then применяется первое, второе получает конфликт с текущими данными (revision 4).
- **S7 · CONTENT-010:** Given серия изменений; When открыт журнал; Then для каждого изменения есть запись с автором, временем, IP и полями «было/стало», в логе сервера — `content.npc.changed` с именами полей без текстов.
- **S8 · CONTENT-003:** Given участник BABEL у торговца фруктами; When администратор увеличивает радиус торговца с 2,7 до 4 м и игрок отходит на 3,5 м; Then покупка проходит; When администратор меняет персону; Then следующий ответ NPC в BABEL получает новую персону через `LanguagePort`.

## Ограничения и вне scope

- Создание новых NPC, смена имени, карты, модели и `figure`, восстановление удалённых, маршруты и расписания движения (CAST-014) — следующие версии.
- Объекты мира кроме NPC и геометрия карты (модели чанков генерирует клиент) — вне модуля.
- Сам экран управления и доступ к нему — [ADMIN](server-admin.md).

## Передача клиенту

Изменения поведения, перемещение и выключение NPC с `figure: entity` работают с текущим клиентом через обычные delta. Для NPC рынка нужна передача [TASK-065](../tasks/065-client-market-npc-entities.md): клиент рисует их по данным сервера, а не из модели карты.

## Открытые вопросы

- Минимальная дистанция между NPC (1,2 м как у игроков, REALTIME-010) и пределы радиуса разговора (0,5–10 м) — предложены и требуют подтверждения.
- Нужно ли восстановление удалённых NPC из панели.
