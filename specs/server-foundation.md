# SERVER — Основа отдельного сервера

## Цель

Обеспечить единственный локальный сервер для браузерных клиентов.

## Требования

- **SERVER-001:** Сервер разрабатывается отдельным проектом, не внутри client/. Он размещает Socket.IO, SQLite, авторизацию, данные мира, состояние игроков и локальный ИИ на одном ноутбуке.
- **SERVER-002:** Модули bootstrap/config, auth, realtime, world, players, persistence и ai имеют явные интерфейсы; транспорт не содержит игровые правила, а хранилище не управляет сокетами.
- **SERVER-003:** Сервер обслуживает локальный HTTP для готового клиента и ресурсов либо документирует локальный способ их раздачи. Публично доступны оболочка приложения и форма входа; данные реального мира выдаются с проверками AUTH и SERVER-WORLD. Браузерный клиент не требует установки ПО.
- **SERVER-004:** Адрес прослушивания, порт, пути БД/мира/моделей и лимиты задаются конфигурацией. Для LAN доступен сетевой интерфейс, для автономного режима — loopback; отсутствуют внешние runtime-зависимости. AI-конфигурация задаёт backend mlx/ollama, локальный snapshot/digest и квалифицированный профиль LLM; inference endpoint не публикуется в LAN, запуск двух моделей/backend одновременно запрещён. MLX-worker может требовать локальный Python независимо от языка игрового сервера.
- **SERVER-005:** При запуске проверяются конфигурация и обязательные ресурсы; ошибки понятны. Корректная остановка прекращает приём команд, завершает сохранение, закрывает БД и соединения.

## Сценарии

- **S1:** SERVER-001–004: Given подготовленный ноутбук; When сервер запущен; Then несколько браузеров LAN открывают клиент, серверные модули находятся в одном процессе или локально управляемой установке.
- **S2:** SERVER-004–005: Given недоступный путь БД/мира или остановка; When выполняется запуск/завершение; Then ошибка диагностируется либо состояние корректно сохраняется.

## Ограничения и вне scope

Без микросервисов, облачной БД и внешнего ИИ. Клиентский репозиторий содержит серверные спеки, но не создаёт серверный код.

## Открытые вопросы

Выбрать runtime/язык сервера и версии зависимостей при создании отдельного проекта. Socket.IO и SQLite заданы пользователем.
