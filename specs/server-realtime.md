# REALTIME — Сетевая сессия и авторитетная симуляция

## Цель

Реализовать серверную сторону [PROTO v1](protocol.md) так, чтобы уже готовый клиент (OnlineSession/SocketIOAdapter) работал без изменений. Сервер авторитетно считает движение и видимость, подтверждает действия и доставляет чат.

## Требования

- **REALTIME-001:** Только соединения, прошедшие handshake [AUTH](server-auth.md), получают игровые события. Каждое событие `game` разбирается `parseClientMessage` из `shared/` до любой обработки. Socket.IO `maxHttpBufferSize` ограничивает пакет величиной 256 KiB плюс служебный запас.
  - Неверный пакет — `error INVALID`. Если requestId извлекается — с ним, иначе с `"server"`.
  - Версия ≠ 1 — `error VERSION`, затем разрыв.
  - Более 10 неверных пакетов за 10 с — разрыв.
  - События кроме `game` игнорируются.
  - До успешного `join` любые другие типы получают `error NOT_READY`; повторный `join` в соединении — `error INVALID`.
- **REALTIME-002 (вход в мир):** `join {mapId}`:
  - неизвестный mapId — `error INVALID`;
  - сущность аккаунта уже в мире (grace, перехват) — сохраняется её позиция;
  - иначе берётся сохранённая позиция игрока, если карта совпадает и точка проходима; иначе spawn из manifest;
  - смена карты относительно сохранённой ставит игрока в spawn новой карты.

  Ответ — `joined {requestId, playerId, revision: 0, snapshot, world}`: `snapshot` — AOI (REALTIME-005) с tick сервера, `world` — bootstrap карты (SERVER-WORLD-003). Сущности v1:
  - **игрок:** `{id: playerId, character {kind: "player", name: displayName}, transform, movement {direction, speed: 3}, renderable {assetId: "demo-player"}, animationState {name: "idle"}}`;
  - **NPC:** `{id, character {kind: "npc", name}, transform, interactable {radius, label: тема}, renderable {assetId}?, animationState {name: "idle"}}` из SERVER-WORLD-008; `renderable` — только если задан `assetId`.
- **REALTIME-003 (движение):** `input` задаёт намерение по правилам PROTO-008 п. 4: последнее, сброс через 250 ms, старые sequence игнорируются. На каждом шаге (`dt = 1/tickHz`) кандидат — `позиция + direction × 3 м/с × dt`; длина direction ограничена 1. Кандидат принимается, если:
  1. все четыре пробы SHARED-005 проходимы;
  2. чанк каждой пробы входит в последний принятый `preparedChunks`.

  ID чанков, которых нет в manifest карты, отбрасываются. Если полный шаг запрещён, по очереди пробуется шаг только по X, затем только по Z (скольжение вдоль стены); иначе игрок стоит. `rotationY = atan2(dx, dz)` фактического смещения, при остановке не меняется. В `movement.direction` — фактически применённое нормализованное направление (нулевое при остановке). `y` не меняется. Клиент не задаёт позицию, скорость, имя и другие защищённые значения.
- **REALTIME-004 (порядок и частоты):**
  - Сообщения соединения обрабатываются в порядке поступления.
  - Намерения применяются на ближайшем шаге; запросы (`interact`, `npc-question`, `chat-send`, `resync`) проверяются по текущему состоянию мира.
  - Шаг — фиксированный `tickHz` (20) с компенсацией дрейфа таймера, не более 5 догоняющих шагов, лишние отбрасываются.
  - Рассылка — каждые `tickHz/broadcastHz` шагов.
  - Шаг синхронный: без await, без SQLite и без ожидания NPC.
  - Длительность шага (p50/p95/max) пишется в лог раз в 60 с.

  Лимиты на соединение (token bucket):

  | Тип | Лимит | При превышении |
  |---|---|---|
  | input | 30/с | отбрасывается без ответа |
  | chat-send | 1/с, всплеск 3 | `error RATE_LIMIT` |
  | npc-question | по [NPC](server-npc-dialogue.md) | по NPC |

  Повтор уже использованного в соединении requestId получает `error INVALID` без эффекта (клиент v1 ID не повторяет).
- **REALTIME-005 (AOI, delta, resync):**
  - **AOI** — собственная сущность плюс сущности той же карты в радиусе `aoiRadius` по XZ, ближайшие первыми, всего ≤256.
  - **Delta.** На каждой рассылке состояние AOI сравнивается с последним отправленным этому соединению по сериализованному виду сущности. Отправляется `delta {revision: prev+1, baseRevision: prev, tick, upsert, remove}`: `upsert` — новые и изменившиеся сущности **целиком**, `remove` — вышедшие из AOI или удалённые из мира. Без изменений пакет не отправляется (PROTO-008 п. 3). Выход из AOI удаляет только клиентское представление, не серверную сущность.
  - **Resync.** `resync` получает `snapshot {revision: текущая, snapshot: AOI}`, и базой следующих delta становится этот снимок.
  - Пакет перед отправкой проверяется на 256 KiB; в тестах исходящие пакеты дополнительно проходят `parseServerMessage`.
- **REALTIME-006 (присутствие):** Разрыв управляющего соединения:
  1. отменяет его ожидающий NPC-запрос;
  2. обнуляет намерение;
  3. оставляет сущность в мире неподвижной на `disconnectGraceMs` (10 с), она занимает слот и видна другим;
  4. после grace сущность удаляется из мира (у наблюдателей — `remove`), позиция сохраняется, слот освобождается.

  Новое соединение аккаунта в течение grace или при живом старом сокете продолжает ту же сущность (AUTH-005): второй сущности и второго слота нет. Позиции игроков, сдвинувшихся с прошлого сохранения, сохраняются каждые `saveIntervalMs`, а также при удалении из мира и при остановке (STORE-003). Ошибка сохранения пишется в лог и не останавливает мир.
- **REALTIME-007 (взаимодействие):** `interact {targetId}`: цель существует на карте игрока, имеет `interactable`, а 3D-расстояние ≤ `radius + 0.5` (запас на задержку). Тогда ответ — `interacted {requestId, targetId}`, иначе `error FORBIDDEN` с текстом «Слишком далеко» или «Объект недоступен». Изменений мира в v1 взаимодействие не вызывает.
- **REALTIME-008 (чат):** `chat-send {text}`:
  - текст после trim, 1–500 символов; управляющие символы, кроме перевода строки, — `error INVALID`;
  - доставка всем подключённым игрокам той же карты, включая отправителя, как `chat {requestId: отправителя, messageId, playerId, name: displayName, text}`;
  - `messageId` уникален и между перезапусками сервера, например `m<время старта в base36>_<счётчик>`: клиент отбрасывает повторный messageId.

  Сервер не интерпретирует текст как HTML и в v1 чат не сохраняет. Область чата v1 — вся карта, независимо от расстояния (ср. BABEL-009).
- **REALTIME-009 (NPC):** `npc-question` передаётся NpcDialogueService по [NPC](server-npc-dialogue.md); realtime только разбирает пакет и доставляет `npc-answer`/`error` своему соединению.

## Сценарии

- **S1 · REALTIME-001–002, 005:** Given 2 тестовых клиента на market; When оба выполняют join; Then каждый получает `joined`, где есть он сам, второй игрок и NPC карты, а все пакеты проходят `parseServerMessage`. When первый двигается; Then второй получает delta с revision +1 и полной сущностью первого, без пустых delta в покое.
- **S2 · REALTIME-003:** Given игрок у стены courtyard с подготовленными чанками; When он идёт в стену по диагонали; Then скользит вдоль неё, внутрь не проходит. When `preparedChunks` пуст или содержит только текущий чанк, а игрок идёт к границе; Then останавливается до неподготовленного чанка. When после `input` с движением больше ничего не приходит; Then игрок останавливается через ≤250 ms.
- **S3 · REALTIME-001, 003–004:** Given пакет с полем `position`, чужим playerId, `v: 2`, повтором requestId и 40 `input` за секунду; When сервер их получает; Then мир не меняется незаконно, клиент получает INVALID/VERSION, лишние input отброшены без error.
- **S4 · REALTIME-005:** Given клиент пропустил delta; When он отправляет `resync`; Then получает snapshot с текущей revision, следующий delta имеет `baseRevision` = этой revision. Given игрок уходит дальше `aoiRadius`; Then наблюдатель получает его ID в `remove`.
- **S5 · REALTIME-006:** Given игрок в мире; When его соединение рвётся и через 3 с подключается снова; Then у наблюдателя нет remove и второй сущности, позиция прежняя. When разрыв длится 11 с; Then наблюдатель получает `remove`, позиция сохранена в БД, слот свободен для пятого аккаунта.
- **S6 · REALTIME-007–008:** Given игрок в 1 м и в 5 м от NPC; When он отправляет interact; Then в первом случае `interacted`, во втором `error FORBIDDEN`. When два игрока пишут в чат; Then оба получают оба сообщения с уникальными messageId, отправитель видит своё с собственным requestId, сообщение с `<script>` доставлено как текст.
- **S7 · REALTIME-004:** Given 4 тестовых клиента двигаются, пишут в чат и одновременно задают NPC вопросы с задержкой заглушки 5 с; When идёт 60 с нагрузки; Then p95 длительности шага и интервал рассылки записаны, шаг не ждёт NPC.

## Ограничения и вне scope

- Prediction/reconciliation, физика, бой, высоты и лестницы вне MVP.
- Покупка, предметы, задания, перевод чата и камень — механики BABEL/SCENE, PROTO v2.
- Чат не сохраняется и не модерируется. Ограничения — размер, частота и вывод как текста.
