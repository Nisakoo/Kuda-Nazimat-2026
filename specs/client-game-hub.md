# HUB — Личный кабинет

## Требования

- **HUB-001:** После успешного входа и регистрации открывается личный кабинет. Первичный выбор облика выполняется из кабинета, а не отдельным обязательным экраном между авторизацией и кабинетом. Фон — тот же локальный фон ворот, что у первого окна входа; настройки доступны через общую шестерёнку.
- **HUB-002:** Кабинет показывает имя авторизованного игрока, подтверждённый облик и действие выбора персонажа. Имя не редактируется в этой поставке. У нового аккаунта виден статус «Выберите персонажа»; без подтверждения облика запуск мира невозможен, сам кабинет доступен.
- **HUB-003:** Родной и изучаемый языки по умолчанию задаются на странице профиля. Они различаются; список приходит от сервера. Существующие значения восстанавливаются, у нового профиля предварительно выбраны ru/en, если они поддержаны сервером. Сохранение показывает ожидание, подтверждение и ошибку. До успешного сохранения игра не запускается. Профиль и языки должны сохраняться независимо от наличия задания; профиль без задания хранится с пустой ссылкой на группу.
- **HUB-004:** Внизу кабинета в один горизонтальный ряд, в указанном порядке, расположены «Выйти», «Подключиться», «Создать игру». Кнопки равной высоты, с читаемыми подписями, доступны Tab/Enter. При узком окне весь кабинет прокручивается без обрезания действий; три действия остаются в одной строке.
- **HUB-005:** «Выйти» отзывает текущую серверную сессию и возвращает пустую форму входа. Облик, языки и игровой прогресс не удаляются. Ошибка серверного отзыва показывается отдельно.
- **HUB-006:** «Подключиться» открывает форму с отдельными полями IP-адреса и порта (1–65535), кнопками «Назад» и «Подключиться». Принимаются IPv4/IPv6; адрес и порт текущего сервера подставлены для редактирования. Невалидный адрес, недоступный сервер, несовместимая версия, полная группа и отсутствие доступной игры показываются явно. Адрес без токена и пароля можно запомнить в браузере.
- **HUB-007:** Подключение к текущему серверу использует текущую действительную сессию. Для другого сервера требуется авторизация на нём; токен или пароль первого сервера автоматически не отправляются другому. После входа на целевой сервер возобновляется намерение подключиться; используются подтверждённые профиль и облик этого сервера. Разные серверы не подразумевают общий аккаунт. Перед переходом клиент проверяет публичный /api/health без credentials и redirect; затем открывает страницу самого целевого сервера. Игровые API работают с его origin. Для отдельной раздачи клиента с другого origin нужны согласованные HTTP/Socket.IO CORS; ошибка не маскируется локальной имитацией.
- **HUB-008:** «Создать игру» открывает указатель выбора режима ENTRY-011. «Назад» с указателя возвращает кабинет без выхода, сохраняя подтверждённый профиль и текущий выбор режима. Языковой этап отсутствует. «Далее» отправляет явную операцию создания с выбранным режимом, после успеха начинается LOAD.
- **HUB-009:** Создание и присоединение — разные серверные операции: создание не должно молча присоединять к чужой ожидающей группе, а подключение не должно создавать новую. Сохранённый прогресс не сбрасывается скрыто. Создание на 1–4 игроков независимо от других ожидающих групп: выбранный режим создаёт новое отдельное приключение, а не заменяет чужую группу. Режим создания выбирается свободно; состояние чужой/старой группы не блокирует radio указателя. У подключающегося режим берётся из целевой игры.
- **HUB-010:** «Создать игру» создаёт игровую сессию на уже работающем локальном сервере, а не запускает процесс ОС из браузера. Ограничение четырёх игроков и отсутствие runtime-интернета сохраняются. Отдельный 3D-лобби-мир не создаётся.

Уточнение HUB-009: кабинет и указатель показывают режим сохранённой игры и действие «Продолжить игру» без повторного ввода адреса. Собственная сохранённая игра не блокирует «Далее»: перед созданием показывается подтверждение «Удалить текущую игру и создать новую?» с указанием выбранного режима и потери прогресса приключения. «Отмена»/Esc ничего не меняют; «Удалить и создать новую» заменяет именно подтверждённую игру одной атомарной операцией. Профиль, облик и личный словарь сохраняются. При выходе из совместной группы данные остальных участников остаются; пустая группа удаляется. Устаревшее подтверждение или ошибка создания не удаляют текущую игру. Без собственной игры можно присоединиться к ожидающей группе: при нескольких вариантах игрок явно выбирает группу по имени ведущего и числу участников; отправляется её устойчивый ID. Без выбора допускается только единственный вариант. При своей игре действие «Продолжить игру» продолжает её, а не обещает переход в чужую. Устаревший выбор полной/начавшейся/исчезнувшей группы сообщает об ошибке и оставляет возможность обновить выбор. Список ограничен последними 64 ожидающими группами; при усечении UI сообщает об этом, новые группы видны первыми. Постоянный отказ (неверные данные, запрет, конфликт) не предлагает «Повторить запрос»; временный или неопределённый отказ допускает повтор того же requestId. Ошибка команды сохраняется при фоновом обновлении состояния до нового действия или смены экрана.

## Сценарии

- **S1 · HUB-001–004:** Новый игрок регистрируется → кабинет; выбирает персонажа и разные языки, сохраняет → три действия доступны в одной строке. После повторного входа данные восстановлены.
- **S2 · HUB-005:** «Выйти» → пустой вход, токен отозван, сохранённые данные остаются.
- **S3 · HUB-006–007:** Игрок вводит IP и порт → получает понятную ошибку при неверных данных/отказе сети, исправляет → проходит авторизацию целевого сервера и подключается; токен исходного сервера не передан.
- **S4 · HUB-008–009:** «Создать игру» → указатель; «Одному»/«С друзьями» переключаются мышью и стрелками; «Назад» → кабинет; повторный вход на указатель сохраняет выбор; «Далее» создаёт именно выбранный режим.
- **S5 · HUB-009:** Есть одиночная игра → выбрать «С друзьями» и «Далее» → предупреждение. Отмена сохраняет ID и прогресс; подтверждение создаёт совместную игру с новым ID и пустым прогрессом, сохраняя профиль/облик/словарь. Аналогично работает замена совместной на одиночную. Чужая или собственная общая ожидающая группа не блокирует новую одиночную или многопользовательскую игру; данные оставшихся участников сохраняются. При двух ожидающих группах новый участник явно выбирает нужную, а запрос без ID не присоединяет его к первой. Продолжение своей игры не меняет её ID.

## Границы

Перенос аккаунтов между серверами, смена имени, восстановление пароля, каталог серверов и запуск серверного процесса из браузера в эту поставку не входят.
