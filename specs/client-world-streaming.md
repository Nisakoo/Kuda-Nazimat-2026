# MAP — Карта и загрузка мира

## Цель

Загружать мир по положению игрока и освобождать ненужные данные.

## Требования

- **MAP-001:** MapSource получает JSON manifest и описания чанков без зависимостей от Three.js. HttpMapSource работает с локально раздаваемыми файлами в LocalSession и авторизованным серверным HTTP-источником в OnlineSession. Данные реального мира не дублируются в публичной клиентской поставке; Socket.IO используется для команд и динамических событий.
- **MAP-002:** Manifest содержит mapId, version, размер чанка, spawn, индекс чанков и ссылки на ресурсы; описания чанков содержат логические объекты, точки взаимодействия, данные коллизий или ссылки на них. Визуальная геометрия — GLB. Статические чанки отделены от динамических сетевых сущностей. Необязательные heightSurfaces задают высоту лестниц/площадок по SHARED-007; отсутствие поля сохраняет плоскую карту.
- **MAP-003:** ChunkManager сначала получает manifest, затем чанки около стартовой позиции: spawn из manifest для LocalSession, подтверждённая сервером позиция для OnlineSession, включая восстановление сохранения. При перемещении и смене карты пересчитывает нужный набор с настраиваемым радиусом, выгружает дальние чанки, ограничивает параллельные запросы и не блокирует игровой цикл.
- **MAP-004:** Повторные запросы одного ресурса объединяются; отменённые или устаревшие ответы не возвращают выгруженные чанки. Ошибки видны в UI, доступен повтор загрузки.
- **MAP-005:** AssetManager учитывает ссылки на общие ресурсы и очищает неиспользуемые данные. Map управляет описаниями и загрузкой данных, render — объектами Three.js и их GPU-жизненным циклом; владельцы и порядок освобождения явны.
- **MAP-006:** Обычный набор мира ограничен окном чанков вокруг игрока: радиус 0–2, максимум 25 чанков с учётом загружаемых. Дальние чанки выгружаются; общие модели хранятся один раз до последнего владельца. Процентного ограничения от размера мира нет. До запроса резервируется консервативный бюджет полезных данных; аварийный предел 128 MiB охватывает активные, pending и ещё освобождаемые ресурсы. При его нехватке подготовка сокращается или откладывается, текущая область защищена. Скрытого browser cache или предварительной загрузки полного мира нет.
- **MAP-007:** Демо-карта содержит достаточно чанков для проверки загрузки и выгрузки в пределах бюджета. В стартовый JS-пакет полный мир не включается; локальный режим загружает файлы по требованию с того же узла.

- **MAP-008:** Связный мир разделён на тематические районы и переходы. Район задаёт контент, а чанки — загрузку; переход между районами не создаёт новую сессию и не загружает район целиком. Общие модели адресуются независимо от чанков и переиспользуются.
- **MAP-009:** Движение разрешено только в подготовленную область с доступными данными взаимодействий/коллизий. Если загрузка не успевает, UI показывает ожидание, а игрок не попадает в отсутствующий участок. Приоритет имеют текущая область и ближайший переход; запас перед выгрузкой допускается только в пределах бюджета. В онлайн-режиме ограничение согласуется с авторитетным сервером, клиент не назначает себе позицию.

## Сценарии

- **S1:** MAP-001–003, 007: Given manifest и spawn; When игрок пересекает границы чанков; Then нужные чанки загружаются, дальние удаляются, кадры продолжаются.
- **S2:** MAP-003–005: Given медленные запросы и общий ресурс; When игрок быстро меняет направление и запрос завершается поздно; Then устаревший чанк не появляется, параллелизм ограничен, общий ресурс жив до последней ссылки.
- **S3:** MAP-004: Given ошибка загрузки; When пользователь повторяет запрос; Then UI показывает результат и цикл не останавливается.
- **S4:** MAP-006: Given радиус 2 и нормальная карта market; When игрок проходит через границы; Then готовится окно до 25 чанков (для компактного market — до 16), дальние удаляются. Для искусственно тяжёлых ресурсов резерв не превышает защиту 128 MiB, даже пока отменённый декодер сохраняет владение.

- **S5:** MAP-003, 008–009: Given два соседних тематических района и медленная загрузка перехода; When игрок подходит к границе; Then сессия сохраняется, соседние чанки подгружаются без загрузки всего района, до готовности области переход безопасно ограничен.
- **S6:** MAP-001, 003: Given онлайн-вход с сохранённой позицией вне manifest spawn; When сервер подтверждает вход; Then загружается окружение сохранённой позиции, а не исходной точки карты.
- **S7:** MAP-003, 004, 006, 009: Given соседний чанк отложен из-за бюджета; When игрок приближается к нему внутри текущего чанка; Then новый приоритет запускает подготовку без ручного retry, текущая область защищена и лимит соблюдён. Если нужный ресурс не помещается даже после вытеснения, менеджер прекращает повторять одинаковые попытки и сохраняет доступные соседние участки; диагностика сообщает об ограничении бюджета.

## Ограничения и вне scope

Реализация серверного источника описана в [серверной спеке мира](server-world.md). Реальная приёмка лимита не заменяется проверкой одного LRU-кеша.

## Контракт учёта и планирования

Основное ограничение — окно чанков; по решению пользователя процентный лимит кеша удалён. Уникальные сериализованные байты статических ресурсов продолжают учитываться для диагностики и проверки размеров файлов. Общий объём — сумма фактических размеров уникальных manifest/chunk/collision/model/image/buffer ресурсов подготовленного мира; bootstrap содержит проверенные общий объём и размер manifest до его запроса. Повторные ссылки на общий ресурс не увеличивают общий объём.

Ресурс считается занятым с резервирования до освобождения последнего CPU/GPU-владельца, даже если исходный HTTP-буфер уже не нужен. Pending-запросы тоже резервируются. Декодирование, GPU-копии и временные буферы не умножают сериализованный размер одного ресурса; для их полезных данных действует отдельный консервативный memory-cap 128 MiB, резервируемый по верхним границам manifest. Это метрика данных, не утверждение о полном RSS браузера/драйвера. HTTP-запросы используют no-store, service worker не создаётся. Неизвестный размер/выход за лимит вызывает отказ до загрузки; неверный размер HTTP-ответа отклоняется.

Для карты market по умолчанию выбраны чанки 32 м и радиус 2 (окно 5×5); demo/science сохраняют радиус 1. Настройка 0–2 и параллелизм 2 доступны во всех режимах. Сначала текущий чанк, затем ближайшие; нет дополнительного удержания дальних чанков. При нехватке бюджета предзагрузка сокращается; текущая готовая область сохраняется. Это параметры данного демо, не обязательные размеры мира отдельного сервера. Локальное движение проверяет готовность и коллизии; онлайн-клиент отправляет намерение/готовность области, авторитетную позицию назначает сервер.

Ограничения PROTO v1 на размер одного файла/manifest (≤worldBytes/10) и memory одного ассета (≤32 MiB) сохранены как валидация формата; они не ограничивают суммарное окно клиента. Сервер (`server/`) предоставляет bootstrap/manifest того же контракта по [SERVER-WORLD](server-world.md); физическая приёмка — DEMO. Клиент не объявляет серверную совместимость проверенной по локальному демо.

## MAP и движение MOVE

MAP-002/006–007: manifest v1 содержит optional ceilingVolumes по SHARED — ≤128 общих объёмов и ≤128 в каждой записи чанка, с разделением по границам клеток. Генератор извлекает консервативные AABB из локальных моделей до batching; сервер читает подготовленные данные. Проверка всего пути/площади следа общая, готовность и бюджет окна остаются у ChunkManager. До готовности начального следа LocalSession не интегрируется; ожидание чанка не тратит запас.
