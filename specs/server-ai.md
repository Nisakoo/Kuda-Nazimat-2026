# AI — Локальные образовательные персонажи

## Цель

Дать NPC индивидуальность и адаптацию к предыдущим действиям конкретного игрока. Основной подход MVP: одна локальная Qwen3.5-2B 4-bit, два взаимозаменяемых backend MLX/Ollama, проверенные локальные материалы и компактная память в SQLite. Конкретный профиль принимается только после LLM-QA; модель не объявляется лучшей по неизмеренным характеристикам.

## Требования

- **AI-001:** Все вычисления ИИ выполняются локально на серверном ноутбуке; тексты, модели и файлы поведения подготовлены заранее. Внешние API, телеметрия и загрузка моделей во время игры запрещены. Выбор backend и модельных артефактов регулирует LLM.
- **AI-002:** Каждый NPC имеет версионированный профиль: npcId, предметную область, стиль, допустимые темы и разрешённый корпус знаний. Минимальное демо включает Эйнштейна для относительности и Геродота для путешествий в Египет. Персонаж — учебная реконструкция, не подлинный исторический собеседник. Ответы обозначают неизвестное и различают содержание исторического источника и установленные современные факты.
- **AI-003:** Ответ учитывает вопрос, профиль, текущий авторитетный контекст и индивидуальную память игрока: обсуждавшиеся темы, явные предпочтения и подтверждённый игрой прогресс. Повторный вопрос вызывает другое объяснение/уточнение, а не неизменную линейную реплику. Факт разговора и модельная оценка понимания не подтверждают освоение темы или игровой прогресс.
- **AI-004:** Память пользователей изолирована и сохраняется через STORE. NPC-специфичная память имеет ключ `(playerId, npcId)`; общая языковая настройка игрока хранится отдельно. Сброс/сжатие/очистка не смешивают игроков; после рестарта персонализация восстанавливается из подтверждённого состояния БД, не из случайно живого KV-кеша.
- **AI-005:** Обработка имеет ограниченную очередь, отмену и таймауты по LLM-010–011; долгий ответ не останавливает симуляцию. Поток, итог и ошибки адресуются только авторизованному владельцу по requestId и dialogueId. Закрытый или устаревший диалог не получает поздние фрагменты; клиентское демо не выдаётся за серверную генерацию.
- **AI-006:** Выбранный путь — локальная LLM с grounding и детерминированным управлением памятью, а не агент с инструментами. NPC не выполняет команды ОС, SQL, HTTP-запросы, не меняет позицию, инвентарь, права или прогресс. Модель создаёт только текст ответа; игровые изменения проходят отдельные авторитетные правила. Безопасность не полагается исключительно на system prompt.
- **AI-007:** Минимальные проверяемые языки — ru, en, es; язык выбирается сохранённой явной настройкой preferences (default ru), в запросе проверяется совпадение locale, для принятого запроса фиксируется снимок языка/стиля. Сам dialogue.request не меняет сохранённую настройку. Другие языки допускаются после отдельного прогона, без обещания одинакового качества всех заявленных моделью языков. Unsupported locale возвращает понятный статус/предложение выбора, а не молчаливую смену языка. Подготовленные материалы могут быть на другом языке, но ответ не должен смешивать языки без учебной необходимости.
- **AI-008:** KnowledgeSource хранит локальные утверждённые фрагменты с sourceId, редакцией, языком и npcId/темой. Для MVP используется поиск по локальному полнотекстовому индексу SQLite FTS5 и небольшие вручную заданные тематические/межъязыковые aliases для ru/en/es; отдельная embedding-модель не нужна. Отсутствие FTS5 в выбранной сборке SQLite обнаруживается при подготовке. Релевантность поиска проверяется корпусом LLM-QA, включая запросы на языке, отличном от источника. Не найдено достаточного основания — NPC обозначает недостаток материала, а не заполняет пробел выдумкой. Игроку можно показать локальные source ID; эти ID формирует сервер, не выдумывает модель.
- **AI-009:** PromptBuilder получает профиль, отобранные материалы, компактную память и последние завершённые реплики только нужного игрока/NPC, затем соблюдает реальный token budget LLM-008. Архив целиком в prompt не включается. Пользовательский ввод, найденные цитаты и память размечаются как данные, не повышаются до system-инструкций. Изоляция данных и отсутствие инструментов обеспечиваются вне LLM. Потоковые фрагменты не являются доверенными учебными фактами; ограничения безопасности и проверка фактов оцениваются отдельно.
- **AI-010:** История и компактная память разделены. В MVP MemoryService детерминированно обновляет обсуждавшиеся темы по выбранным source/topic ID, явные настройки из валидированной операции preferences и события авторитетной игры; предпочтение «без формул» задаётся responseStyle=simple_no_formulas, а не угадывается из свободной реплики; автоматическая LLM-суммаризация и произвольные «факты об игроке» не используются. На пару player/NPC — максимум 16 записей памяти по 256 UTF-8 байт; в prompt выбирается подмножество по лимиту токенов. Для замены записи при переполнении используются тип и давность: явные предпочтения приоритетнее старых обсуждавшихся тем; память не хранит секреты и выводы о чувствительных характеристиках. Данные об освоении поступают только от игровой системы. Reset увеличивает версию памяти, отменяет соответствующие запросы и очищает персональные runtime-кеши; старая генерация не может вернуть сброшенную память.
- **AI-011:** Запрос сначала получает durable-запись в STORE. Промежуточный текст помечается как незавершённый; успешное terminal-событие отправляется только после транзакционного сохранения финального ответа и обновления памяти. Ошибка БД не маскируется успешным запоминанием. Выполнение и terminal-события идемпотентны по scoped requestId; после рестарта незавершённые запросы получают `interrupted`, а завершённые могут быть прочитаны без повторной generation. Факт commit не доказывает доставку: при crash/reconnect сервер возвращает сохранённый результат, а не создаёт второй.

## Границы модулей будущего сервера

```text
realtime/auth → NpcDialogueService → очередь и lifecycle запроса
                                  ├─ KnowledgeSource (SQLite FTS5 + локальные тексты)
                                  ├─ MemoryService / DialogueRepository → SQLite
                                  ├─ PromptBuilder → бюджет tokenizer/template
                                  └─ LlmPort → MlxAdapter / OllamaAdapter
```

Проверки права/дистанции выполняются перед постановкой в очередь и повторно перед generation/доставкой. Потеря доступа отменяет запрос. Повторный requestId с другим содержимым отклоняется. Запрос не держит транзакцию SQLite во время inference; финальная короткая транзакция проверяет текущую версию памяти/reset и сохраняет результат. Очередь/БД не выполняют блокирующее чтение/запись на игровом шаге.

## Сценарии

- **S1 · AI-001–003, 006–009:** Given внешняя сеть отключена и два профиля с утверждёнными источниками; When игрок задаёт вопросы на ru/en/es; Then получает краткий учебный ответ нужного профиля/языка, при отсутствии материала — обозначенное неизвестное, без внешних запросов или новых полномочий модели.
- **S2 · AI-003–004, 010–011:** Given A обсуждал тему, B ещё нет; When оба спрашивают после рестарта; Then A получает адаптированное объяснение, B — независимое; разговор не превращается автоматически в зачтённое знание, история и память восстановлены.
- **S3 · AI-005, 011:** Given очередь, медленный вычислитель и смена диалога; When очередь заполнена, игрок выходит либо ответ приходит поздно; Then есть коррелированный статус/ошибка, синхронизация мира продолжается, поздний текст не попадает в другой диалог.
- **S4 · AI-008–010:** Given цитата или сообщение с поддельной system-инструкцией; When формируется ответ; Then данные не открывают доступ к SQL/ОС/чужой памяти, найденные source ID принадлежат разрешённому корпусу; критические проверки проходят по LLM-QA.
- **S5 · AI-004, 010–011:** Given активный запрос и существующая память; When выполнен reset, произошёл сбой БД либо crash после commit до доставки; Then память не воскресает из старого запроса/кеша, незавершённый ответ не объявляется сохранённым, повтор не создаёт дубликата.

## Ограничения и вне scope

Клиентские демо-реплики не выполняют эту спеку. Нет голоса, fine-tuning, произвольных агентских инструментов и гарантии исторической достоверности только за счёт весов модели. Автоматическая LLM-суммаризация отложена: она добавляет задержку, память и риск выдуманных сведений. Проверенные материалы и ограничения не дают абсолютной гарантии отсутствия галлюцинаций — необходима предметная проверка.

## Открытые вопросы

Подготовить и утвердить локальные материалы/aliases, предметные критерии диалогов и целевое оборудование; квалифицировать модель/артефакты по LLM-QA. Серверный runtime и общий handshake остаются решениями SERVER/PROTO/AUTH. Численные лимиты LLM выбраны, но ещё не подтверждены реализацией.
