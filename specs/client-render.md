# RENDER — Three.js

## Цель

Отображать состояние сущностей и чанков единственным ThreeRenderer.

## Требования

- **RENDER-001:** RenderAdapter изолирует рендеринг от Core, Map и UI. Реализуется только ThreeRenderer; конфигурации выбора движка и загрузки второго движка нет.
- **RENDER-002:** Адаптер создаёт canvas, сцену, камеру и освещение; поддерживает resize, слежение камеры и понятную ошибку недоступного 3D-контекста.
- **RENDER-003:** Внутри адаптера хранится EntityId → VisualObject. Изменение transform обновляет существующий объект, не создавая Mesh каждый кадр. Удаление сущности удаляет её визуальное представление.
- **RENDER-004:** GLB/glTF преобразуются в объекты Three.js внутри render. Поддерживаются визуальные чанки, базовые анимации и состояния AnimationState; ошибки загрузки не останавливают приложение.
- **RENDER-005:** Геометрии, материалы и текстуры переиспользуются; ресурс освобождается после последнего владельца. Выгрузка чанка и dispose освобождают GPU-ресурсы, анимации, подписки и canvas. Владение ресурсами согласовано с AssetManager.
- **RENDER-006:** Render не содержит бизнес-правил и сетевого кода. Состояние визуальной интерполяции отделено от состояния сессии; материалы и оптимизации остаются внутри адаптера.

- **RENDER-007:** Игровое представление использует одну сцену и один рендерер; статические чанки представлены отдельными группами. Динамические игроки/NPC принадлежат сессии и не уничтожаются при выгрузке статического чанка, если продолжают быть актуальны. Смена тематического района не пересоздаёт сцену. Данные GLB подготавливаются асинхронно; добавление крупных наборов объектов распределяется по кадрам при необходимости.

## Сценарии

- **S1:** RENDER-001–003, 006: Given сущность; When transform меняется многократно, затем сущность удаляется; Then визуал двигается без пересоздания Mesh и исчезает, Core не зависит от Three.js.
- **S2:** RENDER-002: Given окно приложения; When меняется размер или недоступен 3D-контекст; Then корректны камера и canvas либо показана ошибка.
- **S3:** RENDER-004–005: Given два чанка с общей GLB-моделью; When один выгружается, затем завершается игра; Then второй остаётся видимым, после завершения общие ресурсы освобождены.

- **S4:** RENDER-007: Given персонаж переходит между чанками/районами; When старый статический чанк выгружен; Then актуальный персонаж сохраняет визуал и анимацию, а сцена и рендерер не пересоздаются.

## Ограничения и вне scope

Нет переключения движка; сложные эффекты, LOD и instancing внедряются только при измеренной необходимости.
