# LLM — Локальный runtime NPC

## Цель

Быстро получать многоязычные ответы NPC на серверном ноутбуке через MLX или Ollama без облака. MLX/Ollama — серверные backend, а не клиентские LocalSession/OnlineSession. Реализация принадлежит будущему отдельному серверному проекту.

## Выбор модели

Основная модель MVP — **Qwen/Qwen3.5-2B**, post-trained, не вариант `-Base`, в 4-битном представлении. Лицензия исходной модели — Apache 2.0. Выбор основан на небольшом размере, многоязычности, доступности двух backend и обычном режиме без thinking по умолчанию. Это выбранная исходная конфигурация, а не утверждение о лучшем качестве или подтверждённой скорости на неизвестном оборудовании.

| Backend | Исходная конфигурация | Что требуется проверить |
|---|---|---|
| Ollama | `qwen3.5:2b-q4_K_M` | Точный digest, состав пакета, отсутствие ненужной загрузки vision, реальный пик RAM |
| MLX LM | 4-bit, group size 64, текстовая часть `Qwen/Qwen3.5-2B` | Совместимость версии MLX LM, преобразование/загрузка весов и chat template; только текстовая генерация |

Для MLX используется проверенный text-only артефакт либо воспроизводимая конвертация исходной post-trained модели. Наличие репозитория `mlx-community/Qwen3.5-2B-4bit` само по себе недостаточно: его карточка описывает `mlx-vlm` и image-text-to-text. Не выдавать такой пакет за проверенный text-only пакет MLX LM. Конвертация и её пиковая память относятся к подготовке, а не игровому runtime; подготовка заранее допустима на более мощной машине. Исследованный, но не выполненный путь: `mlx_lm.convert --model Qwen/Qwen3.5-2B --mlx-path ./qwen35-2b-text-4bit -q --q-bits 4` на заранее закреплённом source snapshot с явно зафиксированным group size 64. У MLX LM v0.32.2 есть загрузчик Qwen3.5 с фильтрацией vision-весов; наличие кода не заменяет smoke-тест результата, состава тензоров, template и автономного запуска.

Резервный кандидат для квалификации — **Qwen3-1.7B Q4_K_M / MLX 4-bit**. Он не переключается автоматически и не считается принятым до тех же проверок. **Qwen3-4B-Instruct-2507 Q4_K_M** используется как необязательная точка сравнения качества, не как поставка по умолчанию: размер файла около 2,5 ГБ не гарантирует общий расход до 4 ГБ. Qwen3.5-0.8B — кандидат только при недостаточной скорости 2B/1.7B и отдельном подтверждении качества.

### Рассмотренные альтернативы

- Qwen3.5-4B оставляет слишком мало запаса под runtime и контекст: пакет Ollama Q4_K_M около 3,3 ГБ; не выбран для строгого бюджета.
- LFM2.5-2.6B имеет русский язык и небольшой GGUF, но всегда использует thinking, авторы не рекомендуют knowledge-heavy задачи, лицензия LFM содержит коммерческие ограничения. Не выбран как основа образовательного диалога.
- Gemma 4 E2B — не просто 2 млрд хранимых параметров: карточка указывает 5,1 млрд с embeddings, обычные пакеты Ollama превышают 4 ГБ. Не выбран.
- SmolLM3-3B обучался и на русском, но русский не входит в 6 основных языков; нет доказанного преимущества для нашего сценария. Не выбран без сравнительного прогона.

## Требования

- **LLM-001:** Поддерживаются `backend=mlx` и `backend=ollama`. MLX LM используется на Apple Silicon; Ollama — на поддерживаемых Windows/macOS, включая Intel Mac с CPU inference. Запуск на несовместимой ОС/архитектуре возвращает диагностируемую ошибку. Требования фиксируемой версии runner проверяются при подготовке. Текущая документация Ollama требует macOS 14+, поэтому произвольный старый Mac не объявляется поддерживаемым.
- **LLM-002:** Одновременно загружены только один backend и одна модель для всех NPC. Обычное переключение выполняется конфигурацией с контролируемым перезапуском AI runtime: новые запросы не принимаются, активный запрос завершается или отменяется по таймауту, очередь получает терминальные статусы, старые процессы/модель выгружаются, затем запускается новый backend. Без подтверждённой выгрузки запуск второго запрещён. Облачный и автоматический модельный fallback отсутствуют.
- **LLM-003:** Модель, tokenizer, chat template, runner и зависимости подготовлены до игры и разрешаются из локальных путей/кеша. Runtime не скачивает файлы, не вызывает внешние API, поиск, телеметрию или облачную генерацию. Для Ollama облачные функции отключены; одного имени модели без `cloud` недостаточно для проверки автономности. Отсутствие артефакта возвращает `model_unavailable`, а не инициирует скачивание.
- **LLM-004:** Запрос к общему порту содержит проверенные сервером `requestId`, `dialogueId`, `playerId`, `npcId`, язык, подготовленные сообщения и лимиты. Порт предоставляет проверку готовности, подсчёт токенов фактическим tokenizer/template, поток нормализованных текстовых фрагментов, завершение, отмену и остановку. Идентификаторы и права назначает/проверяет сервер; транспорт, SQLite и игровые правила не входят в адаптер inference. Внутренние названия событий runner не становятся игровым протоколом. Если runner не предоставляет подсчёт до генерации, адаптер использует локальный tokenizer-helper, его RAM также входит в бюджет. Считается именно окончательный prompt с фактически применяемым template; при необходимости передаётся уже отформатированный prompt через поддержанный raw-режим, без повторного template runner. Приближение по символам и подсчёт только после generation не являются admission control.
- **LLM-005:** `mlx` реализуется через MLX LM в отдельном локальном Python-процессе с ограниченным IPC либо loopback API; Python не навязывает язык игровому серверу. `ollama` использует локальный HTTP API. Порт inference недоступен браузерам/LAN напрямую; доступен только игровому серверу и локальному администратору. Endpoint задаёт доверенная серверная конфигурация, не входной запрос игрока. Loopback сам по себе не является авторизацией: браузер на серверном ноутбуке может обращаться к локальным портам. MLX-worker предпочтительно использует приватный IPC с правами ОС. Для HTTP-границы требуются локальная аутентификация сервисным секретом, строгая проверка Host/Origin и отсутствие wildcard CORS; секрет не включается в клиент/логи. У native Ollama loopback API нет достаточной встроенной авторизации: один proxy с токеном не закрывает обход прямого порта. Выделенный экземпляр изолируется сетевой/process-aware политикой ОС так, чтобы к native endpoint мог обратиться только серверный connector; способ и тесты фиксируются для каждой платформы. Профиль без проверенного барьера остаётся неквалифицированным. Проверяются запросы из локального браузера, посторонний Origin/Host, DNS rebinding и прямой native URL. Это не защита от администратора/root или скомпрометированного доверенного процесса ОС. Если выбранная версия MLX LM не умеет нужный tokenizer/отмену/события, тонкий worker реализует их явно; несовместимость не маскируется OpenAI-совместимым названием API.
- **LLM-006:** Для всех процессов LLM и относимых к AI буферов/кешей суммарный пиковый расход RAM не превышает **4 000 000 000 байт** (4 GB, не 4 GiB). Учитываются daemon/runner/worker, резидентные веса, tokenizer, KV/recurrent state, prefill, очереди, retrieval и буферы промптов/ответов. Нельзя вычитать idle-базу самого runner. Если AI-часть общего серверного процесса нельзя отделить достоверно, её считают консервативно вместе со всем этим процессом. БД/веса на диске не равны RAM. На Apple Silicon unified CPU/GPU memory учитывается один раз, но не исключается из бюджета; отдельная VRAM Windows измеряется дополнительно и не подменяет RAM. Не использовать swap или offload как доказательство соблюдения физического бюджета. Пики проверяются при старте, первом запросе, максимальном промпте, отмене и переключении.
- **LLM-007:** Рабочий профиль резервирует запас: soft threshold **3 500 000 000 байт**. Admission control ограничивает вход, контекст и очередь до запуска generation; монитор памяти при достижении soft threshold отменяет работу, освобождает кеши и при необходимости останавливает worker/runner с `resource_limit`. Предельный бюджет не является параметром `num_ctx` и не гарантируется одним периодическим watchdog. Метод контроля и средства ограничения на каждой ОС фиксируются; профиль без достоверного измерения пиков либо с превышением не получает квалификацию. Не обещать невозможность кратковременного превышения только по разреженным RSS-сэмплам.
- **LLM-008:** Начальный контекст — **2048 токенов суммарно для входа и выхода**, выход максимум **256 токенов**. Все system-инструкции, профиль, найденные материалы, память, история, пользовательский ввод и токены chat template входят в бюджет. Оставляется резерв на выход; запрещено молча увеличивать контекст или вытеснять доверенные правила ради истории. Сначала сокращаются старые реплики и нерелевантные фрагменты; если минимальный безопасный запрос не помещается, возвращается `input_too_long`. Длина ввода ограничена также до токенизации: максимум 4096 UTF-8 байт. Контекст 4096 и другие параметры принимаются только как отдельно квалифицированный профиль.
- **LLM-009:** Thinking выключен средствами фактического chat template/backend; его текст не отправляется игроку и не записывается в историю. Промпт просит краткий ответ на выбранном языке с предложением продолжить. Стартовые sampling-параметры для Qwen3.5-2B: temperature 1.0, top_p 1.0, top_k 20, presence_penalty 2.0, repetition_penalty 1.0 по карточке модели; поддержка каждого параметра проверяется, отсутствующий параметр не игнорируется молча. Их настройка допускается только с повторной оценкой зацикливаний, смешения языков и качества. Модельные параметры не считаются универсальными для резервного Qwen3-1.7B.
- **LLM-010:** Одна generation активна; очередь FIFO содержит не более 4 ожидающих запросов, у игрока не более 1 незавершённого запроса во всём AI-сервисе. Переполнение даёт `busy`, ожидание в очереди более 10 секунд — `queue_timeout`. На запрос после начала generation: до первого текста максимум 10 секунд, полная генерация максимум 30 секунд; это аварийные таймауты, не целевая скорость. Очередь хранит ограниченный пользовательский ввод и IDs, а полный prompt строится перед выполнением по актуальным данным. Ограничение частоты задаётся до очереди: burst 1, не чаще 1 нового запроса игрока в 2 секунды. Повтор с тем же requestId обрабатывается идемпотентно, а не как новый запрос.
- **LLM-011:** Отмена по выходу из диалога, logout, потере доступа, отключению или превышению лимитов доходит до вычислителя. Простое закрытие клиентского потока недостаточно: следующий запрос не запускается, пока прежняя генерация действительно не остановлена; при зависании worker/runner завершается контролируемо. Незавершённые данные не передаются другому игроку. Медленный потребитель не создаёт неограниченный буфер: максимум 64 КиБ неподтверждённых исходящих сериализованных stream-событий на запрос, затем отмена `slow_consumer`. Подтверждения `npc.dialogue.ack` и подсчёт байтов определены в PROTO-007; отсутствие ACK на уже отправленные события более 5 секунд также отменяет активную generation. Terminal-результат остаётся доступен через result, если уже был committed; потеря ACK не превращает completed в cancelled.
- **LLM-012:** Модель остаётся прогретой в пределах одного игрового запуска, без бессрочного накопления персональных prompt/KV-кешей. Повторно использовать можно только проверенный общий префикс; кеш с данными игрока не разделяется с другими пользователями. На shutdown освобождаются owned-процессы, модель и кеши. Выделенный экземпляр Ollama либо явное владение его моделью обязательно: AI-сервис не завершает произвольный пользовательский Ollama и не позволяет посторонним моделям скрыто занимать общий бюджет.
- **LLM-013:** Профиль поставки фиксирует source model ID и commit, все хеши файлов, quantization/group size, tokenizer/template, версии runner/библиотек, ОС/архитектуру, параметры generation, тип/размер кеша, режим GPU и версию корпуса знаний. Для Ollama фиксируется разрешённый digest, а не только изменяемый tag; для MLX — snapshot и при конвертации команды/версии/хеши результата. Apache 2.0 и применимые notices поставляются с артефактами. До квалификации значения остаются явно незаполненными; `latest` не является воспроизводимой версией.
- **LLM-014:** Скорость оценивается по [LLM-QA](npc-llm-evaluation.md) отдельно для каждого backend/железа. Цели для прогретого свободного сервиса: p95 до первого видимого текста ≤2 с и p95 полного стандартного ответа ≤8 с. Ожидание очереди и холодная загрузка публикуются отдельно, не скрываются из пользовательских end-to-end замеров. Поддержка старого Mac по ОС не доказывает быстрый профиль; непрошедшее оборудование отмечается неподтверждённым/неподдерживаемым для цели, а не получает фиктивный pass.

## Сценарии

- **S1 · LLM-001–005, 013:** Given подготовленные Apple Silicon и Windows/Intel Mac; When каждый backend запускается с локальным snapshot без внешней сети; Then один и тот же логический запрос проходит общий порт, модель и версии известны, неподдерживаемая ОС и отсутствующий файл диагностируются без скачивания.
- **S2 · LLM-002, 006–007, 012:** Given активный backend и очередь; When оператор переключает backend или останавливает AI; Then очередь получает статусы, прежние процессы/веса выгружены до новых, во всех фазах проверен общий пик RAM, игровые процессы не уничтожаются.
- **S3 · LLM-004, 008–009:** Given длинные русский, английский и испанский запросы и история; When строится prompt; Then реальный tokenizer/template подтверждает общий лимит, лишняя история убрана либо возвращена ошибка, thinking не появляется в ответе.
- **S4 · LLM-010–011:** Given 6 игроков, один медленный генератор и медленный клиент; When поступают запросы и отмена; Then очередь не растёт выше 4, повтор/спам не обходят лимиты, отменённый вычислитель не работает параллельно со следующим, остальные игровые события продолжаются.
- **S5 · LLM-006–007, 012–014:** Given максимальный разрешённый prompt и повторные диалоги; When выполняется квалификационный прогон; Then учтены все процессы/кеши/пики, нет накопления персональных кешей, опубликованы RAM, TTFT, полное время и очередь для каждого профиля.

## Ограничения и вне scope

Текстовый NPC MVP. Голос, ASR/TTS, изображения, fine-tuning/LoRA, отдельная модель на NPC, внешние embeddings, агентские инструменты и исполнение кода не входят в эту поставку. MLX не означает LM Studio; LM Studio не является обязательной зависимостью. Установка и тестирование моделей на этой машине не выполнены.

## Открытые вопросы

- Указать реальные целевые Apple Silicon, Windows и Intel Mac: CPU, RAM, GPU/VRAM, ОС. Численные цели выше — критерии выбора, не результаты замеров.
- Зафиксировать конкретные версии runner и MLX text-only артефакт после smoke-теста; не заявлять поддержку произвольного snapshot. Для первичной проверки можно исследовать MLX LM v0.32.2 и его text-only загрузчик Qwen3.5; это кандидат версии, не подтверждённый pin.
- Выбрать и проверить process-aware изоляцию native Ollama на каждой целевой ОС; приватный proxy без защиты обходного порта не закрывает требование LLM-005.
- Подтвердить платформенные методы измерения резидентной/unified памяти и пиков. Без них жёсткая приёмка 4 GB остаётся открытой.
