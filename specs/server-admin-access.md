# ADMIN-ACCESS — Доступ администратора из LAN

## Цель
Сохранить решения прерванной `admin-panel` в текущей серверной админке: учитель открывает `/admin` с любого ноутбука локальной сети и входит административным аккаунтом. `/operator` остаётся локальной страницей компьютера сервера. Оба адреса используют один интерфейс и одни use cases; внешний мониторинг не нужен.

## Требования
- **ADMIN-ACCESS-001:** `GET/HEAD /admin` отдаёт офлайн-страницу с формой входа без данных сервера; до входа рабочие разделы скрыты. `/operator` и `/api/operator/*` остаются только loopback (404 с LAN). Данные выводятся через `textContent`, CSP ограничивает ресурсы текущим сервером, ответы `no-store`.
- **ADMIN-ACCESS-002:** `POST /api/admin/login` принимает `{name,password}`, `/api/admin/dev` — `{}` только в development/test, `/api/admin/logout` завершает предъявленную административную сессию. Временный пароль переводит форму к смене пароля через `/api/admin/password` с `{name,password,newPassword}`, который сразу выдаёт административную сессию и не требует игрового места. Токен живёт только в памяти страницы; cookies и localStorage/sessionStorage не используются. После перезагрузки страницы требуется вход. 401/403 возвращает форму входа; выход очищает данные, пароль и незавершённые обновления. Ранее начатый запрос не возвращает данные после выхода или смены сессии.
- **ADMIN-ACCESS-003:** `/api/admin/<path>` использует те же JSON-контракты, историю, журнал, CSV и действия, что `/api/operator/<path>`, после проверки административной сессии на каждом запросе. Без сессии 401, с игровой сессией 403. Лимит 20 запросов/с с burst 40 на сессию; фиксированные шаблоны маршрутов в метриках без NPC id, имён и токенов. Изменяющие loopback-запросы сохраняют Origin/X-Operator проверку AUTH-010; административные запросы требуют явный Bearer.
- **ADMIN-ACCESS-004:** AUTH-017–020 реализуют роль, изоляцию admin/game, 8-часовую сессию без занятого игрового места, отзыв и создание через CLI. Оператор не может случайно создать администратора обычной регистрацией. Команды Windows используют `npm.cmd --prefix server run auth -- create-admin <имя> --env production`; окружение и конфигурация должны совпадать с сервером.
- **ADMIN-ACCESS-005:** Каждая попытка изменения из административной сессии даёт событие `admin.action` с accountId/sessionId/IP, методом, шаблоном пути и результатом и счётчик `admin_actions_total{route,method,result}`. Журнал изменений содержит реальное имя и accountId администратора (ADMIN-SRV-009); автор консоли остаётся `admin` без выдуманного аккаунта. Значения полей NPC и секреты в логи не попадают.
- **ADMIN-ACCESS-006:** Редактор передаёт текущую revision во всех изменениях существующего NPC и подтверждает изменённые поля. 409 показывает пояснение и актуального NPC для повторного просмотра; автоматического повторения или перезаписи чужой правки нет. У embedded NPC недоступны перенос, смена облика, выключение и удаление; у четырёх NPC BABEL недоступны выключение и удаление. Ограничения проверяются сервером и поясняются в UI.
- **ADMIN-ACCESS-007:** Мониторинг использует реестр, ограниченную серверную историю, SVG-графики, минутные записи и CLI report (OBS). `/metrics`, monitoring.token, Prometheus/Grafana и их runtime/config не возвращаются. Неполученный FPS остаётся «нет данных», клиентский TASK-081 и физическая Windows/LAN приёмка не подменяются фикстурами.

## Сценарии
- **S1 · ADMIN-ACCESS-001–004:** Given production и созданный CLI администратор; When другой ноутбук открывает `/admin`, меняет временный пароль и входит; Then доступны разделы, `/operator` с него даёт 404, обычному игроку административный API недоступен.
- **S2 · ADMIN-ACCESS-002–004:** Given две admin-сессии и game-сессия одного аккаунта; When выход из одной вкладки; Then другая и игра работают. When снята роль; Then обе admin-сессии отклоняются, game-сессия сохраняется. Admin-токен не открывает `/game`, world, BABEL или профиль игрока.
- **S3 · ADMIN-ACCESS-005–006:** Given два редактора одного NPC; When первый сохраняет и второй отправляет прежнюю revision; Then второй получает 409 с актуальным NPC, журнал содержит только успешное изменение с настоящим автором.
- **S4 · ADMIN-ACCESS-001–003:** Given медленный запрос; When выход, отзыв или новый вход; Then поздний ответ не показывает прежние данные. Перезагрузка требует входа; в browser storage нет токенов, внешних запросов нет.
- **S5 · ADMIN-ACCESS-006–007:** Given полная панель; When просмотрены разделы, графики и запреты NPC; Then поведение соответствует ADMIN/ADMIN-SRV, недостающие отчёты и недоступные аппаратные проверки явно обозначены.

## Ограничения
Готовность HTTP-ветки не означает готовность транспорта LAN с паролем: совместная поставка объединяется с отдельной HTTPS-веткой и проверяется заново. Игровой клиент этой задачей не изменяется. Реальный FPS, физические ноутбуки и доверие сертификату в Windows проверяются отдельными аппаратными сценариями.
