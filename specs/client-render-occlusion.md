# ROCC — Occlusion culling и Hi-Z

## Цель

После RFRAME проверить, достаточно ли дорог скрытый за стенами город для отдельной системы occlusion. Готовность этой спеки разрешает ограниченные прототипы; наличие Hi-Z в производственном рендере не является обязательным результатом.

## Требования

- **ROCC-001:** По маршрутам плотной застройки и открытого пастбища измерить потенциально скрытые пространственные группы и их стоимость после batching/LOD. Если потенциальная экономия не покрывает бюджет дополнительного прохода/проверок, оформить отказ без внедрения. Early-Z пикселей и frustum culling не выдаются за отмену submission целого объекта.
- **ROCC-002:** Кандидаты оцениваются по возрастанию сложности: консервативная видимость статических зон/PVS при подходящей планировке; асинхронные occlusion queries для крупных групп; Hi-Z только если предыдущие варианты недостаточны и есть измеренный резерв. Не выполнять запрос на каждый мелкий предмет. Для каждого прототипа задача заранее задаёт cap групп, outstanding queries, памяти и время CPU/GPU на кадр по baseline; переполнение выбирает видимость, а не скрытие.
- **ROCC-003:** Источники перекрытия — только надёжные непрозрачные поверхности. Bounds учитывают текущие transform, ветер и анимации. Неопределённость, пересечение near plane, камера внутри bounds, новые/движущиеся группы, устаревшая информация после поворота/перемещения/телепорта/reconnect приводят к консервативному показу. Видимые NPC, предметы и проходы не исчезают даже на один кадр из-за задержанного отрицательного результата.
- **ROCC-004:** Query results читаются только после готовности без ожидания main thread; до результата группа видима. GPU-side проверка без отмены реальных draw calls не называется выигрышем CPU submission. Сохранить состояние WebGLRenderer при низкоуровневых операциях; ошибки/отсутствие возможностей/context loss возвращают обычный путь и освобождают queries/targets.
- **ROCC-005:** Для Hi-Z до кода фиксируются источник depth, конвенция глубины, формат и поддержка render targets, conservative reduction, screen bounds, выбор mip и способ использования результата в WebGL2. Для обычной глубины с дальним значением 1 пирамида хранит максимум покрытых глубин, учитывая незаполненные пиксели; reversed depth требует согласованного обратного правила. Сэмплирование охватывает весь projected bounds, без усредняющей фильтрации, с запасом точности. Нельзя предполагать наличие compute/indirect draw или синхронно читать depth обратно на CPU. Цена построения пирамиды и потребления результата включается в A/B.
- **ROCC-006:** Occlusion основного вида не удаляет данные сессии, коллизии, анимацию видимых зависимых объектов или нужных shadow casters. Новая система сосуществует с RDETAIL и streaming, не оставляет visibility state у повторно использованного instance/чанка. Потеря результата выбирает рендер, не блокирует загрузку.
- **ROCC-007:** Внедрение проходит пороги RPERF на закрытом маршруте, не ухудшает P95 открытого маршрута более чем на 5%, не теряет видимые поверхности на сценариях S2–S3 и укладывается в заранее записанные caps. Если преимуществ нет, итог — отчёт и удалённый/изолированный непроизводственный прототип; обычный рендер сохраняется. Отсутствующие аппаратные замеры не считаются мотивированным отказом по производительности.

## Сценарии

- **S1 · ROCC-001/002/007:** Given одинаковые маршруты закрытого двора и открытого пастбища; When сравниваются baseline и каждый кандидат; Then учтена вся стоимость, отказ или внедрение обоснованы, открытая сцена не скрывает регрессию.
- **S2 · ROCC-003/005:** Given узкий проём, тонкая стена, объект частично открыт или пересекает near plane; When тестируется видимость; Then видимые пиксели не теряются, полностью перекрытая группа может быть исключена.
- **S3 · ROCC-003/004/006:** Given результат прошлого кадра; When камера резко разворачивается, объект движется, чанк загружается, сеть ресинхронизируется или теряется контекст; Then применяется безопасный показ без ожидания и выпадения объектов.
- **S4 · ROCC-002/004/007:** Given исчерпан cap или расширение отсутствует; When система работает и сессия завершается; Then обычный путь доступен, UI не блокируется, targets/queries освобождены.

## Ограничения и вне scope

WebGPU migration и аппаратно-зависимый renderer не входят в этап. Проверять текущий Three.js и реальные браузеры; Hi-Z не считать встроенной настройкой WebGLRenderer. Переход к сложному варианту не обязателен, если более простой уже решает измеренную проблему.
