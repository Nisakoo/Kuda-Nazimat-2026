# RPERF — Измерения и правила сравнения

## Цель

Отделить стоимость JS/отправки команд, GPU и загрузки ресурсов, чтобы следующие этапы устраняли подтверждённую проблему. Первый этап серии ROPT; предшествующих этапов нет.

## Требования

- **RPERF-001:** Отчёт содержит commit и локальный diff, OS, CPU/GPU/RAM, браузер, графический backend, питание, CSS viewport, device DPR и фактический размер drawing buffer, профиль, карту, радиус, число игроков, режим сети/LLM. Стартовая сравнительная сцена — market, радиус 2, 1280×800; low/balanced/high измеряются раздельно. Профиль QUALITY для demo остаётся самостоятельной приёмкой.
- **RPERF-002:** Сценарии воспроизводят стояние с обзором рынка, путь через двор/лестницы/пастбище с переходами чанков, резкие повороты, переключение первого/третьего лица, стрельбу до насыщения лимита следов, холодный и повторный вход. Координаты, действия, длительности, seed/фиксированное состояние и ожидаемые кадры фиксируются в harness/evidence. Для четырёх игроков используется настоящий сервер; синтетическая сцена допустима для изоляции рендера, но помечается и не доказывает LAN/AI. Состав NPC/декора между A/B одинаков.
- **RPERF-003:** Для установившихся маршрутов выполняются ≥5 с прогрева и ≥60 с записи, минимум три сопоставимых прогона каждого варианта последовательно, с чередованием baseline/кандидата. Записываются сырые значения, медианы и разброс, P95/P99 интервалов отправленных кадров, частота цикла, submitted/skipped, CPU по существенным фазам, draw calls и треугольники. Указывать, включают ли счётчики shadow passes; итог не должен незаметно сбрасываться между проходами. Холодная загрузка измеряется отдельно с явно заданным состоянием кэшей.
- **RPERF-004:** GPU duration измеряется неблокирующими timer queries при наличии EXT_disjoint_timer_query_webgl2. Результаты читаются только после готовности; disjoint/недействительные samples отбрасываются, число запросов ограничено, queries освобождаются. При отсутствии расширения поле «недоступно», а не 0; CPU-время renderer и fence не выдаются за GPU duration или показ дисплеем. Диагностика не вводит finish, блокирующий readPixels или ожидание результата.
- **RPERF-005:** До эксперимента задача фиксирует целевую метрику: CPU фазы, GPU ms, P95 загрузочного пика, draw calls либо видимую ошибку качества для CSM. Для оптимизации рабочий порог — улучшение медианы целевой метрики ≥10% и больше разброса повторов; P95 интервала кадра не ухудшается более чем на 5%. Изменение только draw calls считается снижением команд, а не доказанным ростом FPS; при VSync оценивается запас CPU/GPU. При шуме >порога серия продлевается, вывод «ускорено» не делается. Для CSM применяется отдельный бюджет RCSM, поскольку это оценка качества.
- **RPERF-006:** После пяти завершённых циклов входа/выхода проверяются активные чанки, модели, instance/query/target ресурсы, геометрии, текстуры и retained heap по QUALITY. Размер файлов, резерв WorldBudget, JS heap и оценка GPU bytes выводятся раздельно; счётчик текстур не является измерением VRAM. Стоимость включённой диагностики сравнивается с выключенной на одном маршруте; сбор данных ограничен по памяти.
- **RPERF-007:** Задача содержит команды, окружение, маршруты, краткие результаты сравнения, ограничения и список приоритетных узких мест. Сырые замеры, скриншоты, видео, логи, профили и архивы исходников сохраняются только вне checkout; они не добавляются в Git. Исторические временные материалы могут быть удалены после записи итогов. Нельзя переносить результат Apple M4 на слабый ноутбук; доступный профиль именуется явно. Недоступная GPU-метрика не запрещает подтверждённую CPU-оптимизацию, но не позволяет закрыть требование, зависящее от измерения GPU. Отсутствующая четырёхпользовательская/аппаратная приёмка остаётся незавершённой, а изолированные измерения используются только в своих границах.

## Сценарии

- **S1 · RPERF-001–003/005:** Given одинаковая сборка; When выполнены повторные прогоны; Then известен разброс, условия воспроизводятся, A/A не объявляется ускорением.
- **S2 · RPERF-004:** Given расширение отсутствует, запрос ещё не готов или возник disjoint/context loss; When снимается статистика; Then цикл не ждёт GPU, недоступные данные обозначены, ресурсы освобождаются.
- **S3 · RPERF-002/006:** Given холодная загрузка, стрельба и пять повторных входов; When собран отчёт; Then пики отделены от steady-state, число ресурсов возвращается к допустимым значениям.
- **S4 · RPERF-005/007:** Given FPS ограничен VSync либо нет нужного оборудования; When оценивается кандидат; Then вывод опирается на доступную целевую метрику и не расширяется на непроверенные режимы.

## Ограничения и вне scope

Не добавлять внешний мониторинг или расширение протокола. TASK-081 остаётся отдельной передачей серверных perf-отчётов. Существующий `client/scripts/profile-render.mjs` можно развить; его старый короткий маршрут не закрывает RPERF автоматически.
