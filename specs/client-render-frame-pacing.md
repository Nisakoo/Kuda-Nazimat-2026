# RFRAME — Плавность кадра и загрузка

## Цель

После RDETAIL устранить оставшиеся рывки на входе, движении и стрельбе. Разделить задачи установившегося FPS и времени появления новой модели.

## Требования

- **RFRAME-001:** По RPERF разделить затраты анимаций, matrices, raycast, clone/parse, компиляции шейдеров, GPU upload, UI и сборки мусора. Изменять только подтверждённые дорогие участки. Существующая очередь clone с бюджетом 2 мс между заданиями и cap 8 не является гарантией 2 мс для одного неделимого clone; отчёт сохраняет этот предел применимости.
- **RFRAME-002:** Предварительная компиляция материалов/шейдеров и подготовка upload выполняются ограниченно через существующий lifecycle загрузки; compileAsync используется при поддержке текущего renderer. Отмена, выход, потеря контекста и ошибки не оставляют вечного loading или позднего добавления объектов старой сессии. Первый показ объекта остаётся полным; нельзя получить быстрый вход за счёт невидимых обязательных моделей.
- **RFRAME-003:** Ускорение raycast для камеры/дроби сохраняет ближайшие пересечения, material side, drawRange/groups, динамические transform и невидимые поверхности, нужные камере. Пространственный индекс и поиск ближайшего без полной сортировки принимаются только после сравнения с текущим алгоритмом; общий индекс не удерживает выгруженные модели. Повторное использование временных объектов уменьшает измеренные аллокации без изменения игровой логики выстрелов.
- **RFRAME-004:** При подтверждённой GPU-перегрузке оценивается динамическое разрешение внутри профиля: масштаб 0.75–1 от его текущего capped DPR, шаг не более 0.05, изменение не чаще раза в секунду, восстановление только после ≥3 с устойчивого запаса. Целевой бюджет кадра фиксируется в задаче до опыта; переходы не вызывают постоянной переаллокации. Нужна проверенная GPU-метрика либо отдельный опыт чувствительности к разрешению; один CPU spike не считается основанием. При недоступных данных остаётся фиксированный масштаб 1. В эксперименте адаптация явно включается отдельно; до принятия результата прежнее поведение по умолчанию сохраняется.
- **RFRAME-005:** При адаптации размер/чёткость DOM UI не меняются, профиль сохраняется, resize/device DPR учитываются, Pointer Lock и координаты прицела корректны. После паузы, скрытой вкладки, смены сцены или context recovery история нагрузки сбрасывается; длинный перерыв не провоцирует ложное понижение. Принятую пользовательскую настройку согласовать с RENDER-009/SET по ROPT-007; диагностический переключатель не заменяет законченный пользовательский режим.
- **RFRAME-006:** Meshopt/Draco, quantization, KTX2 и упрощение материалов рассматриваются только при измеренном bottleneck передачи/декодирования/памяти/шейдинга. Декодеры локальны, ограничены по workers и проходят AssetManager/auth; размер сжатого файла не подменяет резерв распакованной геометрии/текстуры. Большинство рыночных моделей без текстур: KTX2 не является обязательной работой. Изменение материала требует отдельного визуального сравнения. Depth prepass не включается без GPU A/B, поскольку добавляет проход.
- **RFRAME-007:** Приёмка по RPERF отдельно показывает установившийся кадр, холодный/повторный вход, первый показ модели/материала и серию выстрелов. Дополнительные jobs/workers/cache/targets ограничены, освобождаются и не меняют FrameFence, тайминг сессии или сетевые квоты. Недоказанные варианты отклоняются; отсутствие GPU-проблемы не оправдывает постоянное уменьшение разрешения.

## Сценарии

- **S1 · RFRAME-001/002/007:** Given новая модель и незавершённая компиляция; When игрок выходит/меняет профиль; Then работа отменяется или результат игнорируется, loading завершается корректно и ресурсы не утекают.
- **S2 · RFRAME-003:** Given лучи у края стены, по индексной/неиндексной геометрии и движущейся мишени; When сравниваются алгоритмы; Then ближайшие попадания и следы совпадают, серия выстрелов измерена.
- **S3 · RFRAME-004/005:** Given управляемая GPU-нагрузка, затем её снятие и скрытая вкладка; When включена адаптация; Then масштаб остаётся в границах, меняется без дребезга, возвращается при запасе, UI и прицел не сдвигаются.
- **S4 · RFRAME-006/007:** Given офлайн-режим и неподдерживаемый/ошибочный декодер; When ресурс запрошен или отменён; Then нет внешнего запроса, обхода авторизации или превышения памяти, ошибка восстанавливаема существующим retry.

## Ограничения и вне scope

Не переносить всю игру в Worker/OffscreenCanvas и не добавлять DI/новую систему событий ради оптимизации. Изменение server/shared не требуется. Не выдавать снижение размера GLB за снижение runtime draw calls или гарантированный рост FPS.
