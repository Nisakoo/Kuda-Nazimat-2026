# UI — Ввод и интерфейс

## Цель

Управлять игроком и взаимодействиями через InputController и Svelte 5.

## Требования

- **UI-001:** InputController преобразует физические клавиши WASD в движение относительно направления камеры (в том числе при русской раскладке), E — во взаимодействие, Escape — в меню. Во время активной игры мышь постоянно привязана к камере через Pointer Lock: курсор скрыт, относительные перемещения мыши меняют обзор без удержания кнопок и без ограничения краем экрана. Он не меняет Mesh и не выполняет сетевые запросы.
- **UI-002:** Меню, диалог и фокус текстового ввода освобождают курсор и блокируют движение и обзор; накопленный ввод сбрасывается. Потеря фокуса, скрытие вкладки или непредвиденная потеря Pointer Lock при активной игре останавливают управление и показывают возможность продолжить. Вход и продолжение запрашивают захват мыши по явному действию пользователя; управление включается только после успешного захвата. Отказ или недоступность захвата показываются понятным сообщением с возможностью повторить попытку или выйти в меню. Escape освобождает мышь и открывает меню, а в диалоге закрывает его; одно нажатие не должно повторно переключать меню из-за события потери захвата. После закрытия диалога или текстового ввода доступно явное продолжение с повторным захватом. При остановке захват освобождается и DOM-обработчики удаляются.
- **UI-003:** Svelte 5 + CSS отображают поверх canvas главный экран, HUD, доступное взаимодействие, диалог NPC, загрузку мира, статус связи, настройки и ошибку подключения.
- **UI-004:** UI работает только через GameSession или небольшой фасад GameApp. Конкретные ThreeRenderer и SocketIOAdapter не импортируются; трансформации каждого кадра не проходят через реактивное UI-состояние.
- **UI-005:** В LocalSession игрок подходит к NPC и нажимает E; проверяется доступность взаимодействия, открывается диалог и отображается ответ локального демо-источника. В OnlineSession по PROTO v1 вопрос уходит как `npc-question`, ответ приходит одним `npc-answer` либо `error` (сервер укладывается в 8–9 с, клиент ждёт 10 с); UI показывает ожидание, ответ как текст, не HTML, и ошибку; клиент не выдаёт демонстрационный текст за результат ИИ; поздний ответ не меняет новый диалог. *(PROTO v2.)* С переходом на NPC-подконтракт PROTO-007 UI различает очередь, генерацию, временный streamed-текст, сохранённый финал, отмену и ошибку; показывает ответ как текст, не HTML. Каждый partial содержит весь накопленный текст и заменяет предыдущий, а не дописывается. Дубли/старые seq отбрасываются; пропуск partial безопасен и не требует отмены/восстановления фрагментов. Финал/результат заменяет временный текст без дублирования; после terminal поздний partial игнорируется. Закрытие диалога отменяет запрос, поздние/чужие события не меняют новый диалог. Выбор языка ru/en/es и режима standard/simple_no_formulas передаётся явной операцией preferences через сессию; сохранение настройки показывается только после подтверждения. Per-fragment ACK отсутствует; UI не выбирает backend/параллельность/лимиты и не отправляет system prompt. Disconnect не запускает автоматический повтор generation. После reconnect либо ожидания пропавшего финала клиент читает result в пределах PROTO-007; завершённый результат заменяет временный текст, отменённый/прерванный получает явный статус. Пользователь видит очередь, может отменить запрос и пользоваться меню.
- **UI-006:** Настройки применяют доступные параметры сессии, карты, радиуса и debug; смена сессии корректно завершает предыдущую. Сетевые ошибки не блокируют меню и возможность выхода.

- **UI-007:** Для минимального общения игроков UI отправляет и отображает текстовые сообщения через сессию и общий протокол, не вставляет их как HTML. Ввод сообщения блокирует игровые клавиши; ошибки отправки видны пользователю. Область доставки согласуется с REALTIME.

## Сценарии

- **S1:** UI-001–002: Given игра; When используются WASD, мышь, E и Escape, а затем открывается диалог; Then WASD работает относительно камеры при русской и латинской раскладках, мышь вращает камеру без удержания кнопок, а в диалоге курсор свободен и ввод не двигает игрока и камеру.
- **S2:** UI-003–005: Given NPC рядом и вне зоны взаимодействия; When нажимается E; Then диалог открывается только при доступном взаимодействии, HUD отражает состояние сессии. Given вопрос в OnlineSession v1; When приходит `npc-answer`, `error` или истекают 10 с; Then ответ показан как текст, ошибка видна, поздний ответ не меняет новый диалог. *(PROTO v2)* Given queued/partial/completed/error и новый диалог; When приходят пропуски/дубли/поздние снимки, не доставлен финал и прочитан result после reconnect; Then снимки заменяются, не склеиваются, временный текст не выдаётся за сохранённый, финал не дублируется, generation не повторяется, отмена и смена языка доступны, чужой диалог не меняется. На клиентском этапе используется тестовая доставка; реальный LLM проверяется при интеграции.
- **S3:** UI-002, 006: Given открытая игра; When теряется фокус, меняется сессия и игра завершается; Then нет залипшего ввода и старых обработчиков.
- **S4:** UI-003–004, 006: Given обновления позиции и ошибка сети; When игра работает; Then UI не перерисовывается целиком каждый кадр, ошибка видна и выход доступен.

- **S5:** UI-007: Given подключённые игроки и тестовая доставка; When игрок вводит и отправляет сообщение; Then другой видит текст, отправитель не двигается во время ввода, ошибка доставки отображается.

- **S6:** UI-001–002: Given активная игра с захваченной мышью; When мышь движется многократно в одном направлении; Then камера продолжает вращаться без упора в край экрана. При Escape, blur или потере захвата управление останавливается и клавиши сбрасываются; после явного продолжения и успешного захвата старый ввод не возобновляется.
- **S7:** UI-002: Given главный экран или меню; When захват мыши отклонён или недоступен; Then движение и обзор не включаются, показано сообщение и доступны повторная попытка и выход. После завершения игры не остаётся захвата и обработчиков предыдущего экземпляра.

## Ограничения и вне scope

Клиентское демо NPC не заменяет адаптивного серверного ИИ. Полноценная регистрация, квесты и боевые интерфейсы вне клиентского MVP.

## Открытые вопросы

Прежнее описание чата как AOI расходится с REALTIME-008 и кодом GameService: v1 доставляет сообщение всей текущей карте. Нужен ли отдельный режим чата по близости или заданию — решение для следующей версии; в текущем UI указана вся карта. Тестовый сетевой режим не подтверждает серверную приёмку.

## Расширение UI для MOVE

UI-001–002: физический Space даёт один прыжок по фронту, оба Shift вместе образуют удержание спринта. Автоповтор Space не прыгает повторно; потеря управления очищает движение/Shift/непотреблённый прыжок. UI-003: кольцо выносливости по MOVE-009, источник — motion сессии через GameApp, именованный progressbar без live-озвучивания каждого тика.
