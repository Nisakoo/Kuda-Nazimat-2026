# UI — Ввод и интерфейс

## Цель

Управлять игроком и взаимодействиями через InputController и Svelte 5.

## Требования

- **UI-001:** InputController преобразует WASD в команды движения, мышь — в команды камеры, E — во взаимодействие, Escape — в меню. Он не меняет Mesh и не выполняет сетевые запросы.
- **UI-002:** Меню, диалог и фокус текстового ввода блокируют соответствующее игровое управление; при потере фокуса сбрасываются зажатые клавиши. При остановке удаляются DOM-обработчики.
- **UI-003:** Svelte 5 + CSS отображают поверх canvas главный экран, HUD, доступное взаимодействие, диалог NPC, загрузку мира, статус связи, настройки и ошибку подключения.
- **UI-004:** UI работает только через GameSession или небольшой фасад GameApp. Конкретные ThreeRenderer и SocketIOAdapter не импортируются; трансформации каждого кадра не проходят через реактивное UI-состояние.
- **UI-005:** В LocalSession игрок подходит к NPC и нажимает E; проверяется доступность взаимодействия, открывается диалог и отображается ответ локального демо-источника. В OnlineSession ответы поступают от сервера по NPC-подконтракту PROTO-007; клиент не выдаёт демонстрационный текст за результат ИИ. UI различает очередь, генерацию, временный streamed-текст, сохранённый финал, отмену и ошибку; показывает ответ как текст, не HTML. Каждый partial содержит весь накопленный текст и заменяет предыдущий, а не дописывается. Дубли/старые seq отбрасываются; пропуск partial безопасен и не требует отмены/восстановления фрагментов. Финал/результат заменяет временный текст без дублирования; после terminal поздний partial игнорируется. Закрытие диалога отменяет запрос, поздние/чужие события не меняют новый диалог. Выбор языка ru/en/es и режима standard/simple_no_formulas передаётся явной операцией preferences через сессию; сохранение настройки показывается только после подтверждения. Per-fragment ACK отсутствует; UI не выбирает backend/параллельность/лимиты и не отправляет system prompt. Disconnect не запускает автоматический повтор generation. После reconnect либо ожидания пропавшего финала клиент читает result в пределах PROTO-007; завершённый результат заменяет временный текст, отменённый/прерванный получает явный статус. Пользователь видит очередь, может отменить запрос и пользоваться меню.
- **UI-006:** Настройки применяют доступные параметры сессии, карты, радиуса и debug; смена сессии корректно завершает предыдущую. Сетевые ошибки не блокируют меню и возможность выхода.

- **UI-007:** Для минимального общения игроков UI отправляет и отображает текстовые сообщения через сессию и общий протокол, не вставляет их как HTML. Ввод сообщения блокирует игровые клавиши; ошибки отправки видны пользователю. Область доставки согласуется с REALTIME.

## Сценарии

- **S1:** UI-001–002: Given игра; When используются WASD, мышь, E и Escape, а затем открывается диалог; Then выполняются соответствующие действия, ввод диалога не двигает игрока.
- **S2:** UI-003–005: Given NPC рядом и вне зоны взаимодействия; When нажимается E; Then диалог открывается только при доступном взаимодействии, HUD отражает состояние сессии. Given queued/partial/completed/error и новый диалог; When приходят пропуски/дубли/поздние снимки, не доставлен финал и прочитан result после reconnect; Then снимки заменяются, не склеиваются, временный текст не выдаётся за сохранённый, финал не дублируется, generation не повторяется, отмена и смена языка доступны, чужой диалог не меняется. На клиентском этапе используется тестовая доставка; реальный LLM проверяется при интеграции.
- **S3:** UI-002, 006: Given открытая игра; When теряется фокус, меняется сессия и игра завершается; Then нет залипшего ввода и старых обработчиков.
- **S4:** UI-003–004, 006: Given обновления позиции и ошибка сети; When игра работает; Then UI не перерисовывается целиком каждый кадр, ошибка видна и выход доступен.

- **S5:** UI-007: Given подключённые игроки и тестовая доставка; When игрок вводит и отправляет сообщение; Then другой видит текст, отправитель не двигается во время ввода, ошибка доставки отображается.

## Ограничения и вне scope

Клиентское демо NPC не заменяет адаптивного серверного ИИ. Полноценная регистрация, квесты и боевые интерфейсы вне клиентского MVP.

## Открытые вопросы

Текстовое общение — предложенный минимум исходного требования взаимодействия игроков; область доставки и payload согласуются в REALTIME/PROTO.
