# UI — Ввод и интерфейс

## Цель

Управлять игроком и взаимодействиями через InputController и Svelte 5.

## Требования

- **UI-001:** InputController преобразует физические клавиши WASD в движение относительно направления камеры (в том числе при русской раскладке), E — во взаимодействие, Escape — в меню. Во время активной игры мышь постоянно привязана к камере через Pointer Lock: курсор скрыт, относительные перемещения мыши меняют обзор без удержания кнопок и без ограничения краем экрана. Он не меняет Mesh и не выполняет сетевые запросы.
- **UI-002:** Меню, диалог и фокус текстового ввода освобождают курсор и блокируют движение и обзор; накопленный ввод сбрасывается. Потеря фокуса, скрытие вкладки или непредвиденная потеря Pointer Lock при активной игре останавливают управление и показывают возможность продолжить. Действие создания/подключения инициирует вход и намерение захвата (LOAD-006); отдельной штатной кнопки «Начать прогулку» нет. Продолжение после меню запрашивает захват по явному действию пользователя; управление включается только после успешного захвата. Отказ или недоступность захвата показываются понятным сообщением с возможностью повторить попытку или выйти в меню. Escape освобождает мышь и открывает меню только без другого окна; в диалоге закрывает только его. Одно нажатие не должно повторно переключать меню из-за события потери захвата. Действие закрытия игрового окна запрашивает повторный захват; при отказе браузера доступно отдельное «Вернуть управление» без автоматического открытия паузы. Закрытие настроек, открытых из паузы, возвращает в существующую паузу. При остановке захват освобождается и DOM-обработчики удаляются.
- **UI-003:** Svelte 5 + CSS отображают поверх canvas главный экран, HUD, доступное взаимодействие, диалог NPC, загрузку мира, настройки и важные ошибки подключения. В активной игре HUD не содержит кнопок и инвентаря: задачи открываются по Tab, чат/словарь/карта/языки — по физическим 1/2/3/4, меню — по Esc. Текущие задача и язык отображаются текстом. Подсказка управления видна справа снизу только при удержании Alt/Option; потеря фокуса/захвата и отпускание скрывают её. В модальных окнах Tab сохраняет навигацию фокуса; ввод цифр, IME и сочетания с модификаторами не вызывают игровые действия (HUD-002–010).
- **UI-004:** UI работает только через GameSession или небольшой фасад GameApp. Конкретные ThreeRenderer и SocketIOAdapter не импортируются; трансформации каждого кадра не проходят через реактивное UI-состояние.
- **UI-005 (NPC):** В LocalSession игрок подходит к NPC и нажимает E; проверяется доступность взаимодействия, открывается диалог и отображается ответ локального демо-источника. В текущей OnlineSession по PROTO v3 вопрос уходит как `npc-question`, ответ приходит одним `npc-answer` либо `error`. UI показывает ожидание, текст без HTML и ошибку; демонстрационный текст не подменяет результат ИИ, поздний ответ не меняет новый диалог.

  **Текущий deadline.** Серверный `npc.timeoutMs` настраивается оператором: default 30000 мс, config 1–300000 мс, Make/CLI — целые секунды 1–300. Очередь входит в срок. Клиент получает effective `npcTimeoutMs` через `/api/game-config` при connect/reconnect от фактического serverUrl и ждёт NPC этот срок +2000 мс; остальные pending, включая чат, — 10 с. Поздняя настройка старого соединения игнорируется. Пока metadata неизвестна/ошибочна, NPC недоступен с понятной ошибкой без блокировки мира/чата и без короткого fallback. Увеличение срока не квалифицирует LLM-скорость.

  **Серверный поток и клиентский TODO.** Сервер уже реализует opt-in PROTO-007 (`stream: true`), `npc-partial`, `npc-cancel`/`npc-cancelled`, `PartialThrottle` и scripted-поток. Клиент пока не включает поток; его поддержка — [TASK-041](../tasks/041-client-npc-stream.md). После её реализации каждый partial заменяет временный текст целиком, не дописывается; дубли/старые seq отбрасываются, пропуск безопасен, ACK/replay фрагментов нет. Финал после сохранения заменяет временный текст без дублирования; terminal закрывает вопрос, поздние снимки игнорируются. Закрытие диалога должно отменять его запрос через сессию; поздние/чужие события не меняют новый диалог. Серверный поток использует `npc.streamTimeoutMs` по NPC-002/008 (default 30000 мс, config 1–300000 мс); явный Make/env/CLI override одинаково задаёт оба NPC deadline, без override их отдельные значения сохраняются; снимки не продлевают его. Настоящие LLM-workers пока выдают только приватный operational progress и финал, не игровые partial.

  **Будущий полный AI-план.** Различение durable queued/running/completed, чтение result после reconnect, preferences ru/en/es и standard/simple_no_formulas, reset и подтверждённая компактная память требуют новых согласованных операций AI/STORE и клиентской работы. Эти операции не входят в реализованный PROTO-007 и не означают переход игры с v3 обратно на v2. Сохранение настройки показывается только после подтверждения; будущий result заменяет временный текст без повторной generation. UI не выбирает backend/параллельность/лимиты и не отправляет system prompt. Disconnect не запускает автоматический повтор generation; меню остаётся доступным.

- **UI-006:** Игровые настройки — радиус, громкость и облик ([SET](client-settings.md)); смена сессии корректно завершает предыдущую. Сетевые ошибки не блокируют меню и возможность выхода.

- **UI-007:** Для минимального общения игроков UI отправляет и отображает текстовые сообщения через сессию и общий протокол, не вставляет их как HTML. Ввод сообщения блокирует игровые клавиши; ошибки отправки видны пользователю. Область доставки согласуется с REALTIME.

## Сценарии

- **S1:** UI-001–002: Given игра; When используются WASD, мышь, E и Escape, а затем открывается диалог; Then WASD работает относительно камеры при русской и латинской раскладках, мышь вращает камеру без удержания кнопок, а в диалоге курсор свободен и ввод не двигает игрока и камеру.
- **S2:** UI-003–005: Given NPC рядом и вне зоны взаимодействия; When нажимается E; Then диалог открывается только при доступном взаимодействии, HUD отражает состояние сессии. Given single-final вопрос OnlineSession по PROTO v3 и загруженная metadata; When приходит `npc-answer`/`error` либо истекает effective NPC deadline +2 с доставки; Then текст/ошибка показаны, поздний ответ не меняет новый диалог. Given metadata неизвестна или относится к старому соединению; Then NPC-запрос не отправляется, мир/чат доступны. **После TASK-041:** Given opt-in partial/cancel/terminal; When приходят дубли/пропуски/поздние снимки или закрыт диалог; Then текст заменяется, не склеивается, отмена адресована своему вопросу, terminal не дублируется. **После согласования полного AI-плана:** проверить preferences/reset/result после reconnect без второй generation. Тестовая доставка и scripted-поток не квалифицируют настоящую LLM.

- **S3:** UI-002, 006: Given открытая игра; When теряется фокус, меняется сессия и игра завершается; Then нет залипшего ввода и старых обработчиков.
- **S4:** UI-003–004, 006: Given обновления позиции и ошибка сети; When игра работает; Then UI не перерисовывается целиком каждый кадр, ошибка видна и выход доступен.

- **S5:** UI-007: Given подключённые игроки и тестовая доставка; When игрок вводит и отправляет сообщение; Then другой видит текст, отправитель не двигается во время ввода, ошибка доставки отображается.

- **S6:** UI-001–002: Given активная игра с захваченной мышью; When мышь движется многократно в одном направлении; Then камера продолжает вращаться без упора в край экрана. При Escape, blur или потере захвата управление останавливается и клавиши сбрасываются; после явного продолжения и успешного захвата старый ввод не возобновляется.
- **S7:** UI-002: Given главный экран или меню; When захват мыши отклонён или недоступен; Then движение и обзор не включаются, показано сообщение и доступны повторная попытка и выход. После завершения игры не остаётся захвата и обработчиков предыдущего экземпляра.

## Ограничения и вне scope

Клиентское демо NPC не заменяет адаптивного серверного ИИ. Полноценная регистрация, квесты и боевые интерфейсы вне клиентского MVP.

## Открытые вопросы

Прежнее описание чата как AOI расходится с REALTIME-008 и кодом GameService: v1 доставляет сообщение всей текущей карте. Решено: сообщение получают все игроки текущей игровой сессии независимо от расстояния (BABEL-009); доставка всей карте — текущее состояние v1. Тестовый сетевой режим не подтверждает серверную приёмку.

## Расширение UI для MOVE

UI-001–002: физический Space даёт один прыжок по фронту, удержание любого Shift даёт спринт (MOVE-006). Автоповтор Space не прыгает повторно; потеря управления очищает движение/Shift/непотреблённый прыжок. UI-003: кольцо выносливости по MOVE-009, источник — motion сессии через GameApp, именованный progressbar без live-озвучивания каждого тика.

## Расширение UI для NEXT (частичная реализация)

NEXT-011 добавляет физическую F: один фронт поднимает доступный предмет при свободных руках либо кладёт переносимый предмет на свободную поверхность перед персонажем. Все роли равноправны; максимум один предмет в руках, это единственный «инвентарь» (BABEL-020). Подсказка, ожидание/отказ и занятость рук отражают подтверждённое состояние сессии. Автоповтор, меню, ввод текста, blur/visibility и потеря Pointer Lock не создают отложенного действия; действует сброс UI-002. Анимация не подменяет ответ сервера и не блокирует MOVE.

NEXT-015 добавляет один регулятор громкости в существующие настройки: 30% по умолчанию, сохранение в браузере после reload, 0% — тишина. Показ новой реплики может сопровождаться коротким стилизованным бормотанием; перечитывание истории и polling его не повторяют. Отдельный редизайн для этих элементов не требуется. Требования и критерии — [NEXT](world-next-stage.md); реализация и открытая совместная приёмка отражены в [клиентской задаче](../tasks/056-world-client.md), [аудиозадаче](../tasks/057-world-audio.md) и [evidence](../tasks/evidence/world-next/acceptance.md). Непроверенные сценарии не объявляются принятыми.
